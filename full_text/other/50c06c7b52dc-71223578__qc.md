# QC: Deep Review

## Trigger

This skill is reached through **three first-class entry points**. All three resolve target / criteria / flags through the *same* Parameter Parsing grammar (below) — only how the invocation arrives differs. The sentinel form (a) is the original; (b) and (c) are pure-increment additions (v2.0.0) that do not change (a)'s semantics or the flag set.

**(a) Sentinel `/qc` — first token of the user message** (original form; semantics unchanged):
Activate ONLY when `/qc` (case-insensitive) appears as the **first token** of the user message. Tokenization ignores leading whitespace and blank lines before the sentinel. Ignore `/qc` occurring inside code fences, blockquotes, quotes, or inline examples. Do NOT activate on natural language: check / review / verify / inspect / audit / 检查 / 审阅 / 复核 / 审计 or similar. If the user clearly wants QC but uses no sentinel **and** did not invoke the skill directly, do nothing — they may use `/qc` to invoke.

**(b) Skill-tool args — the skill is invoked directly** (the dominant real path: in the retention-window usage snapshot, ~420 Skill-tool invocations vs 0 raw first-token sentinels — (b)+(c) together are ~100% of real activations). The args string carries the **same grammar as the text after `/qc`**, but WITHOUT the `/qc` prefix (activation is already done by the tool call). Parse args identically: first non-flag semantic unit = target, the rest = additional criteria, `--`-prefixed known flags = flags (position-independent). Empty args → auto-detect (Parameter Parsing step 3).

**(c) Prose-embedded `/qc …`** — the user's message is natural-language prose containing an embedded `/qc <target> <flags>` instruction that is NOT the first token: parse the embedded sentinel-and-args by the same grammar, then **echo the parsed result** (resolved target / criteria / flags) before executing, so a mis-parse is catchable. This does NOT relax (a)'s no-natural-language guard — a bare "please review X" with no `/qc` token is still not a trigger; only an explicit embedded `/qc` is.

You now assume the role of **strict reviewer**. Conduct a thorough, meticulous, comprehensive, in-depth, and critical examination of the specified target.

## Parameter Parsing

1. Read the args (the text after `/qc` for entry (a)/(c), or the Skill-tool args string for entry (b) — same grammar): the first non-flag semantic unit is the review target (single word, quoted phrase, or file path); the rest are additional criteria. Flag tokens (`--` prefix matching known flags below) are excluded from target/criteria regardless of position. **Long criteria**: the criteria span is everything from after the target token to end-of-args (interspersed flags removed); it may be long (median ~408 chars in usage) — pass the full span to the review, never truncate.
   - **Quoting**: paths with spaces MUST use double quotes (e.g., `/qc "my project/analysis.R"`). Single quotes and backslash-escaped spaces are not supported; unquoted path-like tokens with spaces → ask user to re-invoke with quotes. Empty quoted string → falls through to auto-detect step 3.
   - `--loop`/`--循环` [N]: activate **Loop Mode**. N defaults to 3 (aligns with L2/L4 in `ref_verification_depth_ladder.md`; use `--loop 2` for L1/L3). The immediately-following token is consumed as N ONLY if it is a positive integer; otherwise (non-numeric) it re-enters the token stream. Explicit non-positive integer literals (`--loop 0`, `--loop -1`, etc.) → treat as user error, prompt for clarification rather than silent fallthrough. Ambiguous result → prompt user.
   - `--sub`/`--子代理`: activate **Subagent Counterfactual Mode** (see below).
   - `--lite`/`--省流`: activate the **efficiency preset (Lite Mode)** — token-economical. Its four levers (subagent→sonnet, relaxed no-C/M exit, once-at-exit `--sub` dispatch, skip-Evolution) and their conditionality are defined once in § Loop Mode → **Lite Mode (efficiency preset)**; this entry does not restate them (single-definition-point convergence, v2.0.0 — behavior unchanged).
   - `--sonnet` / `--haiku` / `--gpt`: **Subagent Model Override** — set which model runs the `--sub` counterfactual (no effect without `--sub`). `--sonnet`/`--haiku` swap the isolated Claude subagent's model (default opus → that model); `--gpt` routes the counterfactual to a real GPT model via the Codex CLI — a genuine **cross-model** check, not an in-harness Claude (see Subagent Counterfactual Mode → Model Resolution + GPT Cross-Model Dispatch). Position-independent. **Overrides `--lite`'s implicit sonnet** (explicit > implicit; `--lite`'s other levers — relaxed exit, once-at-exit dispatch, skip-Evolution — still apply). **Validation order**: if `--sub` is absent, model-overrides are inert → emit `[model-override ignored: no --sub]` and proceed (counterfactual stays inline; multiplicity not checked — moot). If `--sub` is present, enforce **at most one** model-override (`--sonnet --gpt` etc. → user error, prompt for clarification). Model names are proper nouns — English only, no Chinese aliases.
   - `--resume`: **resume an interrupted loop** from its on-disk state file (§ Loop State Persistence & Resume). Implies Loop Mode. Target, level, and the full flag regime are restored from the state-file header, so a bare `/qc --resume` needs no target argument; any explicit target/flags given alongside `--resume` **override** the restored values and MUST each be announced in the resume confirmation block. No resumable state file found → error (see candidate discovery). `--resume` combined with a fresh (non-interrupted) invocation intent is a user error — it never starts a new loop.
   - `--loop`, `--sub`, `--lite`, and the model-override flags (`--sonnet`/`--haiku`/`--gpt`) are independent switches and combine without conflict; a model-override requires `--sub` to have any effect. `--resume` combines with any of them, where they act as explicit overrides of the restored regime.
2. Target mapping: 代码/code → Code | 方案/plan → Plan | 文档/doc → Document | 数据/data → Data | 建议/advice → Advice | skill/prompt/技能/提示词 → Skill/Prompt | diff/changeset/directory/目录 → Code overlay (blast-radius scope = diff/directory); for mixed content → select the primary type based on the user's question focus or content proportion; overlay checks from secondary types
3. No arguments → auto-detect in this priority order:
   1. A review target named in the user's current message — a file path, or an explicitly-named output/artifact (e.g. "the plan above", "that script"). This is the entry-(b)/(c) branch: args empty but the invoking prose points at a target → use it.
   2. Most recent substantive assistant output — must satisfy BOTH: (a) size: code block ≥3 lines, numbered plan ≥5 items, or prose ≥5 lines (excludes tables, data dumps, single-line answers); (b) type: classifiable as code/plan/document/data/advice/skill/prompt (excludes tool-status, errors). If uncertain, skip.
   3. Most recently edited or read file in the session
   4. Fallback: prompt user
4. If target content is not in context but a file path or recently edited file exists → Read it first (segment oversized files, prioritising core logic). Read failure (persisting per the Tool Priority § Read-target degradation trigger — consecutive, not first-time) → apply its `ctx_execute cat` / `Bash cat` fallback; if that also fails, report in Coverage and fall back to in-context content if available (`[degraded: context fallback]`), else prompt user to verify path.

## Loop Mode (activated by `--loop [N]` / `--循环 [N]`)

When `--loop` is present, execute a review-fix-review cycle:

1. Run standard QC review on the target.
2. **Pass** → increment consecutive pass counter (may be overridden by `--sub` subagent; see Subagent Counterfactual Mode). **Not Pass** → reset counter to 0, fix all non-WNF findings (Critical → Major → Minor; **under `--lite`: Critical/Major only** — Minors are deferred, not fixed; see Lite Mode exit below), then re-review. Recurrence: if the same finding (same dimension + location) reappears after a prior-round fix, note in history as `M(recur)`; after 3 recurrences, pause and prompt user per WNF Path 2.
3. Exit when consecutive passes ≥ N (default 3) or total rounds ≥ 15. If cap is hit while the latest rating is non-Pass (e.g., subagent reopened), report: `[Loop cap reached: X/15 rounds completed. Final rating: [rating]. Unresolved findings remain — see last round above.]`
4. Each round header: `🔄 Round X/15 | Passes: Y/N | History: [P, M, m, P, ...]` (P=Pass, C=Critical, M=Major, m=Minor; decorators: `(recur)` = finding recurred after prior-round fix; `(N WNF)` = N won't-fix items; `(N C-WNF)` = N Critical won't-fix items; `P(N def-m)` = a lite qualifying round that deferred N Minor findings; `P(prop-close)` = a proportional-close exit round (§ Exit protocols); a round's rating may be retroactively replaced in history after subagent reopening — per the Post-Dispatch Logic `update_round_history` step, `references/subagent-spec.md` § Post-Dispatch Logic). **Under `--lite`**: append ` | lite` to the header; the `Passes: Y/N` field then reads as "consecutive no-Critical/Major rounds: Y/N" (the ` | lite` tag signals this reinterpretation — no separate counter field is added).  <!-- emoji is part of this template's format spec; overrides default no-emoji rule -->
5. Target is resolved once at invocation; subsequent rounds re-review the same target — files: re-read from disk; in-context content: review the latest corrected version Claude output. Re-read failure → degrade per Parameter Parsing step 4 (which routes through the Tool Priority `cat` fallback before giving up) (`[degraded: context fallback]`); 2 consecutive failures of that full chain (Read *and* `cat` both fail on two successive rounds) → terminate with `[Loop terminated: target unreadable since round X]`. If target was auto-detected, confirm with user before entering the loop; if rejected, prompt for explicit target (step 3.4). Non-loop `/qc` with auto-detected target proceeds without confirmation by design — a single-round review is cheap to re-run, while loop mode's multi-round commitment on the wrong target is expensive.
6. Calibration files (examples.md, pitfalls.md): loaded once at loop start (= once per session — a `--resume` continuation re-reads them, see § Loop State Persistence & Resume). **Read path** — pitfalls.md exceeds a single Read window (~65–90k tokens, estimator-dependent — several × the cap), so "load it" must be executed deliberately: **L3/L4** → segmented full Read (sequential token-cap-adaptive windows — 9 measured at v2.2.0 ship; dense mid-file lines cap near ~14 lines/window, and line-bounded windows run under the token cap, so the measured count exceeds the naive size-ratio ~4; full coverage mandatory; verify the final window reaches EOF; no tag filtering). **L1/L2** → the always-read set (`[all]` / `[protocol]` / untagged entries) + target-type-relevant entries via tag-token **substring** Grep (tag combos vary in order across entries — match individual tokens like `code`, never whole-combo literals like `[code+skill]`). Grep **locates** matching lines but omits long-line content in its display (`[Omitted long matching line]` — see the pitfalls Grep-truncation entry), and pitfalls entries routinely exceed that cap: **retrieve** the selected entries via targeted Read of the located lines or a scripted line print — never treat Grep's display as the entry content. examples.md fits in one Read. Historical `#N` cross-references: entry-body sites are dual-tracked IN PLACE as 「标题」（旧 #N）(hedged 中/中高 where the map so rated; via-comment sites carry 〔=「标题」〕 annotations; 4 sites carry 〔unresolved，候选见 id-map §6〕 and stay unresolved — 宁缺勿猜), so body refs self-parse by the adjacent title with no lookup. `pitfalls-id-map.md` is a FROZEN appendix: consult it only for EXTERNAL historical refs (changelog / memory files) and for its live §9 new-ID registry; if the map is needed but missing or unreadable, degrade to title-keyword Grep over pitfalls.md (`[degraded: id-map unavailable]`). NEVER resolve any `#N` by line-jump or ordinal arithmetic (two legacy ID eras make both unreliable) — a rare bare un-annotated `#N` in live text resolves by title-keyword Grep, never by arithmetic. Evolution Protocol fires on **loop exit round only** (skipped entirely when `--lite` is active — see Evolution Protocol).
7. **State persistence**: at loop entry create the loop-state file; at each round's end append one self-contained snapshot block (written LAST, after every other disk write of that round); at the terminal exit apply the cleanup rule. Full mechanics: § Loop State Persistence & Resume.

### Lite Mode (efficiency preset) — activated by `--lite` / `--省流`

This is the **single definition point** for all `--lite` behavior — Parameter Parsing, § Model Resolution, § Dispatch Logic, and § Output Format Change cross-reference here rather than restating it. `--lite` is a token-economical preset whose lever 2 relaxes the loop exit criterion (§ Exit protocols (D4)). External semantics/behavior are unchanged from v1.15.0 (F10 equivalence).

**Four levers** (each applies only when `--lite` is active):
1. **Subagent model** → the `--sub` counterfactual runs on **Sonnet** (default Opus). An explicit `--sonnet`/`--haiku`/`--gpt` override wins (§ Model Resolution step 1). *Fires whenever `--sub` is present.*
2. **Relaxed exit** → the exit criterion relaxes to "consecutive rounds with no Critical/Major". A round **qualifies** if it has no Critical/Major (rating Pass or Minor); increment the consecutive counter on qualifying rounds, reset to 0 only when a Critical or Major appears. Between rounds fix **Critical/Major only** — Minor findings are reported and left unfixed (collected as `Deferred (lite)` in the final Summary) and never reset the counter. A Minor **reopened by the once-at-exit `--sub` counterfactual (lever 3) on the prospective exit round** is treated identically to an inline-found Minor: added to `Deferred (lite)`, recorded in that round's `P(N def-m)` token, and does NOT reset the qualifying counter — so the exit still stands (a reopened **Critical/Major**, by contrast, does reset it and the loop continues). Exit when consecutive qualifying rounds ≥ N (N from `--loop [N]`, default 3). *Fires whenever `--loop` is present.*
3. **Once-at-exit dispatch** → under `--loop --sub`, the subagent counterfactual dispatches only **once**, on the prospective exit round (the qualifying round reaching `consecutive_qualifying == N`); earlier rounds use inline counterfactual (designed behavior, not a degradation). *Fires only when both `--loop` and `--sub` are present.*
4. **Skip Evolution** → the Evolution Protocol (and its `/necess --3` gate) is skipped; emit `Evolution check: skipped (lite mode)`. *Always under lite.*

Lite does NOT change `--loop [N]`, the round cap (15), Blast Radius Scan, the five-dimension main review, per-round disk re-read, WNF semantics, or depth checkpoints.

In loop mode, "review only" is suspended: Claude fixes findings between rounds. Pause the loop if a fix needs user input or if tool failure blocks application (e.g., Write unavailable). Pauses (including WNF paths) follow normal session timeout; the loop does not auto-resume.

### Exit protocols (D4)

A loop run ends through exactly one **terminal exit path** (recorded in the round-log `exit_path` field, § Round-Effectiveness Logging). A **mid-loop flag change** is a *transition*, not an exit — recorded in the `events` array, orthogonal to `exit_path` (a run may carry both). Terminal exit paths:

1. **`npass`** — normal convergence: consecutive passes (or, under `--lite`, qualifying rounds) reach N. Default success path.
2. **`proportional`** — proportional-close, L1/L2 only (see below).
3. **`early-close`** — the user explicitly ends the loop ("到此为止" / "stop here" / "that's enough"). Record the user's exact words in `note`; report in-scope findings so far as-is. *(Only on explicit user instruction.)*
4. **`out-of-scope`** — a finding is real but outside the review's scope: report the in-scope Pass **separately** from the suspended out-of-scope item(s) so `final` reflects only in-scope status and is NOT polluted by the suspended item. (Before v2.0.0 such items had to borrow `paused` or a free-text note — now they have their own terminal path.)
5. **`cap`** — round cap (15) hit while still non-Pass (Loop Mode step 3). Unresolved findings remain.
6. **`paused`** — a WNF path, or a fix needing user input, suspends the loop (does not auto-resume).
7. **`terminated`** — abnormal termination (target unreadable, context limit).

**State-file cleanup at exit**: paths 1–5 (`npass`/`proportional`/`early-close`/`out-of-scope`/`cap`) **delete** the loop-state file AND any same-stem key-node backup under `~/.claude/qc-round-log/active-loops/` — for `cap`, only after the exit report is emitted AND the round-log line is appended (order: report → round-log → delete); paths 6–7 (`paused`/`terminated`) **keep** both, and before keeping, append the interruption marker `interrupted: <paused|terminated> @ <ISO timestamp>` immediately before the tail sentinel (§ Loop State Persistence & Resume — marker absence is how candidate discovery detects a live or crashed loop).

**Mid-loop flag change** (transition, `events` not `exit_path`): only on an **explicit user instruction** (e.g. "加上 --sub" mid-loop). Record the trajectory and the round it takes effect as `{"type":"flag-change","round":R,"from":"…","to":"…"}`. The loop continues — a flag change never ends the run.

**Proportional-close (`proportional`) — L1/L2 only** (Q5): a legitimate 2/N early exit for low-stakes small targets. **Eligibility is decided by `level`, NOT by flag combination** — the ladder combo↔level mapping is a usage suggestion, not a constraint, so an L1/L2 task carrying `--sub` is a legitimate over-provision (the "if `--sub`" clause below is a live branch, not dead logic). All conditions must hold:
- `level ∈ {L1, L2}` — **established at invocation** (explicitly declared, or inferred from invocation context per the ladder combo↔level mapping noted above) **before** the round being considered for close; a level first asserted on the exit round itself does NOT count. (The round header carries no `level` slot and Parameter Parsing has no `--level` input, so there is no per-round "header" surface to read it from — level is an invocation-time property.) Level unstated / not inferable (null) → not eligible; fall back to rigid N.
- **small target**: single file ≤300 lines, or in-context ≤200 lines.
- **clean history**: no Critical/Major anywhere in History (only P/m).
- **two consecutive Passes**.
- **if `--sub`**: the 2nd Pass's subagent verdict = `confirmed` → may close at 2/N (effective for N=3; for N=2 this coincides with the normal `npass` exit).
- **Mutually exclusive with `--lite`**: proportional-close does NOT apply under `--lite` — lite's own relaxed-exit (§ Lite Mode lever 2) is the low-stakes exit accelerator, and lite's once-at-exit dispatch (lever 3) would leave proportional's 2nd-Pass `--sub` precondition structurally unmet. A run is either lite-governed or proportional-eligible, never both; when `--lite` is active, ignore this exit and use `npass` under lite's qualifying-round criterion.
- Header tag `P(prop-close)`; round-log `exit_path=proportional`.
- **Declared L3/L4, or level unknown → this exit does NOT apply** (rigid N-consecutive-pass = red line M1-3, unaffected).
- **Interface with the S1-4 counter self-check**: when `exit_path=proportional`, `counter == 2` is the **expected** value — a legitimate exception, NOT a protocol violation.

**Fix-report brevity (D2)**: Between rounds, summarize each fix in ONE line: `- [dim] loc: what changed` (no re-explanation of why). Verbose multi-paragraph fix rationales → prohibited unless the fix was non-obvious AND triggered a WNF path, in which case include a **Why:** line limited to one sentence.

**WNF gating rule**: A finding may only be marked won't-fix (WNF) via one of these paths:
1. **User rejects fix**: user explicitly rejects Claude's fix (e.g., "don't change that", "这个别改") — must be directed at the specific fix, not general acknowledgment. Ambiguous responses → retry next round; after 3 consecutive ambiguous responses, escalate to Path 3 format (recorded as path:3).
2. **Recurrence**: finding recurs 3 times after fixes → prompt per Loop Mode step 2. User confirms WNF → mark WNF; user provides guidance → re-enter fix cycle.
3. **Infeasible fix**: Claude determines auto-fix is infeasible (constraint conflict, capability limit, disproportionate cost) → issue WNF proposal:
   `⚠️ WNF proposal: [finding ref] — [reason infeasible]`  <!-- emoji is part of this template's format spec; overrides default no-emoji rule -->
   and wait. **Consent keywords**: `WNF` / `skip` / `跳过` / `不修`. Unambiguous non-keyword expressions (e.g., "不用管了", "leave it") accepted but MUST record the user's exact words in the round report for audit. Ambiguous responses ("继续", "好", "OK") → re-prompt once; still unclear → pause loop with: "WNF consent unclear for [ref] — confirm with WNF/skip/跳过/不修 or provide fix guidance."

Path 1 counter (3 ambiguous) and Path 2 counter (3 recurrences) measure different things and are mutually exclusive (ambiguity means no fix was applied, so it cannot recur). Path 3 has the strictest consent because it originates from Claude's judgment, not user behavior. Claude MUST NOT silently mark findings as WNF based on inferred preferences — the "cannot auto-fix" judgment is Claude's; the "skip it" decision is the user's.

WNF items are excluded from subsequent round severity (a round whose only remaining findings are WNF rates as Pass). Track in header for audit (e.g., `History: [M, P(1 WNF), P, P]`). **Critical-severity WNF**: require explicit confirmation prompt and tag as `P(1 C-WNF)`.

**WNF retraction**: user explicit request ("还是修一下", "fix that after all") → remove from WNF register, re-enter fix cycle next round, reset consecutive pass counter to 0.

**No-shortcut rule (pass rounds)**: Every pass round (even consecutive) MUST:
1. **Re-read** target from disk (use Read tool; do not rely on memory; in-context targets → re-examine latest version).
2. Produce a genuine **five-dimension assessment**. Compact format (one line per verdict) is fine, but each verdict must reflect fresh examination — never copy prior round.
3. In the **counterfactual**, cite an area **different** from the prior round — prefer rotating across angle dimensions (see `references/llm-audit-antipatterns.md` §Meta-4 for a candidate rotation list). For small targets, revisiting is OK only from a different angle (e.g., correctness vs performance vs edge cases).

A pass round that copies prior output without evidence of fresh examination is a protocol violation.

### Per-round output skeleton (weak-model floor, D5)

The review's quality must not depend on model strength — every loop round emits a fixed, mechanically-checkable skeleton so a weaker model cannot silently skip a step. **Every round MUST output these five lines** (compact form; expand a verdict only for Critical/Major evidence or a checkpoint round):

1. **Header** — `🔄 Round X/15 | Passes: Y/N | History: [...]` (per Loop Mode step 4).  <!-- emoji is part of the header template's format spec -->
2. **Five-dimension verdict** — one line per dimension (or the merged `✓ … : No issues` line), each reflecting fresh examination (No-shortcut rule).
3. **RCPT** — the receipt line (below).
4. **Counterfactual** — the `**Counterfactual**:` line with its source tag (§ Output Format Change).
5. **Rating** — `**Overall Rating**: [Critical / Major / Minor / Pass]`.

A round missing any skeleton line is a protocol violation (a weak-model floor breach), not a stylistic lapse.

**RCPT receipt block** (Q5b — one line, machine-verifiable, D8/round-log-linked; kept terse so the fill-in surface is minimal even for a weak model):

```
RCPT: reread=<file@mtime | in-context-vN> counter=<consecutive-passes recomputed from History>/<declared N> angle=<this round's counterfactual angle> blast=<files scanned | NA> pitfalls=<checked/matched/triggered>
```

- `reread` — evidence the target was re-read this round (file path @ mtime, or the in-context version tag). A value unchanged across rounds with no mtime change on a file target is a No-shortcut red flag.
- `counter` — **recomputed from the History string, NOT carried in memory**: count the trailing run of Pass-equivalent rounds in History — a bare `P` **or any `P(...)`-decorated form** (`P(1 def-m)`, `P(1 WNF)`, `P(1 C-WNF)`, `P(prop-close)`) counts toward the run; an `m`, `M`, `C`, or `M(recur)` entry breaks it (under `--lite` these Pass-equivalents are the "qualifying rounds"). Write `<recomputed>/<declared N>`. **If the recomputed value ≠ the counter you were about to report, that is a protocol violation → self-correct to the History-derived value before proceeding** (History is authoritative). Exception: at an `exit_path=proportional` exit, `counter == 2` is the expected value (§ Exit protocols), not a violation.
- `angle` — the counterfactual angle used this round (must rotate vs the prior round — No-shortcut rule 3).
- `blast` — files scanned in the Blast Radius Scan (or `NA` when blast radius is skipped).
- `pitfalls` — `checked/matched/triggered` counts (mirrors the Pitfalls Check output line).

Each `RCPT:` field value is a single whitespace-free token (`\S+`) — the receipt is one space-delimited line, so a value containing a space would split into a spurious field. A multi-word `angle` must be hyphen-joined (e.g. `adversarial-reviewer`, `data-cardinality`), never left as separate words; likewise a `reread` whose target path contains spaces (e.g. an OneDrive path) must be given token-safely — `basename@mtime`, or the mtime alone — not the full spaced path. (This tightens the spec to match the machine-verifiable single-token contract the `--self-test` F11 fixture already enforces; no test-file change.)

**Depth checkpoint rounds** (round_number is a multiple of 5: rounds 5/10/15): produce a **full five-dimension report** with expanded reasoning, regardless of rating or pass streak. Treat as round 1 — fresh eyes, maximum rigor. Checkpoints and subagent counterfactual are independent; when both apply, produce both the full report AND the subagent dispatch. **Interaction with Pass-round gating**: the full-report requirement always applies at a checkpoint, but subagent dispatch still respects the loop-mode Pass-round gate in Dispatch Logic — a non-Pass checkpoint round produces the full inline report AND runs inline counterfactual (no subagent), per the `if this_round_rating == "Pass"` branch in Dispatch Logic below. **Under `--lite`**: subagent dispatch additionally respects lite's once-at-exit gate — a checkpoint round that is **not** the prospective exit round produces the full report with an **inline** counterfactual (no subagent dispatch); only a checkpoint coinciding with the prospective exit round dispatches the subagent (model per § Model Resolution; sonnet by lite default).

**Context pressure management**: In long loops (round ≥ 6, non-checkpoint), if summarizing earlier rounds becomes cheaper than carrying them in full (Claude's operational judgment — no fixed % threshold), summarize rounds 1 through (current_round - 4) into single-line records (round + rating + finding IDs) — with loop state on disk (§ Loop State Persistence & Resume) this summarization is loss-safe: anything dropped is recoverable from the last snapshot block. WNF tracking state (Path 1 ambiguity counter, Path 2 recurrence counter, WNF register) MUST NOT be summarized — keep in a dedicated block. Report `[degraded: context pressure]` in Coverage, run the context-pressure key-node backup (§ Loop State Persistence & Resume → Key-node backups), and add ONE line telling the user they may safely `/compact` now and continue via `/qc --resume` (a hint only — the loop keeps running unless the user acts). Context limit reached → terminate with `[Loop terminated: context limit reached at round X — state preserved: <state-file path>; resume with /qc --resume]`.

**Adversarial re-framing**: In rounds 2+, before reviewing, adopt: "This was written by someone else. My job is to find problems, not confirm correctness." Counteracts the tendency to validate own fixes.

### Loop State Persistence & Resume (`--resume`)

Loop state is serialized to disk every round so a `/compact`, a crash, or a new session can deterministically resume an interrupted loop. **One file per loop** — created at loop entry, appended per round, deleted on most terminal exits (no per-round temp-file litter).

**State file**: `/c/tmp/qc-loop-state/qc_loop_<session-id>_<target-hash>.md` (create the dir first: `mkdir -p /c/tmp/qc-loop-state`). `<session-id>` = a fresh unique ID from the same `date +%s`_PID_RANDOM generation as `QC_SUB_DIR` (`references/subagent-spec.md` § Subagent Working Directory) — generated independently, never coupled to an actual `--sub` dir; `<target-hash>` = a short (8-hex) hash of the resolved target path/descriptor.

**File layout** (header written once at creation; one snapshot block appended per round via Edit, inserted immediately BEFORE the tail sentinel `<!-- QC-LOOP-STATE-END -->`):

```
<!-- qc-loop-state v1 -->
created: <ISO timestamp> | session: <session-id>
target_desc: <human-readable target descriptor — REQUIRED; the filename hash is not reversible>
target_mode: file | in-context
target_path: <path (file mode) | none (in-context mode)>
level: <L1-L4 | null> | flags: <full regime: --loop N / --sub / --lite / model overrides>
main_model_start: <main-session model at loop start>

## Target Content    <- in-context mode ONLY: the ORIGINAL target copy (audit anchor — resume reviews the last snapshot's Current Content, not this)

## Snapshots

### Round <X> @ <ISO timestamp>
status: completed
history: <full History, round-log serialization form (comma-separated, decorators kept)>
counter: <Y>/<N> | angle: <this round's counterfactual angle — next round rotates against it>
target_mtime: <file mtime (file mode) | in-context version tag vN>
wnf_register: <ALL settled entries verbatim, incl. Path: n/a anchors; in-flight WNF proposals are NOT serialized>
deferred_lite: <lite Minor-deferral list | none>
events: <accumulated flag-change/resume events, JSON array — feeds the exit round-log row>
sub_tally: dispatches=<n> reopens=<n> reopen_preexit=<n>    <- feeds the exit round-log row

#### Current Content    <- in-context mode ONLY: full corrected copy of the target as of this round's end

interrupted: <paused|terminated> @ <ISO timestamp>    <- appended ONLY at a paused/terminated exit (§ Exit protocols); absent while the loop is live or after a crash

<!-- QC-LOOP-STATE-END -->
```

Each snapshot block is **complete and self-contained** — resume reads ONLY the last block, never replays earlier ones. To read just that block without slurping the whole file (an in-context target may accumulate up to 15 full `#### Current Content` copies — a context flood the weak-model floor exists to avoid), scan backward from the tail sentinel `<!-- QC-LOOP-STATE-END -->` to the last `### Round` header and read only from that offset. **Last-block integrity gate**: the per-round snapshot append is a single whole-file rewrite, assumed atomic (the Edit/Write tool writes via temp-file-then-rename, so a crash yields either the pre- or the post-write file, never a torn one). Should a runtime break that assumption, the crash model has a third state — a PARTIAL last block — that resume MUST catch rather than trust: a last `### Round` block missing any of the nine self-contained fields (status/history/counter/angle/target_mtime/wnf_register/deferred_lite/events/sub_tally), or, in in-context mode, carrying a malformed/truncated `#### Current Content`, is treated exactly like a missing snapshot — fall back to the previous intact block and rerun from there, stating that it did (a silent read of a torn block would else corrupt the resumed review — e.g. correct-looking History over truncated content).

**Write order (hard constraint)**: the snapshot is written LAST in each round — five-dimension review → fixes land on disk → `--sub` dispatch integrated → History/counter updated → THEN the snapshot. A snapshot claiming `status: completed` while a fix is not yet on disk would silently lose that fix on resume; the order makes every snapshot a receipt for work already durable. For in-context targets the snapshot's `#### Current Content` block IS the durable fix record — no other disk copy exists — so writing it is what makes the receipt claim true in that mode.

**Key-node backups** (one-shot copies, NOT per-round mirroring): copy the state file to `~/.claude/qc-round-log/active-loops/` at exactly three moments — loop entry (right after the first snapshot), entering `paused`, and the context-pressure trigger (§ Context pressure management). C:/tmp is volatile; if at resume time the primary is gone but a backup exists, offer the backup — with explicit user confirmation ALWAYS required (a fallback candidate is never direct-resumed; it may lag behind the lost primary). **Backup lifecycle**: every terminal-delete exit (paths 1–5, § Exit protocols) also deletes any same-stem backup here — deterministic exit cleanup, not GC — so completed loops leave nothing behind in `~/.claude/` (design contract: no temp-file litter). What survives in `active-loops/` is therefore only backups of genuinely `paused`/`terminated` loops — durable safety copies by design, removed when the resumed run reaches its own terminal-delete exit; a suspended loop the user never resumes leaves its backup indefinitely (deliberately — it is the user's recovery copy; delete manually if unwanted). Orphaned PRIMARY state files in C:/tmp (e.g., a `terminated` loop never resumed) rely on C:/tmp's natural cleanup — an explicit design boundary; qc builds no garbage collector of its own.

**Degradation**: if the state dir cannot be created or a snapshot write fails, note `[degraded: loop-state unavailable]` in Coverage once and CONTINUE the loop — persistence is recovery infrastructure and never blocks the review itself; but never claim resumability that does not exist (no confirmation-block promises when the file is absent).

**Resume procedure (`--resume`)**:

1. **Candidate discovery**: scan `/c/tmp/qc-loop-state/` (top level; `~/.claude/qc-round-log/active-loops/` as fallback when the primary dir is empty or missing). Classify each candidate by its **interruption marker** (`interrupted:` line, § Exit protocols): **clean** = marker present (a deliberately kept `paused`/`terminated` loop); **unmarked** = no marker — the loop is either RUNNING RIGHT NOW in a concurrent session (a live loop's file exists from entry to terminal exit) or crashed mid-round. 0 candidates → error: `No interrupted qc loop found`. Exactly 1 **clean** candidate → resume it directly (no list). A sole **unmarked** candidate → NEVER direct-resume: present it with `⚠️ no interruption marker — possibly live in another session or crashed mid-round (mtime <t>); confirm no other session owns this loop` and wait for explicit confirmation. ≥2 → list all candidates (target_desc + interrupted round + marker status `paused`|`terminated`|`⚠️ unmarked` + timestamp + session-id) and let the user pick — never auto-guess; picking an unmarked candidate repeats the ⚠️ confirmation. Fallback-dir (`active-loops/`) candidates additionally always require explicit confirmation, whatever their marker status (Key-node backups above).  <!-- ⚠️ is part of this template's format spec; overrides default no-emoji rule -->
2. **Staleness gate** (file targets only): compare the target's current mtime against the last snapshot's `target_mtime`. Mismatch → STOP and ask the user to choose: discard the state and start a fresh loop, or resume anyway (explicit confirmation that the target changed under the loop). Never proceed silently on a mismatch. **Override ordering**: if the `--resume` invocation carries an explicit target override (step 3), resolve that override FIRST so the staleness gate binds to the EFFECTIVE (post-override) target — otherwise a "state-for-A resumed against target-B" is mtime-checked against A while B is never checked at all. And because the gate is mtime-based (a heuristic, not path identity), an explicit target whose path differs from the header `target_path` is ITSELF a mismatch → STOP and confirm: resuming A's loop state against a different file B is a distinct, deliberate act, not a silent continuation.
3. **Regime restore**: level and the FULL flag regime (N value, `--sub`/`--lite` booleans, model overrides) restore from the header. Explicit flags/target on the `--resume` invocation override restored values — announce each override in the confirmation block.
4. **Confirmation block** (fixed 6-line format, emitted before the first resumed round):  <!-- emoji is part of this template's format spec; overrides default no-emoji rule -->

   ```
   🔁 QC Loop Resume | state: <file stem>
   Target: <target_desc> (<target_path | in-context>)
   Level: <level> | Flags: <effective regime; mark any overrides>
   Interrupted: round <R> (<paused|terminated|crashed — one-phrase reason>, <timestamp>)
   History: [<restored History>] | WNF: <count> | Staleness: <mtime OK | user-resolved: <choice> | n/a (in-context)>
   → Resuming at round <R+1>/15
   ```

   The line-4 reason vocabulary is `paused|terminated|crashed`: `paused`/`terminated` name a marker-recorded exit (step 1 clean class); an **unmarked** candidate the user confirmed to resume (step 1, no `interrupted:` marker — live-or-crashed) renders as `crashed — no marker` (round <R> = the last snapshotted round), so the fixed format can faithfully represent the crash-resume path its own discovery supports rather than mislabeling it `terminated`. Line 5's `Staleness` value is likewise mode-specific: file targets carry the gate result (`mtime OK` or `user-resolved: <choice>`), while an **in-context** target — whose staleness gate does not run (step 2, file-only; its `target_mtime` is a version tag, not a filesystem mtime) — renders `n/a (in-context)`, so the fixed-format weak-model floor is fully specified for both target modes.

5. **Continuation semantics**: resume at round R+1 where R = the last snapshotted round. A crash mid-round left no snapshot → that round simply reruns from its start (idempotent: fixes that already landed on disk survive and the fresh re-review sees them). Round numbering is continuous across sessions; depth-checkpoint rounds (5/10/15) re-derive from the round number; the 15-round cap counts ALL rounds across sessions (the cap red line is session-count-agnostic). Generate a FRESH `QC_SUB_DIR` — never reuse the interrupted session's. **Clear the `interrupted:` marker** as the loop reactivates (before appending the first resumed snapshot): the loop is live again, and the layout invariant is that the marker is *absent while the loop is live* — leaving it makes candidate discovery misclassify this now-live loop as clean-`paused`, so a concurrent session could direct-resume it without the ⚠️ ownership guard; it re-appends only at the next `paused`/`terminated` exit. (The residual window — two sessions running discovery *simultaneously* before either clears the marker — is the documented no-lock, user-arbitrated boundary, not closed here.) If the marker-clear write itself FAILS (the same `[degraded: loop-state unavailable]` condition as a failed snapshot write), do NOT proceed silently as a clean live loop: the stale `paused`/`terminated` marker would leave a concurrent session's discovery misclassifying this now-live loop as clean-resumable — re-opening the very failure mode this step fixes, under degradation rather than the documented simultaneous-discovery window. Surface `[degraded: loop-state unavailable]`, retry the clear, and if it still fails warn the user that ownership-guard integrity is not assured for this loop until the marker is cleared. In-context targets: review the LAST snapshot's `#### Current Content` copy — it carries all fix progress up to the last snapshotted round (the header's `## Target Content` keeps the untouched ORIGINAL as an audit anchor; fall back to it only if no snapshot carries a content block, and say so — that fallback DOES lose all fix progress and re-reviews the original). Crash-loss asymmetry (explicit): a file target's applied fixes survive on disk even un-snapshotted; an in-context target's fixes are durable only through the snapshot's content block, so its un-snapshotted round is lost entirely — bounded at one round of fix progress, accepted by design.
6. **Round-log linkage**: the resumed run's exit row carries a `resume` event (§ Round-Effectiveness Logging → resumed-run linkage).

## Subagent Counterfactual Mode (activated by `--sub` / `--子代理`)

When `--sub` is present, the counterfactual test (see meta-calibration principle in Key Principles) is delegated to a physically isolated subagent instead of running inline. This provides genuine context isolation — the subagent has never seen the generation or review process, eliminating self-review bias. In loop mode, dispatch is gated to Pass rounds only — non-Pass rounds already have surfaced findings to fix, so inline counterfactual suffices there (see Dispatch Logic below).

### Model Resolution

The counterfactual subagent's model is the **verifier-tier** — a role, not a hardcoded product name. It is resolved once per dispatch (highest precedence first):

1. **Explicit model-override flag** — `--gpt` → GPT (Codex CLI); `--sonnet` → Claude Sonnet; `--haiku` → Claude Haiku. Explicit wins over everything below.
2. **Else `--lite` active** → Claude Sonnet (implicit override — see § Lite Mode; an explicit flag in step 1 outranks it).
3. **Else the default verifier-tier**, resolved in two sub-steps:
   a. **Consume the global routing rule** `~/.claude/rules/model-effort-routing.md` — its §1 speed-table and §4 verify-gate pin the qc `--sub` dispatch to **Opus** (a permanent verification gate, annotated there as qc's built-in default, "勿改"). Use that pinned model.
   b. **Fallback chain** — if the routing rule is unreadable or yields no qc-`--sub` policy value (file missing, permission error, or the rule was restructured / the section moved), fall back to the historical hardcoded default **Opus** AND emit `[degraded: routing-rule unavailable]`. The fallback is never silent: a routing-rule change that hides the policy value must be observable, so the routing rule is treated as a versioned external dependency (same principle as § Degradation's `subagent-spec unavailable`).

The resolved model is identical to v1.15.0's chain in every case — explicit override > `--lite`→Sonnet > default Opus — so this is a **purely structural** change (the scattered "strongest = opus" hardcode is replaced by a single `verifier-tier` role sourced from consume-then-fallback); behavior is unchanged (validated by the F13 model-resolution assertions: no override + non-lite → opus; `--lite` + no override → sonnet).

Dispatch target by resolved model:
- **opus / sonnet / haiku** → in-harness Claude subagent via the Agent tool (`general-purpose`) with an explicit `model:` parameter. File-transport verdict (`verdict_temp.json`) — the existing flow, only the `model:` value changes.
- **gpt** → out-of-harness **Codex CLI** (`codex exec`), a genuinely different model family — NEVER the Agent tool (Claude-only) and NEVER the `codex:codex-rescue` agent (it runs in-harness Claude — a documented non-cross-model trap). Stdout-transport verdict. See § GPT Cross-Model Dispatch.

**Model attestation (anti-silent-drift — MANDATORY every dispatch)**: the verdict JSON carries a `verifier_model` field (the subagent/GPT self-reports the model it actually ran as), and the main agent cross-checks it against the requested model. **Comparison is family-level** (opus / sonnet / haiku / gpt): a requested `opus` matches an attested `claude-opus-4-6[1m]` (same family → no drift); a requested `sonnet` attested as `claude-opus-4-6` is a family mismatch → drift. Record the **exact** attested model string in the tag (e.g. `[subagent:claude-opus-4-6[1m]]`), not only the family. A global `CLAUDE_CODE_SUBAGENT_MODEL` env var may take precedence over the per-call `model:` (per `~/.claude/rules/token-economy.md`), so a per-call `model: "sonnet"` can be silently overridden to the env model — **attestation is what surfaces this instead of letting it pass as the requested model**. On mismatch → tag the round `[model drift: requested X, attested Y]` and treat per § Degradation; always report the **attested** model, never the requested one. **If the attestation source is absent** (Claude: `verifier_model` empty/missing; GPT: no Codex `model:` header) → attestation is **inconclusive**: tag `[model unconfirmed]`, report the requested model as *unverified*, and do not assert it ran. The GPT path adds a **stronger, external** attestation (Codex's own `model:` header line) — see § GPT Cross-Model Dispatch. The attested model appears in every Counterfactual line (see Output Format Change).

The Pass-round / lite gating above is identical regardless of model/target; only the dispatch mechanism and verdict transport differ.

> Note: `consecutive_qualifying` is the **same** Loop-Mode consecutive-pass counter, with its increment criterion relaxed from "Pass" to "no Critical/Major" — NOT a new variable.

> Lite exit-gate reopen handling: if the exit-gate subagent reopens with a genuine new **Critical/Major** → reset the counter and continue (it may re-dispatch at the next prospective exit). If it reopens with **Minor only** → under lite that does not gate; log the Minor as `Deferred (lite)`, do not reset. The round remains **qualifying** (no C/M), so the counter **increments normally** → `consecutive_qualifying` reaches N → loop exits; a Minor-only reopen neither blocks exit nor re-fires the subagent. (Reset/recalc behavior is the lite carve-out added to `references/subagent-spec.md` § Post-Dispatch Logic.)

> **Confirmed + severity_adjustments**: A `confirmed` verdict may still include non-empty `severity_adjustments` (e.g., the subagent agrees no new issues were missed but recommends re-rating an existing finding). These adjustments are applied to the main report regardless of verdict.

> **Confirmed + wnf_reidentified**: A `confirmed` verdict may include non-empty `wnf_reidentified` — the subagent found no genuinely new issues but re-identified known WNF items (or declined-observation anchors, `Path: n/a`). These are logged for audit trail but do not affect rating or pass counter. If the subagent returns verdict `reopened` with `new_findings` empty after cross-check (all items matched WNF register), the verdict is overridden to `confirmed`.

> **Confirmed + new_findings**: If a subagent returns `confirmed` with non-empty `new_findings` (self-contradictory output), the verdict takes precedence — `new_findings` are not processed (the `if result.verdict == "reopened"` branch is never entered). Log a warning in the round report if this occurs.

> **Anti-downgrade self-check**: Before writing the `**Counterfactual**:` line, verify: "Is `--sub` active AND is this round rated Pass (loop mode) or any rating (non-loop)?" If YES, you MUST dispatch a subagent — if you find yourself about to write an inline counterfactual when the condition is met, STOP and dispatch the subagent instead. Never silently downgrade to inline without reporting `[degraded: inline fallback]` and the specific failure reason. If NO (i.e., loop mode + non-Pass round), inline counterfactual is the **designed behavior** — no degradation tag needed. **Under `--lite` (loop+sub)**: the dispatch condition is narrower — you MUST dispatch only on the **prospective exit round** (the qualifying round reaching `consecutive_qualifying == N`); inline counterfactual on every earlier round (including qualifying ones) is the **designed** behavior, not a degradation (no tag). The `[degraded: inline fallback]` tag still applies if a genuine dispatch failure occurs on the exit-gate round itself.

### GPT Cross-Model Dispatch (resolved model = gpt, via `--gpt`)

The `--gpt` counterfactual runs on a real GPT model through the **Codex CLI** — the only path that reaches a different model family. The Agent tool cannot (Claude-only); the `codex:codex-rescue` agent MUST NOT be used (it runs in-harness Claude — a documented trap, see the `cross-model-fact-check-via-codex-cli` skill). Reuses `QC_SUB_DIR`; verdict travels via **stdout** (Codex runs `-s read-only` and cannot write the file-transport JSON).

**The verbatim procedure** — the `gpt_input.txt` build, the exact `codex exec` command, and the parse — lives in `references/subagent-spec.md` § GPT Cross-Model Dispatch Procedure (moved there in v2.0.0 to cut per-load cost). SKILL.md keeps only the behavior rules:

- **Prerequisite**: `codex` on PATH (`codex --version` → `codex-cli …`). Absent/unconfigured → degrade per § Degradation (`[degraded: gpt unavailable → inline]`).
- **Model source**: pinned by the **verification profile** — the dispatch passes `--profile verify`, loading `~/.codex/verify.config.toml` over the base config (the user's strongest verification tier + high effort; do **NOT** pass `-m`). `--gpt` tracks that profile **by design**; the exact model is always recorded in the `[gpt:<exact model>]` tag, so a profile change is *visible, never silent*. A missing/renamed profile file silently falls back to the base config (exit 0, no warning — empirically verified) — the attestation gate below catches that silent mode only when the fallback lands on a non-GPT model (it checks family, not tier); a same-family fallback is surfaced by the exact model recorded in the `[gpt:<attested model>]` tag, so inspect the attested model rather than assuming the profile loaded — a read that distinguishes a fallback only while the verify profile pins a different model than base; under a lockstep base==verify config a silent fallback is indistinguishable by any run signal, and harmless (the same tier runs either way).
- **Attestation (anti-drift gate — MANDATORY, before parsing)**: confirm all **THREE** model signals agree and are GPT-family (case-insensitive `GPT`) — (a) `gpt_err.txt` `model:` header (authoritative), (b) `gpt_out.txt` `MODEL=`, (c) the parsed `verifier_model`. Any signal naming a Claude/non-GPT model, or the three disagreeing → **NOT cross-model** → tag `[model drift: gpt requested, attested <X>]`, degrade to inline, do **not** emit `[gpt:*]`; a signal merely *absent* → `[model unconfirmed]`. Gate on **content AND exit code**: require exit 0 *and* valid content (exit 0 alone can be a refusal; an absent `model:` header = the run never happened).
- **Cost / safety**: each dispatch is a real OpenAI API call (cost + latency) — one GPT call per Pass round in `--loop --sub --gpt` (non-lite), or once on the prospective exit round under `--lite`. Codex enforces the same non-C-drive isolation as Claude Code (config + hook), so a GPT verifier is drive-safe; never pass a non-C path to Codex (`-C` and all I/O stay on C:).

### Degradation

If subagent dispatch fails (tool error — including Write tool failure when creating temp files —, timeout, unavailable model, etc.) → fall back to inline counterfactual. Report line shows `[degraded: inline fallback]`.

Invalid subagent response (`verdict_temp.json` missing after the subagent returns, unreadable or unparseable JSON, missing required fields such as `verdict`, or markdown wrapping inside the file despite the raw-JSON instruction) → treat as dispatch failure: fall back to inline counterfactual with `[degraded: subagent JSON invalid]` tag and include a one-line excerpt of the malformed file content (or note the file's absence) in the round report for user audit. The subagent's final chat message is NOT a fallback verdict channel — do not attempt to parse a verdict out of it.

If `references/subagent-spec.md` is unreadable (file missing, permission denied, encoding error) → the canonical subagent prompt template is unavailable; `--sub` cannot dispatch correctly. Fall back to inline counterfactual and tag `[degraded: subagent-spec unavailable]` with the specific file-read failure reason. Do NOT attempt to reconstruct the template from memory — it is intentionally versioned separately to avoid drift.

Model-override degradation: if `--gpt` is active but Codex is unavailable (no `codex` on PATH, CLI error / non-zero exit, empty `gpt_out.txt`) → fall back to inline counterfactual, tag `[degraded: gpt unavailable → inline]`. **The requested cross-model GPT check did NOT run** — this is a *prominent* degradation, not a silent substitution: the round's counterfactual is inline Claude (NOT cross-model), so state it explicitly in the report, record the degradation in the round-log, do **not** emit a `[gpt:*]` tag, and do **not** represent the round as cross-model-verified. In loop mode the loop continues (inline preserves progress). If the GPT attestation gate fails, split by cause: (a) the Codex `model:` header / `MODEL=` line is **absent** (no attestation to read) → tag `[model unconfirmed]` (matching its Output-Format-Change definition below) and fall back to inline; (b) the header is **present but names a non-GPT/Claude model** → tag `[model drift: gpt requested, attested <X>]` (`<X>` = the attested model) and fall back to inline. Either way the run is NOT cross-model; do NOT use its verdict as a GPT check. For Claude `--sonnet`/`--haiku`: if the `verifier_model` attestation disagrees with the requested model (e.g. a `CLAUDE_CODE_SUBAGENT_MODEL` env override) → tag `[model drift: requested X, attested Y]`; the verdict still stands as an independent isolated check (no inline fallback needed), but report the **attested** model, never the requested one.

## Blast Radius Scan (file modifications only)

When the review target includes file modifications (including `directory`/`目录` targets, which are treated as multi-file change sets), perform this pre-scan before the five dimensions:

1. Identify the change set: if a diff/changeset is available, use it; otherwise list session-modified files **relevant to the review target** (not the entire session indiscriminately)
2. **Declare scan boundary explicitly** in the report (see template below): state which files are in scope and which directories were searched
3. For each changed file, search for other files that reference it — use Grep for the filename/path; check import/require/source statements; search index files (MEMORY.md, CLAUDE.md, AGENTS.md, README.md, package manifests, repo-local instruction files) for references. Scope: current working directory; also `~/.claude/` if config files are involved. This scan does not automatically reach fixed paths outside the workspace; for known external dependencies, encode them as pitfalls entries.
4. For each reference found, assess whether it is a substantive dependency (not just a passing mention) and whether it needs updating
5. Feed findings into the Completeness dimension below
6. For config files (`.bashrc`, `settings.json`, `mcp.json`, `MEMORY.md`, `rules/*`, `scripts/*`), also verify against any workspace instruction file that defines linked-update rules (e.g., `CLAUDE.md`, `AGENTS.md`, repo-local policy files) if present
7. **Version-bump consistency scan** (fires when target file contains a version marker — `<!-- version: X.Y.Z -->`, `**Version**: vX.Y.Z`, `"version": "X.Y.Z"`, or similar conventional patterns): Grep the old version string across the repo-level anchor files (README.md, CHANGELOG.md, MEMORY.md, AGENTS.md, package manifests, plugin-details.md) and `~/.claude/` if this is a skill/plugin config. Report all stale matches as Completeness findings. Scope note: this is **value-consistency dependency** (different axis from step 3's reference dependency); run both.

**Boundary rule**: If the user provides only a file path (e.g., `/qc file.R`) without a diff/changeset and no session modifications exist for that file, treat it as a **standalone content review** — skip blast radius. Only perform blast radius when (a) a diff/changeset is explicitly provided, (b) the file was modified in the current session, or (c) the user explicitly asks to review modification impact.

Skip this step **only** when the review target is entirely standalone content with no file dependencies (this includes the file-path-only scenario described in the boundary rule above, as well as freestanding advice, unsaved document drafts, or plans not tied to existing files).

If Grep fails during blast radius scanning, first apply the Tool Priority § Blast-radius-Grep fallback (`Bash grep` via `ctx_execute`); only if that also fails, report `[degraded: no blast radius]` in the Blast Radius output line and note the limitation in Coverage.

## Review Framework (Five Dimensions)

Examine each dimension and render a verdict:

| Dimension | Core Question |
|-----------|---------------|
| Correctness | Facts accurate? Logic sound? No hallucinations or fabrications? |
| Completeness | All key points covered? Edge cases considered? † |
| Optimality | Is this the best approach? Any simpler or more efficient alternatives? |
| Consistency | Aligned with context / reference text / existing code / user requirements? No self-contradictions? Doc/code contract drift (documented return values, function signatures, schema fields silently mismatched in implementation) routes here, not Completeness. |
| Standards | Compliant with relevant standards? (academic conventions / coding style / security rules) |

> **Routing rule (Consistency vs Completeness)**: any mismatch between **documented behaviour** (docstring, type hint, comment, frontmatter, README claim) and **implemented behaviour** routes to **Consistency**, NOT Completeness. Completeness is reserved for *unaddressed edge cases* where no documentation exists (e.g., NA handling, empty input, NULL paths). Worked example: a docstring promises `$n` (sample size) but the return list omits it → **Consistency Minor** (default; escalate to Major only on demonstrated downstream failure).

> † For file modifications, Completeness includes blast radius — see **Blast Radius Scan** above.

### Target-Specific Overlays

- **Code**: +Security vulnerabilities +Performance +Error handling +Readability +Dependency reasonableness +Test coverage
- **Plan**: +Feasibility (technical / resource / timeline achievability) +Potential risks (list top 3; label each Probability High/Med/Low × Impact High/Med/Low) +Mitigation strategies (1–2 sentences per risk) +Missing steps (list critical omissions) +Resource estimates (personnel / time / tools; quantify)
- **Document**: +Citation authenticity +Fact-checking +Academic standards (STROBE / CONSORT, etc.) +Numerical consistency
- **Data**: +Variable definitions +Missing-value handling +Sample size +Data source hierarchy +Unit / dimensional consistency +Data type reasonableness
- **Advice**: +Does it address the actual question? +Any better alternatives? +Potential side effects or negative consequences +Applicable boundaries and prerequisites
- **Memory/Rules/Config** (high-freq, L4-heavy — apply when the target is a memory file, `rules/*`, `settings.json`, `mcp.json`, `CLAUDE.md`/`AGENTS.md`, or similar runtime/state config; layered on top of the primary type): +Linked-update completeness (every cross-referencing file updated — pairs with Blast Radius Scan) +MEMORY.md pointer consistency (pointer ↔ file existence/name) +three-check rule compliance (sync related sections within the file / update MEMORY.md if it references this config / update dependent files) +version-bump consistency +authorization-scope correctness (L-level matches the edit's blast radius)

- **Skill/Prompt**: +Trigger/activation boundary clarity +Parameter parsing edge cases (spaces, quotes, empty input) +Consistency between instruction text and examples +Token cost awareness (mandatory pre-reads, growing reference files) +Portability assumptions (which runtime features are required?) +Degradation path coverage (does the skill define behavior when tools are unavailable or context is insufficient? — missing → Major) +Self-review bias risk (does the same agent both generate and review output without isolation? — Minor, design limitation) +Runtime vs development material boundary (are files clearly marked as runtime-loaded vs development-only reference? — Minor, cognitive burden) +LLM audit anti-patterns (on-demand reference: `references/llm-audit-antipatterns.md` §A 7 runtime patterns / §B 3 completeness principles / §C 4 LLM-as-auditor meta patterns — consult when the Skill/Prompt target is itself an LLM-facing prompt or audit harness; not a mandatory checklist)

- **Commit/PR text** (low-frequency — apply when the target is a commit message, PR/issue body, or release notes): load the Commit/PR text overlay from `references/overlays.md`.
- **Faithful-transcription/wiki-page** (low-frequency — apply when the target is a verbatim transcription or a wiki/knowledge-base page): load the Faithful-transcription/wiki-page overlay from `references/overlays.md`.

> **Low-frequency overlays are externalized to `references/overlays.md`** (v2.3.0): the four overlays immediately above (Figure/Table, Translation, Commit/PR text, Faithful-transcription/wiki-page) recur rarely, so their `+Check` items live in that file and are **loaded on demand** — read it (small, one Read window) only when the resolved Target Type matches one of the four, then apply the matching overlay's checks on top of the base five dimensions. Do NOT pre-load it for the six base types (Code/Plan/Document/Data/Advice/Skill/Prompt) or the two high-frequency inline overlays (Memory/Rules/Config, Handoff/Prompt), which recur constantly and stay inline. **Degradation**: if `references/overlays.md` cannot be read (missing / unreadable), emit `[degraded: overlays unavailable]` and review with the base five dimensions only — the same coverage these types received before v2.3.0, so this is not a regression.

## Tool Priority

When multiple tool options exist for a QC operation, use the preferred tool first and degrade per the table below. Degradation triggers are **consecutive failures** (not first-time errors). Transient failures do not trigger fallback.

| Operation | Preferred tool | Degradation trigger | Fallback path |
|-----------|----------------|---------------------|---------------|
| Read target | Read | Read returns error 2 consecutive times | `ctx_execute cat` or `Bash cat` |
| Subagent dispatch | Agent (`general-purpose`, model per § Model Resolution) | First dispatch yields missing/invalid `verdict_temp.json` (Meta-3) → no retry | inline counterfactual + `[degraded: subagent JSON invalid]` tag |
| GPT cross-model dispatch (`--gpt`) | Codex CLI (`codex exec --profile verify`, verification-profile model — `~/.codex/verify.config.toml`) | `codex` absent / non-zero exit / attestation gate fails (attestation absent, or attested non-GPT) | inline counterfactual + `[degraded: gpt unavailable → inline]` (codex absent/errored) / `[model unconfirmed]` (attestation absent) / `[model drift: …]` (attested non-GPT) tag — see § Degradation for the absent → `[model unconfirmed]` vs present-non-GPT → `[model drift]` split |
| Blast radius Grep | Grep | Grep 2 consecutive failures | `Bash grep` via `ctx_execute` sandbox |
| Anchor re-verify (pre-edit) | Grep (content mode, exact keyword) | Grep 2 consecutive failures | `Bash grep` via `ctx_execute` sandbox |
| Checkpoint report | Inline generation | Exceeds token budget | Compact wrap + `[degraded: checkpoint abbreviated]` tag |

## Key Principles

- **Output calibration**: Before writing the report, read `examples.md` (format/severity calibration) and `pitfalls.md` (user-specified check items) from this skill's directory (`~/.claude/skills/qc/`). For each pitfall entry, first assess whether its trigger tag (if present) matches the current review target type and context; only apply matching entries. In the Pitfalls Check output line, report: checked X entries; Y matched context; Z triggered findings. Scan tags/headings first and read only matching sections in full. If either file is unavailable or empty, proceed without it.
- **Pitfalls tag matching rules**: `[tag1/tag2]` — `/` means OR; an entry applies if ANY listed tag matches the current context. No tag = always applicable (same as `[all]`). Matching is contextual (AI judges applicability), not a literal string comparison against the target type name. Suggested tags: `[all]`, `[code]`, `[academic]`, `[academic/statistics]`, `[file-modification]`, `[file-path]`, `[code/R/Python]`, `[skill/prompt]`. Keep tags within a single dimension (object type OR action context OR language); avoid mixing dimensions in one OR group.
- **Review only — no auto-fixes**: Output the review report only. Do not modify any content automatically. Fixes are the user's decision. (This principle is suspended when `--loop` is active — see **Loop Mode** above.)
- **Evidence-led, not suspicion-led**: Every finding in the Findings section must have concrete evidence (direct quote, file:line, code snippet, or explicit absence citation). Uncertain items without sufficient evidence → place in the **Open Questions** section instead. Goal: zero missed real issues — but suspicions without evidence are questions, not findings.
- **Reference project-level academic rules**: If academic workflow rules (e.g., citation verification, numerical reporting standards) are present in the current context, prioritise them.
- **Language**: this spec's structure and rules are written in English; incident quotes carried in pitfalls/examples keep their **original** language (evidence fidelity — do not translate them); the runtime QC report language **follows the session language**.
- **Additional criteria take priority**: User-specified additional criteria are checked first, on top of the five-dimensional framework.
- **Never skip Blast Radius Scan**: For any review involving file modifications, MUST perform the Blast Radius Scan before the five dimensions. When in doubt about whether it applies, perform it — false negatives are costlier than false positives.
- **Reviewer-prompt integrity (no pre-judging)**: When you construct any dispatched review prompt — the `--sub` subagent's `## Additional Context`, or any reviewer/judge you brief elsewhere — never tell it to ignore, downplay, or pre-rate a finding ("don't flag X", "Minor at most", "this was intentional"); suppressing findings or pre-setting severity defeats the isolation. Treat the generator's own rationale ("kept it simple", "YAGNI") as an **unverified claim**, never as evidence that lowers severity. (Adapted from superpowers v6 task-reviewer; complements **Adversarial re-framing** and the canonical template's Additional Context Constraint.)
- **Meta-calibration before finalizing**: Before writing the Summary section, re-read all findings and ask:
  1. Would I rate this the same severity if it appeared in isolation?
  2. Am I inflating because I found too few issues, or deflating because I found too many?
  3. **Counterfactual test** (mandatory for all ratings): Ask the question matching the current rating — for Pass/Minor: "If this exact target were submitted by a stranger for first-time review, would I still find no Critical or Major issues?"; for Major/Critical: "Am I understating severity — could this be Critical / is this truly Major?". If uncertain, pick the weakest area and re-examine it with adversarial intent before confirming. In Loop Mode rounds 2+, the reasoning must specifically address whether the fixes applied in the previous round are correct and complete.
     **Operational guidance for effective counterfactual execution**:
     - Start from the execution layer (scripts, configs) rather than documentation — docs get covered in normal QC; execution code is the trust blind spot.
     - Verify implementation assumptions — seeing a comment or label (e.g., `<!-- T050 -->`) does not mean the system enforces it; read the enforcement code to confirm.
     - Scan for namespace collisions — ID/key/variable uniqueness is the most common collision point in self-testing code.
     - Trace the root cause chain — after finding a bug, ask "why could this bug exist?" to identify missing guards, registries, or spec coverage.
  Adjust if needed.

## Failure Modes

- **Self-review confirmation bias**: counterfactual test degenerates to mechanical "Confirmed" without re-examination, especially under context pressure or many findings. *Mitigation*: counterfactual MUST articulate a specific alternative interpretation before confirming; flag all-confirmed rounds without substantive reasoning.
- **Loop convergence dependency on WNF protocol**: ambiguous user responses or disengagement from WNF prompts can stall the loop. *Mitigation*: 3-path WNF with explicit consent keywords; ambiguity counter escalates to Path 3 after 3 unclear responses; round cap (15) as hard stop.
- **Subagent context isolation loss**: template drift (rewording, missing sections, stale refs) silently degrades subagent review. *Mitigation*: copy the canonical template literally; verify template version matches SKILL.md.
- **WNF state loss under compaction**: WNF tracking state in conversation context can be lost during summarization, re-raising dismissed findings. *Mitigation*: anchor WNF state in findings file, not conversation alone; verify WNF register survives compaction. (Historical: v1.3.0 added `## WNF Register` to qc_input_temp.md + `wnf_reidentified` JSON field + dispatch-logic cross-check to fix **Subagent WNF blindness**.)
- **Subagent temp file race**: target can change between temp write and subagent read; external processes can overwrite `qc_input_temp.md`. *Mitigation*: subagent cross-validates temp copy vs disk original (authoritative); session-unique `QC_SUB_DIR`; verify temp file timestamp before dispatch. (Historical: v1.2.0 fixed **concurrent `--sub` temp collision** on the shared `C:/tmp/qc_sub/`.)
- **MCP tool name environment drift**: hardcoded MCP tool names silently fail after env changes. *Mitigation*: "tool not found" → degrade gracefully; log missing tool for user.
- **Pass-round no-shortcut degradation**: pass rounds silently degrade to copy-previous without fresh re-read. Distinct from confirmation bias — affects the core five-dimension assessment, not the counterfactual. *Mitigation*: no-shortcut rule (re-read from disk, fresh verdicts, rotating counterfactual focus); copy-previous without evidence is a protocol violation.
- **Depth checkpoint skipping under context pressure**: checkpoint rounds may produce compact format under context pressure, negating the anti-degradation purpose. *Mitigation*: checkpoints are mandatory regardless of context; cannot produce full report → flag `[degraded: checkpoint abbreviated]` in Coverage.
- **Adversarial re-framing fatigue**: "written by someone else" stance decays over many rounds as agent identifies with own fixes. Distinct from confirmation bias — affects the full review posture, not just the counterfactual. *Mitigation*: depth checkpoints at rounds 5/10/15 force fresh-eyes pass; round cap (15) limits cumulative fatigue.
- **Category dispatch coverage gap**: dispatch logic (pitfalls tag matching, overlay selection) may handle one category but silently skip others. *Mitigation*: assert dispatch coverage matches reference file categories before review; flag unrouted categories.

## Round-Effectiveness Logging (token-economy instrumentation, v1.10.0; round-log schema v2 in v2.0.0)

At **loop exit** (Loop Mode only; skip for single-round `/qc`), append ONE line to `/c/tmp/qc-round-log/qc-rounds.jsonl` (create the dir first: `mkdir -p /c/tmp/qc-round-log`), then proceed to Evolution Protocol. Purpose: gather cross-session evidence on whether later rounds and `--sub` subagent dispatches actually change the verdict — the input to `~/.claude/rules/token-economy.md` C4 (deciding whether L3/L4 verification rounds can be safely downgraded).

Write via Bash `echo '<json>' >> /c/tmp/qc-round-log/qc-rounds.jsonl`. Use **multi-character JSON keys only** (a single-letter key before `:` — e.g. `"N":` — trips the BV-9 drive-letter false-positive hook; see CLAUDE.md § Programming). **round-log schema v2** (v2.0.0): all v1.15.0 keys preserved (red line M1-5) plus `schema`/`exit_path`/`events`/`note`, and controlled enums on `level`/`exit_path`/`final`:

`{"schema":2,"date":"<YYYY-MM-DD>","level":"<L1|L2|L3|L4, or null if unstated>","main_model":"<main-session model alias: sonnet|opus|fable — read from your own system-prompt model identity; null if genuinely unstated>","category":"<config-rule|skill-agent|memory-file|manuscript|analysis-code|wiki-ingest|handoff-meta|other — infer from the review target's path/content; when unsure use other>","npass":<N>,"sub":<true|false>,"lite":<true|false>,"rounds":<total rounds>,"history":"<History as stored — strip the header's surrounding brackets and inter-item spaces, KEEP decorators, comma-separate; e.g. P,M(recur),P(1 WNF),P — this compact form is the log serialization, distinct from the display-only bracketed [P, M, m, P] header form>","exit_path":"<npass|proportional|early-close|out-of-scope|cap|paused|terminated — the single terminal exit, per § Exit protocols>","events":[{"type":"flag-change","round":<R>,"from":"<flags>","to":"<flags>"}],"note":"<free-text catch-all, optional — e.g. the user's exact words on early-close>","sub_model":"<attested model of the --sub dispatches: opus|sonnet|haiku|gpt-<ver>; null if no --sub; first-attested if mixed>","sub_dispatches":<count>,"sub_reopens":<rounds where the --sub subagent reopened a would-be Pass>,"sub_reopen_preexit":<of those reopens, how many were on a pre-exit Pass round (not the prospective-exit round) — raw position data for the exit-only-dispatch token-economy lever; see Key metrics #3 below for interpretation + the lite:false caveat; 0 if no reopen>,"final":"<Pass|Minor|Major|Critical|paused|terminated>"}`

**schema v2 field rules**:
- `schema`: literal `2` — the generation marker. Historical rows (the v1.15.0-era append-only lines) have NO `schema` key; analysis scripts MUST **defend both generations** (absent `schema` ⇒ generation 1; `schema:2` ⇒ generation 2). Existing rows are NEVER rewritten (red line M1-5; append-only, Q5c).
- `exit_path` (**terminal only**): exactly one § Exit protocols path. `out-of-scope` no longer borrows `paused` or a free-text note. `level`/`exit_path`/`final` are controlled enums — typo/free-text variants are protocol violations (F8 asserts).
- `events` (**optional array**, omit when empty): mid-loop transitions that are NOT exits — `{"type":"flag-change","round","from","to"}` or `{"type":"resume","round":<first resumed round>,"state":"<state-file stem>"}` (`type` is a controlled enum: `flag-change` | `resume`). A run may carry both `events` entries and a terminal `exit_path`; the two are **orthogonal** — neither `flag-change` nor `resume` may occupy `exit_path` (F8 asserts the coexistence).
- `note` (**optional**): the single free-text catch-all — all ad-hoc annotations go here, so no whole-line ad-hoc row variants (the P2 failure mode) reappear.
- **Resumed-run linkage** (v2.1.0): a run interrupted as `paused`/`terminated` writes its row at interruption with the state-file stem in `note` (`state: <stem>`). The resumed continuation writes a fresh row at ITS exit whose `events` carries the `resume` entry with the same stem and whose `history`/`rounds`/`sub_*` tallies cover the FULL run (pre-interruption rounds included — restored from the snapshot). Rows sharing a stem are one logical run; metric reads treat the latest row as authoritative and drop the earlier interruption row(s) from per-run denominators. Append-only is untouched — interruption rows are never rewritten (red line M1-5). If the resuming session's main model differs from `main_model_start` in the state header, `main_model` records the exit session's model and `note` additionally carries `main_model mixed: <start>-><resume>`.
- **Proportional-close three-form binding** (anti-drift): the concept "proportional-close" ⟺ `exit_path=proportional` ⟺ header tag `P(prop-close)` — one mapping, fixed at spec-authoring; never spell it three different ways.

**Archival** (Q5d): the write path stays `/c/tmp/qc-round-log/` (zero permission friction); an **idempotent archive** to `~/.claude/qc-round-log/` (the saving-mode-logs "buffer → consolidate → move to `_consolidated/`" pattern) runs at the Evolution time-point (default — implementation is entirely in SKILL.md, no new authorization surface). C4/M5 metric reads take the archive + buffer union as the corpus.

**Populating `sub_reopen_preexit`**: during the loop, when a `--sub` dispatch reopens a would-be Pass, note whether this round's Pass would bring consecutive passes to ≥ N (the prospective-exit round) or leave them < N (an earlier, pre-exit round); tally the pre-exit ones. Pure observation — it does not change dispatch, rating, or the loop (per the Non-blocking note below).

**Key metrics** (read four ways, all on evidence not assumption):
1. **Opus-gate value** (resolved 2026-06-25, KEEP): the **per-run** reopen rate — (L3/L4 Opus runs with `sub_reopens`>0) ÷ (runs with `sub:true`) — was ~28% (L3) / ~42% (L4) at the resolution snapshot (2026-06-24; the 2026-07-05 recount over a larger denominator gives ~31% / ~45% — same KEEP conclusion), so the Opus gate is non-redundant (token-economy C4, whose denominator is *runs* not dispatches; the pooled Σ`sub_reopens`/Σ`sub_dispatches` is a distinct, smaller per-dispatch rate).
2. **Model-downgrade question** (open): stratify the same reopen-rate **by `sub_model`** — a cheaper model (`sonnet`/`haiku`/`gpt-<ver>`) is a safe substitute only if its reopen-rate matches Opus's **and its reopens are validated as real** (a weaker model may match the rate at lower precision — more false reopens; the log records reopen *count*, not *validity*). So this needs deliberate comparison runs **with human / cross-model validation of the cheaper model's reopens**, not the log alone — and non-Opus rows accrue only under 省流 or an explicit `--sonnet`/`--haiku`/`--gpt`.
3. **Exit-only-dispatch question** (open — a token-economy downgrade lever): read `sub_reopen_preexit` as a **conservative** signal, **over `lite:false` L3 runs only** (`lite:true` runs already dispatch once at exit, so their `sub_reopen_preexit` is structurally 0 and would bias the pooled signal toward "exit-only is free") — ≈ 0 across those runs ⇒ dispatching `--sub` only on the prospective-exit round loses nothing → L3 drops to one dispatch/loop; > 0 is inconclusive (check whether those issues recur at the exit round before concluding). The clean answer is an explicit every-round-vs-exit-only A/B.
4. **Main-model stratification** (routing observation, added 2026-07-05): stratify the per-run reopen rate by `main_model` — the Sonnet-baseline reform (rules/model-effort-routing.md; ADR-0001) watches whether Sonnet-main runs reopen materially more than the Opus-main baseline (single-item rollback trigger: ≥1.5× with n≥10; criteria table in ADR-0001 appendix). `category` additionally enables task-type × reopen analysis (e.g. wiki-ingest quality watch).

**Non-blocking**: if the dir is unwritable or the echo fails, **skip silently** — note `[degraded: round-log skipped]` in Coverage at most once. This logging NEVER alters review logic, ratings, fixes, or the loop; it is pure observation.

## Evolution Protocol

After completing the QC report (in Loop Mode: loop exit round only — see Loop Mode section; skipped on abnormal terminations such as target-unreadable, context-limit, or loop-cap-without-convergence exits where unresolved findings remain), self-reflect on whether the review surfaced knowledge worth preserving. This is a **post-review** step — never let it interfere with the review itself. **Skipped entirely when `--lite` is active** — emit `Evolution check: skipped (lite mode)` in place of the Evolution check line, and do not run the `/necess --3` gate.

### When to Propose

**Selectivity (D3) — default to silence**. Proposal bar requires BOTH:
(a) pattern is **not even loosely covered** by any existing pitfall/example/overlay — merely adjacent coverage disqualifies, AND
(b) pattern is likely to **recur** in future reviews (one-off quirks do not qualify).

(a) is satisfied by at least one of these concrete signals:
- Target type encountered with no matching overlay
- Pattern worth capturing not in pitfalls.md (and not a near-duplicate)
- Calibration gap not in examples.md (new anti-pattern / severity edge case)
- Domain knowledge applied that should be formalized

If BOTH (a)+(b) hold → append **Evolution Proposal** after Summary. Otherwise end with `Evolution check: no new patterns` — this is the **expected case**, not a failure.

**Necessity gate (mandatory)** — before presenting this proposal, apply the `/necess --3` review (3 independent passes of the 5-gate necessity filter) to the draft, then act on necess's aggregated verdict: converged **KEEP** → present as-is; **REFINE** → present the revised version; **RETRACT** → **suppress** the proposal (emit `Evolution check: proposal retracted by /necess --3` instead of the block); **mixed verdicts across passes** → surface necess's divergence report to the user and let them decide (per necess Strategy A — no majority vote). Run the gate **once**; necess output is final — do not re-gate it. **Outcome tag (auditability)** — a surviving proposal (KEEP/REFINE) presented to the user must carry a one-line `necess --3: KEEP` / `necess --3: REFINE` tag in the Evolution Proposal block; a *missing* tag is the visible signal that the gate was skipped. (RETRACT already emits its suppress line above; mixed-verdict already surfaces the divergence report — neither needs an extra tag.)

### Proposal Format

Append this block to the report output:

```
### Evolution Proposal

> 🔄 **Proposed Evolution**  <!-- emoji is part of this template's format spec; overrides default no-emoji rule -->
>
> **Type**: pitfall | example | overlay-gap
> **Draft entry**:
> `- **Title** [tag1/tag2]: One-line description`
> **Rationale**: Why existing rules don't cover this.
> **Action**: "Add to pitfalls.md" / "Add to examples.md" / "Flag for SKILL.md review"
>
> *Approve / modify / reject?*
```

### Write Mechanics (on user approval)

- This applies to **pitfall** and **example** types only. For **overlay-gap** proposals, approval means flagging for a dedicated SKILL.md review session — no file write is performed.
- **pitfalls.md**: Append new entry after the last entry in the Entries section (match on `## Entries` prefix, ignoring any bilingual suffix)
- **examples.md**: Append after the last example block (before any trailing horizontal rule or EOF), following the existing format (section header with bilingual title, brief context, fenced code block with example report)
- Auto-include provenance comment: `<!-- via: evolution-proposal, YYYY-MM-DD -->`
- **ID allocation**: a new pitfalls.md entry claims the next ID in `pitfalls-id-map.md` § 分配登记 (max+1 from #301 — see that file's header rule) and carries `id: #N` inside its tail via-comment. Never derive an ID from the entry's line number or ordinal position (two legacy ID eras made those unreliable; the map owns resolution).
- **Cross-reference & title discipline**: body cross-references to other entries cite by TITLE (「标题」 form, optionally plus a registry ID) — never introduce a new bare `#N`. Historical numbers already in entries live in the dual form 「标题」（旧 #N）; keep both halves intact when editing near them. Entry titles are IMMUTABLE anchors: renaming one requires a same-day full sweep of every citing site (body dual-tracks, via annotations, id-map, changelog/memory refs) — prefer not renaming (meta-rule mirrored in the pitfalls.md header).
- Before writing, scan existing entries for semantic overlap; if found, warn user and suggest merging instead of adding
- If the Write/Edit tool fails after user approval, output the complete entry (with provenance comment) as a fenced code block in the conversation for manual insertion, and report the tool failure

### Constraints

- **Max 1 proposal per QC review** — for `--loop` all rounds share one proposal budget (if 2+ novel patterns surface, pick the highest-value one).
- Never auto-write to any file; always wait for user confirmation.
- Never propose changes to the 5 core dimensions or severity definitions.
- SKILL.md structural changes (new overlays, new dimensions) → flag only, defer to dedicated review session.
