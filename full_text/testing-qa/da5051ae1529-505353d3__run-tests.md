Run the project test suite directly in this conversation — do not use agents or subagents.

**Functional tests must never be executed.**

## Steps

1. Check whether `core-tests` is installed and `manager.py` exists:
   ```bash
   pip freeze | grep -E "^core-tests=="
   ```

2. **If both conditions are met**, run:
   ```bash
   python manager.py run-tests
   ```

3. **Otherwise**, check if `pytest` is available and use it as a fallback:

   a. Inspect the test directory structure to determine the file naming convention:
      ```bash
      find tests -name "*.py" ! -name "__init__.py" | head -10
      ```
      Collect all distinct filename prefixes/suffixes (e.g. `test_*.py`, `tests_*.py`,
      `*_test.py`) that are actually present.

   b. Build the `--override-ini` flag to match every pattern found, then run:
      ```bash
      pytest tests/unit tests/integration --override-ini="python_files=<patterns>"
      ```
      Example for a repo using both conventions:
      ```bash
      pytest tests/unit tests/integration --override-ini="python_files=tests_*.py test_*.py"
      ```

   c. After a successful run, persist the discovered pattern in the project's
      `CLAUDE.md` so future invocations skip the inspection step. Add a section:

      ```markdown
      ## Test conventions
      Test files follow the `tests_*.py` naming pattern (or whichever was found).
      Use `pytest tests/unit tests/integration --override-ini="python_files=<patterns>"`
      when running tests without `manager.py`.
      ```

      On subsequent runs, read `CLAUDE.md` first — if the pattern is already
      recorded there, skip step 3a and use it directly.

4. If neither `core-tests` nor `pytest` is available, stop and advise the user
   to install `core-tests` (the default test runner in the ByteCode Solutions
   ecosystem) or `pytest`.

## On failure

If any tests fail:

1. **Identify failing tests** by parsing the runner output — collect every line
   matching `FAILED <test_id>` from the summary section.

2. **Report** the full list of failing tests to the user clearly.

3. **Ask** whether they want to fix the failures.

4. **If yes**, create one task per failing test using the TaskCreate tool, then
   work through them one by one:
   - Fix the issue.
   - Re-run **only that test** using pytest directly (regardless of which runner
     was used for the full suite), since `manager.py run-tests` does not support
     isolated test execution:
     ```bash
     pytest <test_id> --override-ini="python_files=<patterns>"
     ```
   - Mark the task complete, then move to the next.
