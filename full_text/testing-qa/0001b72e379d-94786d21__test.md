Generate comprehensive tests for the provided code. Follow this process:

## 1. Analysis Phase
- Identify the testing framework (pytest, unittest, vitest, jest, etc.)
- Find existing test patterns in the codebase
- Understand the code's public interface
- Identify dependencies that need mocking

## 2. Test Categories

### Unit Tests
- Test each public function/method independently
- Mock external dependencies
- Focus on single responsibility

### Edge Cases
- Empty inputs (null, empty string, empty array)
- Boundary values (0, -1, max int, min int)
- Invalid types where applicable
- Unicode and special characters for string handling

### Error Conditions
- Expected exceptions are raised
- Error messages are meaningful
- Resources are cleaned up on failure

### Integration Points
- Database operations (if applicable)
- API calls (if applicable)
- File system operations (if applicable)

## 3. Test Structure

Use Arrange-Act-Assert pattern:
- Clear test names describing behavior (test_X_when_Y_then_Z)
- Docstrings explaining test purpose
- One assertion per test when practical
- No test interdependencies

## 4. Output

Generate complete, runnable test files following project conventions.
