# chok-task

사용자의 말을 듣고 업무(태스크)를 생성하는 스킬.  
인터뷰 → 추출 → 확인 → `docs/tasks.md` 기록의 5단계 플로우를 실행한다.

---

## 실행 방법 (Usage)

```
/chok-task                                        # 인터뷰부터 시작
/chok-task 인증 시스템 구현                        # 내용이 명확하면 추출부터 시작
/chok-task "로그인, 회원가입, JWT 발급 구현해줘"
/chok-task --task-file docs/sprint-1.md "결제 모듈 연동"  # 파일 경로 지정
```

| 옵션 | 기본값 | 설명 |
|------|--------|------|
| `--task-file` | `docs/tasks.md` | 태스크를 기록할 파일 경로. chok-auto-agent의 `--task-file`과 맞춰 사용. |

**Phase 진입 판단**: $ARGUMENTS에서 "무엇을(목적어) + 어떻게 한다(동작 의도)"의 구조가 1개 이상 식별되면 Phase 2로 바로 진입한다. 판단이 모호하면 Phase 1 인터뷰를 실행한다.

---

## Phase 1: 인터뷰

**실행 조건**: $ARGUMENTS가 비어있거나 명확한 동사구가 1개도 포함되지 않은 경우.

AskUserQuestion을 사용해 다음 순서로 질문한다. 최대 5회. 답변이 충분하면 조기 종료.

**질문 목록**:
1. "이번에 진행할 작업의 목표가 무엇인가요?"
2. "완료 기준(Acceptance Criteria)은 어떻게 되나요?"
3. "알고 있는 의존성이나 선행 작업이 있나요?"
4. "범위 밖으로 제외할 항목이 있나요?"
5. "우선순위나 마감 기한이 있나요?"

**조기 종료 조건**: 목표 + 완료 기준이 확보되면 더 이상 질문하지 않는다.

---

## Phase 2: 태스크 추출

인터뷰 답변 또는 $ARGUMENTS에서 태스크를 추출한다.

**추출 규칙**:
- 동사구 단위로 분리 ("추가하다", "수정하다", "구현하다" 등)
- 순서 표현("먼저", "그 다음", "완료 후") → 의존성으로 변환
- 각 태스크는 커밋 단위 크기 (너무 크면 분리, 너무 작으면 합침)
- 제목 형식: 명령형 한국어, 30자 이내 ("인증 미들웨어 구현")

**태스크 데이터 구조**:

<task-schema>
  <field name="subject" type="string" max="30">명령형 제목</field>
  <field name="description" type="string">구체적 설명</field>
  <field name="acceptance" type="string">완료 기준</field>
  <field name="depends_on" type="array" item-type="string">선행 태스크 이름 목록 (이름 문자열, 빈 배열 가능). 번호(#1) 방식 사용 금지</field>
  <field name="priority" type="enum" values="high|medium|low">우선순위</field>
</task-schema>

<priority-heuristic order="first-match">
  <rule priority="low" condition="keyword-match" keywords="개선,최적화,추가로,나중에">선택적/개선 키워드 포함 시</rule>
  <rule priority="high" condition="depends_on is empty">키워드 없음 + 의존성 없음</rule>
  <rule priority="medium" condition="depends_on is not empty">키워드 없음 + 의존성 있음</rule>
</priority-heuristic>

## Phase 3: 제안 & 확인

추출된 태스크를 마크다운 테이블로 표시한다. 의존성 컬럼은 태스크 이름으로 표기한다.

```
제안된 태스크 목록:

| # | 태스크                       | 의존성                     | 우선순위 |
|---|------------------------------|----------------------------|---------|
| 1 | 인증 미들웨어 구현           | 없음                       | high    |
| 2 | JWT 토큰 검증 로직 추가      | 인증 미들웨어 구현          | medium  |
| 3 | 로그인 API 엔드포인트 작성   | JWT 토큰 검증 로직 추가     | medium  |
```

AskUserQuestion으로 확인: "이 태스크 목록으로 진행할까요? 수정이 필요하면 말씀해 주세요."

**수정 요청 처리**:
- 수정 내용 반영 후 테이블 재표시 → 다시 확인 질문
- **max-retries=2**: 수정 요청이 2회를 초과하면 재시도를 중단한다.
  다음 메시지 출력 후 최종 확인:

  > "수정을 2회 시도했으나 반영하지 못했습니다. 원본 제안으로 진행할까요? (승인 / 취소)"

  - 승인 → Phase 4 (원본 목록으로 진행)
  - 취소 → 스킬 종료

---

## Phase 4: 기록

`TASK_FILE=${TASK_FILE:-docs/tasks.md}` 경로에 태스크를 기록한다.

### 파일 처리 절차

**Step 1**: `Read $TASK_FILE`로 파일 존재 여부 및 `## 프로젝트 목표` 블록 포함 여부 확인.

**Step 2**: 상태별 도구 지정:

| 상태 | 사용 도구 | 처리 |
|------|----------|------|
| 파일 없음 | `Bash` + `Write` | `mkdir -p $(dirname $TASK_FILE)` 후 `Write`로 전체 생성 (목표 블록 + 세션 섹션) |
| 파일 있음, `## 프로젝트 목표` 없음 | `Edit` + `Bash` | `Edit`으로 파일 최상단에 목표 블록 삽입, 이후 `Bash: printf '\n\n%s' "$(세션 섹션)" >> $TASK_FILE`로 하단 추가 |
| 파일 있음, `## 프로젝트 목표` 있음 | `Bash` | `printf '\n\n%s' "$(세션 섹션)" >> $TASK_FILE` 로 하단에만 추가 (목표 블록 재작성 금지) |

**세션 제목 생성 규칙**: Phase 1 Q1 답변 또는 $ARGUMENTS의 핵심 의도를 명사구로 요약, 20자 이내.  
예: "쇼핑몰 기본 기능 구현", "인증 시스템 구현", "결제 모듈 연동"

**프로젝트 목표 출처**: Phase 1 Q1 답변 전체를 사용. $ARGUMENTS 직접 입력 시 핵심 의도 1~2문장으로 요약.

### docs/tasks.md 기록 형식

```markdown
## 프로젝트 목표
{최초 1회만 작성 — 사용자가 말한 전체 프로젝트 목표}

---

## [세션 제목] — YYYY-MM-DD

### 태스크
- [ ] 인증 미들웨어 구현
  - 설명: JWT 토큰 기반 인증 처리. Express 미들웨어로 구현.
  - 완료 기준: /api/* 엔드포인트에서 유효하지 않은 토큰 차단
  - 우선순위: high

- [ ] JWT 토큰 검증 로직 추가
  - 선행: 인증 미들웨어 구현
  - 설명: jsonwebtoken 라이브러리 사용, 만료 시간 체크 포함
  - 완료 기준: 만료/변조 토큰은 401 반환
  - 우선순위: medium

- [ ] 로그인 API 엔드포인트 작성
  - 선행: JWT 토큰 검증 로직 추가
  - 설명: POST /api/auth/login, 이메일/비밀번호 검증 후 JWT 발급
  - 완료 기준: 정상 로그인 시 access_token 반환
  - 우선순위: medium
```

**중요**: `- [ ] 태스크명` 헤더 행에 의존성을 인라인으로 쓰지 않는다. 반드시 하위 들여쓰기 `- 선행: 이름` 형식을 사용한다.  
chok-auto-agent의 `- [ ] 태스크명` → `- [x] 태스크명` 완료 처리와 충돌하지 않아야 한다.

## Phase 5: 확인

기록 완료 후 다음 메시지를 출력한다:

```
docs/tasks.md에 {N}개 태스크가 추가되었습니다.

세션: {세션 제목}
추가된 태스크:
  - {태스크 1}
  - {태스크 2}
  ...

다음 단계:
  /loop chok-auto-agent   → 태스크 자동 실행 시작
  /chok-task              → 추가 업무 입력
```

## 엣지 케이스 처리

| 상황 | 처리 |
|------|------|
| $ARGUMENTS에 명확한 동사구 포함 | Phase 1 건너뜀, Phase 2로 바로 진입 |
| 단일 동사구 ("로그인 구현해줘") | 단일 태스크 추출, Phase 3 확인 후 기록 |
| 매우 모호한 입력 ("뭔가 만들어줘") | Phase 1 인터뷰 실행 |
| docs/tasks.md 없음 | mkdir -p docs 후 Write로 신규 생성 |
| 기존 tasks.md에 완료 태스크 있음 | 완료 항목(`- [x]`) 유지, 새 태스크만 추가 |
| 10개 이상 태스크 추출 시 | Phase별 그룹핑 제안 ("Phase 1: 인증", "Phase 2: API") |
| 수정 요청 2회 초과 | 원본 제안 유지 후 최종 승인/취소 확인 |

## chok-auto-agent 연동

`chok-task`는 `docs/tasks.md`를 생성하고, `chok-auto-agent`는 이를 소비한다.

```
사용자
  └─ /chok-task "인증 시스템 구현"
        ├─ Phase 1: 인터뷰 (필요 시)
        ├─ Phase 2: 태스크 추출
        ├─ Phase 3: 확인
        └─ Phase 4: docs/tasks.md 기록
              │
              └─ /loop chok-auto-agent
                    ├─ docs/tasks.md 읽기
                    ├─ - [ ] → - [x] 완료 처리
                    └─ 완료 리포트
```

**연동 규칙**:
- `chok-task`는 `- [ ] 태스크명` 헤더 행을 단순하게 유지한다 (인라인 부가정보 금지)
- 메타데이터(설명, 선행, 완료 기준, 우선순위)는 하위 들여쓰기로만 추가한다
- `chok-auto-agent`는 `- [ ]` 헤더만 읽으므로 하위 줄은 무시된다 — 호환성 유지

---

## Boundaries

**Will:**
- 사용자 인터뷰를 통한 요구사항 파악
- 동사구 기반 태스크 자동 추출
- 의존성 순서 자동 감지 및 이름 참조 형식으로 표기
- 우선순위 자동 배정 (휴리스틱 기반)
- docs/tasks.md 호환 형식 기록 (chok-auto-agent 연동 보장)
- chok-auto-agent 실행 가이드 제공

**Won't:**
- 코드 직접 구현 (chok-auto-agent 역할)
- 사용자 확인 없이 파일 작성
- 10개 초과 태스크를 한 번에 추가 (Phase 분리 제안)
- 기존 완료된 `- [x]` 태스크 수정
- `## 프로젝트 목표` 블록 중복 생성
