# 灵感衣帽间 Skill

## 功能定位

这是一个 **AI 形象顾问 + 风格诊断 + 视觉搭配生成** 的 skill。

核心逻辑：用户只需上传一张照片（半身 / 全身 / 仅脸部均可），Skill 根据照片中的面部气质、五官风格、身形比例，结合专业的四季色彩理论，自动诊断适合的穿衣风格，并生成完整的视觉化搭配方案手册。

**不需要**用户填写大量文字，不需要整理衣柜，输入最直观，体验感最强。

---

## 诚实边界声明

- 不做精确医学或身体测量
- 不对长相做价值判断，不评价用户"好不好看"
- 不做真实虚拟试衣的高精度模拟
- 不保证 AI 生成图与本人完全一致
- 不做电商购买闭环（仅提供购买方向建议）
- 不做整容、医美、减肥建议
- 不储存敏感照片作为长期训练数据，除非用户明确授权

---

## 工作流程

**⚠️ 重要原则：整个工作流程为内部处理逻辑，不向用户展示中间分析过程。用户只需要看到最终的 HTML 形象手册。**

**输出要求：**
- 不输出冗长的文字分析报告
- 不逐步展示诊断过程
- 直接生成完整的 HTML 风格手册作为最终交付物
- 简短告知用户"正在为您生成专属形象手册..."，然后静默完成所有分析和生成步骤

### 第一步：照片分析与用户画像（内部处理，不展示）

#### 1.1 读取照片

使用 Read 工具读取用户上传的照片。根据照片类型判断分析深度：

- **仅脸部照**：主要做面部气质分析 + 四季色彩诊断 + 风格方向判断
- **半身照**：面部气质 + 四季色彩 + 上半身比例 + 风格方向
- **全身照**：面部气质 + 四季色彩 + 完整身形比例 + 全套风格建议

#### 1.2 面部气质分析

静默分析以下维度（仅作为内部决策依据，不输出给用户）：

| 维度 | 分析内容 |
|---|---|
| 五官量感 | 五官是否偏大、中等、偏小 |
| 脸部线条 | 硬朗 / 柔和 / 中性 |
| 面部冷暖感 | 冷色系气质 / 暖色系气质 |
| 少年感 / 成熟感 | 偏年轻活泼 or 偏成熟稳重 |
| 甜美感 / 清冷感 | 亲切甜美 or 清冷高级 |
| 亲和感 / 距离感 | 容易接近 or 气场感强 |
| 骨骼感 / 柔和感 | 骨骼线条明显 or 整体柔和 |
| 整体氛围 | 综合定性，给出 2-3 个关键词 |
| 发型影响 | 当前发型对气质的加分 / 减分分析 |
| 穿搭匹配度 | 当前穿搭与本人气质是否匹配 |

**诊断输出格式（写入HTML色彩方案页）：**

1. **所属季型**（12季型具体分类，如"冷冬型人"）
2. **判断依据**（肤色冷暖+明度+对比度+饱和度的综合分析）
3. **色彩特征关键词**（如"深邃+冷调+气场十足"）

6. **⚠️ 完整色板展示**：在HTML中用色块矩阵展示该季型的所有推荐颜色，每个色块标注色名

### 第二步：风格库匹配（内部处理，结果写入 HTML）

**⚠️ 核心优化：使用预设风格库进行快速匹配,而非让 LLM 从零生成风格描述。**

#### 2.1 加载预设风格库

读取 `references/style-library.md` 文件,该文件包含 30+ 种预设风格,分为 3 个维度:

- **国家/区域维度** (7种): 中国风、日系、韩系、欧美风、法式、英伦风、波西米亚风
- **设计理念维度** (8种): 新中式、简约风、极简风、中性风、复古风、Y2K风、淑女风、名媛风
- **场景/功能维度** (8种): 运动风、通勤风、度假风、休闲风、校园风、工作风、约会风、Party风

每个风格包含:
- 核心特征描述
- 适合人群画像
- 色彩方案建议
- 参考案例/博主

#### 2.2 智能匹配流程（按优先级顺序）

**⚠️ 匹配顺序调整：国家/区域 → 设计理念 → 场景/功能**

基于用户画像按以下优先级匹配风格：

1. **第一步：国家/区域维度匹配** (选1-2个)
   - 根据用户气质、五官特征、审美偏好匹配最适合的区域风格
   - 匹配维度：五官立体度、脸部线条、肤色底调、文化认同感
   - 输出：1-2个核心区域风格(如"日系+法式")

2. **第二步：设计理念维度匹配** (选1-2个)
   - 基于用户个性、年龄、生活方式匹配设计风格
   - 匹配维度：气质关键词、成熟度、个性特质、生活场景
   - 输出：1-2个设计理念(如"简约+复古")

3. **第三步：场景/功能维度匹配** (动态选3个)
   - **⚠️ 关键原则：场景必须根据用户画像动态选择，不能固定！**
   - 根据用户年龄、职业、生活方式、补充需求推断最适合的3个场景
   - **场景选择逻辑**：
     - 学生党：校园风 + 休闲风 + 约会风
     - 上班族：通勤风 + 休闲风 + 社交/Party风
     - 自由职业：休闲风 + 工作风 + 度假风
     - 宝妈：休闲风 + 运动风 + 家庭聚会风
     - 艺术工作者：工作风 + 创意休闲风 + 社交风
     - 用户明确提到特定场合（如"要参加婚礼"/"经常出差"）：优先匹配对应场景
   - **避免千篇一律**：不要每次都是"日常+通勤+约会"，要根据真实需求变化！
   - 输出：3套针对不同场景的完整搭配方案，场景标签清晰

匹配结果将直接写入 HTML 手册的"风格诊断"页面。

在完成场景选择后，从下表中为每个场景挑选 1 个最贴合用户气质、色型、身材特点的风格（若多个风格都合适，优先选择与"设计理念维度"匹配结果重合度最高的一个）：

| 场景 | 优先推荐风格 |
|---|---|
| 通勤 | OL通勤、Business Casual、Clean Fit、Quiet Luxury、极简风 |
| 日常休闲 | 韩系休闲、法式慵懒、美式休闲、盐系、Clean Girl |
| 约会 | 法式优雅、韩系温柔、轻熟风、Old Money、Clean Girl |
| 聚会 | 小香风、甜酷风、韩系小姐姐、法式复古、轻熟风 |
| 夜生活 | Y2K、辣妹风、欧美街头、暗黑风、Techwear |
| 旅行 | Resort、Boho、Old Money、法式度假、亚麻自然风 |
| 户外 | Gorpcore、工装风、机能风、Athleisure |
| 看展 | 文艺复古、Academia、法式复古、日杂风、极简风 |
| 演唱会 | Y2K、辣妹风、街头风、Blokette、丹宁风 |

**匹配步骤：**
1. 先确定 3 个目标场景（按 2.2 第三步的场景选择逻辑）
2. 针对每个场景，从上表对应行的推荐风格中，结合用户四季色型、气质关键词、身材特点，选出 1 个最终风格
3. 组合成"场景×风格"命名，如"通勤×Quiet Luxury"、"约会×法式优雅"、"旅行×Old Money"
4. 这个"场景×风格"命名将贯穿后续所有环节：搭配方案名称、图像生成 prompt 的背景设定、最终 HTML 手册的方案标题

**命名格式规范：** `{场景}×{风格}`，中间用"×"（乘号）连接，例如：
- 通勤×OL通勤
- 日常休闲×韩系休闲
- 约会×法式优雅
- 旅行×Old Money
- 看展×Academia

### 第三步：流行款式调研（必需步骤，内部处理）

**⚠️ 重要：在生成搭配方案前，必须先调研当前流行趋势，确保推荐的单品既符合用户气质又贴近时尚潮流。**

#### 3.1 根据匹配风格生成调研关键词

基于第二步匹配的风格维度，生成针对性的搜索关键词：

**构建逻辑：**
- 区域风格 + 设计理念 + 当前季节 + "流行"/"穿搭"/"款式"
- 区域风格 + 场景 + "2026"/"最新"/"趋势"
- 设计理念 + 单品类别 + "推荐"/"博主"

**示例：**
假设用户匹配结果为"日系+简约风+通勤场景"，生成的搜索词应包括：
- "2026日系简约风流行穿搭"
- "日系通勤装搭配推荐"
- "简约风春季款式趋势"
- "日系博主最新穿搭"
- "极简风格单品推荐2026"

每次生成 5-8 组针对性搜索词。

#### 3.2 执行流行趋势调研

使用 WebSearch 工具搜索关键词，从搜索结果中提取：

**必须收集的信息：**
- **当前流行的单品类别**：今年流行哪些款式(如"奶油风针织衫"/"高腰阔腿裤"等)
- **流行配色方案**：当季热门颜色组合(如"莫兰迪色系"/"多巴胺配色"等)
- **流行版型廓形**：主流廓形趋势(如"oversize"/"修身"/"直筒"等)
- **博主推荐单品**：小红书/微博穿搭博主高频推荐的具体单品
- **品牌档次参考**：性价比高的品牌推荐(如"优衣库UT系列"/"ZARA新款"等)

**调研输出（内部结构化数据）：**
```python
trend_research = {
    "popular_items": ["奶油风针织开衫", "高腰直筒牛仔裤", "乐福鞋"],
    "popular_colors": ["奶白色", "浅卡其", "雾霾蓝"],
    "popular_silhouettes": ["oversize上衣", "高腰线", "直筒裤型"],
    "blogger_recommendations": ["优衣库羊毛混纺开衫", "ZARA高腰阔腿裤"],
    "affordable_brands": ["优衣库", "ZARA", "UR", "COS"]
}
```

#### 3.3 调研结果应用规则

**⚠️ 关键：调研结果必须融入第四步的搭配方案生成中！**

- **单品选择优先级**：优先推荐调研中出现的流行单品类别
- **配色方案融合**：在符合四季色型的前提下，优先使用当季流行色
- **版型廓形对齐**：搭配方案中的单品廓形应与流行趋势一致
- **品牌推荐落地**：购买指引中的品牌建议应基于调研结果，确保用户能实际买到

### 第四步：搭配方案生成（内部处理，结果写入 HTML）

**⚠️ 标准输出：每次分析必须生成 3 套完整的搭配方案。**

#### 4.1 搭配原则（AI 生成方案时须遵守的规则）

**色彩搭配规则：**
- 遵循四季色型，主色 1-2 个，辅助色不超过 2 个，点缀色 1 个
- 全身颜色建议不超过 3 个
- 同色系深浅搭配优先于强撞色
- 花色/印花单品出现时，其他单品须为纯色

**比例原则：**
- 上宽下窄 or 上窄下宽，避免上下同宽
- 小个子优先高腰线设计，强调竖向延伸
- 腿型不完美时优先中长裙 / 直筒裤，避免过膝短裙或紧身裤
- 肩宽者避免宽领 / 泡泡袖，选择 V 领 / 窄肩设计

**层次叠穿规则：**
- 叠穿以 2 层为主，最多 3 层
- 内短外长，形成层次感
- 避免厚重感堆叠（厚料子 + 厚料子）

**风格统一原则：**
- 每套方案主风格关键词控制在 1-2 个，单品须服务于同一风格
- 不允许同一套装中混入风格矛盾的单品（如：法式上衣 + 破洞街头裤）
- 配饰风格须与主体服装一致

**场合适配规则：**
- 日常通勤：舒适度优先，正式感 ≤ 4/10
- 约会 / 聚会：氛围感优先，可加 1-2 件点睛单品
- 正式场合：廓形利落、用色克制、避免过度花哨细节

**⚠️ 关键：使用独立的 Python 脚本生成图片，通过后台任务方式运行，避免超时限制。**

创建 `gen_outfit_images.py` 脚本，包含以下功能：
- 接收 3 套搭配方案的 prompt 作为输入
- **使用 `requests` 库直接调用 HTTP API（不使用 OpenAI SDK）**
- 使用线程池并发调用 API 生成 3 张图片
- 实时输出进度日志
- 自动重试失败的任务
- 生成完成后保存为本地文件和 base64 数据

**Python 脚本示例代码（必须使用此配置）：**
```python
import requests
import base64
import os
from pathlib import Path

# ⚠️ 强制配置，不可更改；API key 必须通过环境变量提供
API_KEY = os.environ["XIAOJING_API_KEY"]
API_ENDPOINT = "https://open.xiaojingai.com/v1/images/edits"
MODEL = "gpt-image-2-reverse-vip"

# 读取用户上传的原始照片（jpg 或 png 均可）
user_image_path = "user_photo.jpg"  # 用户上传的照片路径

# 读取照片并转为 base64
with open(user_image_path, "rb") as f:
    image_data = base64.b64encode(f.read()).decode("utf-8")

# 判断图片格式
img_suffix = Path(user_image_path).suffix.lower()
mime_type = "image/jpeg" if img_suffix in [".jpg", ".jpeg"] else "image/png"

headers = {
    "Authorization": f"Bearer {API_KEY}",
    "Content-Type": "application/json"
}

payload = {
    "model": MODEL,
    "image": [
        {
            "type": "input_image",
            "image_url": f"data:{mime_type};base64,{image_data}"
        }
    ],
    "prompt": outfit_prompt,  # 换装指令，如"把衣服换成浅蓝色针织开衫..."
    "size": "1024x1024",
    "quality": "high"
}

# 调用图像编辑 API（用户照片 + 文本指令 → 换装效果图）
response = requests.post(API_ENDPOINT, headers=headers, json=payload, timeout=180)
response.raise_for_status()
result = response.json()
image_base64 = result["data"][0]["b64_json"]
# 保存图片...
```

```python
    # 检查是否已生成完成标记文件

# 3. 验证图片文件是否存在

    "通勤×OL通勤.png",

else:

# 4. 只有在这一步完成后，才能继续执行第六步生成 HTML
```

**关键注意事项：**

4. **错误处理**：如果部分图片失败，记录失败信息，但继续生成 HTML（使用占位图）

#### 5.2.1 沙箱执行时间限制与解决方案（重要）

**⚠️ WorkBuddy 沙箱环境对命令执行有时间限制：**

**限制特征：**
- **Python 脚本通过 Bash 工具直接调用时**，单条命令执行时间上限约 120 秒（2 分钟）
- 超时后进程被强制终止（SIGTERM），日志显示 "Duration: 2m 0s"
- 单张图片 API 调用平均耗时：~108 秒（1.8 分钟），接近上限，任何波动都会触发超时

**✅ 成功的自动化方案：使用 shell 后台任务 + run_in_background**

**核心技巧：**
```bash
# 关键：命令末尾加 & 符号 + run_in_background=true
python3 script.py > output.log 2>&1 &
```

通过 `run_in_background=true` 调用 Bash 工具，并在命令末尾添加 shell 后台符号 `&`，能让进程**真正独立运行，不受 120 秒限制**。

**实测验证（2026-07-03）：**
```bash
# 同时发起 2 个后台任务
python3 gen_one.py 2 > gen2.log 2>&1 &
python3 gen_one.py 3 > gen3.log 2>&1 &
```

结果：
- ✅ 第3张图：**成功生成**，耗时 **168.4 秒**（远超 120 秒限制）
- ✅ 第1张图：之前已成功生成
- 🔄 第2张图：网络不稳定导致前两次超时，第3次重试中（证明进程持续运行超过 6 分钟）

**推荐方案：串行后台生成（自动化 + 可靠）**

创建单张图生成脚本 `gen_one.py`，在 skill 中连续发起 3 个独立的后台任务：
