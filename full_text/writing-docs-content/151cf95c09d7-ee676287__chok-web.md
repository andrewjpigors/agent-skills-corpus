# chok-web — 웹 프로젝트 기획/설계 스킬

어떤 웹 프로그램이든 **시작·변경·교체**를 인터뷰로 파악한다.
**spec + `docs/tasks.md`** 산출 → `/loop chok-auto-agent` 위임. 직접 구현 안 함.

## Phase 0 — 모드 감지

사용자 입력 의도로 3모드 분기. 모호하면 `AskUserQuestion`으로 확인.

| 모드 | 의도 신호 |
|------|----------|
| **scaffold** | "새로", "시작", "만들어", 기존 프로젝트 언급 없음 |
| **modify** | "구조 바꿔", "이 페이지 개선", "변경", 기존 코드/URL 지목 |
| **migrate** | "프레임워크 교체", "라이브러리 바꿔", "X에서 Y로", "이전" |

```xml
<route>
  <case signal="신규 생성 의도" mode="scaffold" />
  <case signal="기존 구조 변경 의도" mode="modify" />
  <case signal="스택 교체 의도" mode="migrate" />
  <fallback action="AskUserQuestion으로 3모드 중 선택 요청" />
</route>
```

## Mode: scaffold (신규 웹 프로젝트)

1. **기준 인터뷰** — `AskUserQuestion` 1문항씩. 종류(SPA/풀스택/정적/대시보드)·핵심 기능·타깃·선호 스택 확인.
2. **preset 로드** — `presets.md`(내장) + `~/.claude/chok-web/presets.json`(사용자) 병합 → 제안.
3. **권장 스택 확정** — 사용자 선택/수정.
4. **보안 버전 해결 (Hybrid)** — baseline 로드 → 설계 시점 CVE 재검증. 상세 §보안.
5. **하네스 설계** — `chok-harness` design/build-roadmap 모드(audit 아님). 웹용 최소 하네스(CLAUDE.md/hooks/MCP) 로드맵.
6. **테스트 설계** — `chok-test`(scenario) → 테스트 시나리오 확보.
7. **부트스트랩** — 프로젝트 루트 확정/생성. **루트 먼저, task는 그 다음.** (§부트스트랩)
8. **산출** — `<root>` 안에:
   - spec → `<root>/docs/superpowers/specs/YYYY-MM-DD-<name>-design.md` (`spec-template.md` 기반)
   - tasks → `<root>/docs/tasks.md` (`tasks-template.md` 기반):
     ```
     - [ ] 프로젝트 scaffold (공식 CLI: create-next-app / npm create vite … 또는 직접 생성)
     - [ ] 하네스 구축 (chok-harness 로드맵 기반)
     - [ ] 테스트 환경 구축 (chok-test 시나리오 기반)
     ```
9. **핸드오프** — "`<root>`에서 `/loop chok-auto-agent` 실행하세요" 안내.

## Mode: modify (기존 구조 변경)

1. **대상 자동감지**:
   - 로컬 소스 존재(cwd에 package.json/src 등) → 파일 툴(Glob/Grep/Read)로 구조 분석.
   - URL만 제공 → `chok-research` 위임 크롤(WebFetch → 동적이면 claude-in-chrome MCP 폴백)로 DOM/구조 파악.
   - 둘 다 없음 → 소스 경로 또는 URL 요청.
2. **현 구조 요약** — 컴포넌트/라우팅/스택/스타일 시스템 요약 제시.
3. **변경 인터뷰** — `AskUserQuestion`으로 변경 구체화 → 변경 가이드(영향 범위 명시).
4. **보안 버전 해결** — 변경에 신규 의존성 추가 시만 (§보안).
5. **산출** — spec(변경 가이드) + tasks.md (충돌 규칙 §tasks.md).
6. **핸드오프** — `/loop chok-auto-agent` 안내.

## Mode: migrate (프레임워크/라이브러리 교체)

1. **현 스택 파악** — 로컬 소스 분석(의존성, 빌드 설정, 핵심 패턴).
2. **교체 요구 확인** — from→to, 범위(전체/부분), 호환성 제약, 데이터/라우팅 보존.
3. **영향/리스크 분석** — `chok-techreview` 4-lens(트레이드오프/표준/보안성능/의존성).
4. **보안 버전 해결** — target 스택 (§보안).
5. **산출** — spec(단계 절차 + 롤백 포인트) + tasks.md(단계적 `- [ ]`).
6. **핸드오프** — `/loop chok-auto-agent` 안내.

## 보안 버전 정책 (Hybrid)

하드코딩된 버전 pin은 새 CVE 발생 시 거짓 보안 주장이 됨 → Hybrid:

1. **Baseline**: `recommended-specs.md` manifest + `verified-as-of` 날짜.
2. **재검증**: 스택 확정 시 chok-techreview/chok-research 위임으로 CVE 대조 → 안전 버전 확정.
3. **재검증 실패**: baseline 사용 + "재검증 안 됨 (verified-as-of 기준)" 경고 명시.
4. **갱신**: manifest는 chok-trendsync로 주기 갱신.

## 부트스트랩 (scaffold 전용)

**순서: 루트 확정/생성 → 그 안에 task 생성.**

| 상황 | 동작 |
|------|------|
| cwd 비었음/신규 루트 | cwd 사용 |
| cwd에 기존 코드 존재 | 인터뷰 프로젝트명으로 `./<name>/` mkdir → 루트 |

## tasks.md 처리 (modify/migrate — 루트 기존재)

기존 큐 덮어쓰기 금지(데이터 손실).

| 상황 | 동작 |
|------|------|
| 없음 | 신규 생성 |
| 존재 + 미완료 `- [ ]` | 덮어쓰기 금지. 사용자 확인 → append 또는 `docs/tasks-<name>.md` |
| 별도 파일 | 핸드오프에 `/loop chok-auto-agent --task-file docs/tasks-<name>.md` 포함 |

## 엣지케이스

- 모드 모호 → AskUserQuestion 분류.
- modify 대상 없음(소스/URL 둘 다 X) → 요청.
- CVE 재검증 실패 → baseline + 경고.
- 권장 스택에 없는 요구 → 직접 생성 + 보안 주의.
- 기존 tasks.md 미완료 큐 → 사용자 확인 후 별도 파일/append.

## Usage

```
/chok-web "새 Next.js 대시보드 프로젝트 시작"
/chok-web "이 사이트 네비게이션 구조 개선"
/chok-web "https://example.com 리뉴얼"        # modify, URL 자동감지
/chok-web "CRA에서 Vite로 마이그레이션"        # migrate
```

## 생태계 연동

| 스킬 | 시점 | 역할 |

| /loop chok-auto-agent | 핸드오프 | tasks.md 소진 루프 + 자동 재개 |

| /chok 라우터 | 진입 | 자동 디스커버리 |

## 작성 원칙 (간결 문장)

이 스킬이 쓰는 모든 텍스트(이 SKILL.md, 지원 파일, 런타임 산출 spec/tasks.md)는:

- 한 문장 1개 개념. run-on 금지. 표/리스트/코드블록 우선.
- 산문 라인 120자 이내(코드/표 제외).
- description은 마침표 구분 fragment.
