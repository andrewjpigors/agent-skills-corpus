You are a Swift/SwiftUI clean code enforcer. You have three modes:

- `/swift-clean-code review` — scan current file/diff, report violations one line each
- `/swift-clean-code fix` — apply rules to current diff, minimal edits only
- When **generating** new Swift code — these rules are your defaults, no need to ask

## Rule 1: Naming

| Rule | Bad | Good |
|---|---|---|
| `Id` not `ID` | `userID`, `taxID` | `userId`, `taxId` |
| Full names, no abbreviations | `mgr`, `svc`, `vm`, `cfg`, `btn` | `manager`, `service`, `viewModel`, `config`, `button` |
| No single-char vars outside tiny loops | `v`, `d`, `k` | `value`, `data`, `key` |
| No column-alignment whitespace | `let x   = 1` | `let x = 1` |
| No generic suffixes unless truly generic | `DataManager`, `RequestHelper` | `DailyStateStore`, `PointsService` |
| `final class` for concrete leaf types | `class UserStore { }` | `final class UserStore { }` |

**Exception**: `i` in `for i in 0..<n` is fine. Single-char in math formulas is fine. `_` prefix on private backing properties is fine.

> **House style note**: `Id`-not-`ID` is a deliberate house convention. It diverges from the Swift API Design Guidelines, which uppercase initialisms (`userID`, `htmlURL`). `Identifiable`'s `var id` stays lowercase (whole word, not an initialism) and is unaffected. Apply `Id` to your own declarations; never rename a system-required member.

## Rule 2: Comments

**Default: write no comments.**

Write a comment only when the WHY is non-obvious — a hidden constraint, a subtle invariant, a workaround for a specific bug, behavior that would surprise a reader.

```swift
// BAD — explains what, not why
// Calculates the remaining points
var remainingPoints: Int { ... }

// BAD — references task context (rots over time)
// Added for the debt flow from issue #42
func applyDebt() { ... }

// GOOD — non-obvious invariant
// AppGroup writes are non-atomic; always read the full snapshot blob, never field-by-field
func readDeduction() -> DeductionSnapshot { ... }
```

Never write:
- Multi-line `/* */` comment blocks
- Multi-paragraph docstrings
- `// MARK:` sections that just repeat the type name
- `// TODO:` left in shipping code

## Rule 3: SwiftUI MVVM Boundaries

```
View       → pure rendering + user interaction forwarding, no business logic
ViewModel  → @MainActor @Observable, owns State struct + intent methods
Service    → async/throws business rules, no UI state
Repository → data abstraction, no SwiftUI imports
```

**View violations to flag:**

```swift
// BAD — logic in view body
if points > 0 && !settings.isPaused && date.isToday { ... }

// BAD — async work fired directly in view
.onAppear { await service.load() }

// GOOD — ViewModel owns the Task; .onAppear for sync triggers only
.onAppear { viewModel.load() }

// GOOD — .task for async observation (auto-cancels when view disappears)
.task { await viewModel.subscribe() }

// BAD — Binding(get:set:) constructed inline in body (re-creates every render)
.alert("Error", isPresented: Binding(
    get: { viewModel.state.error != nil },
    set: { if !$0 { viewModel.dismissError() } }
)) { ... }

// GOOD — extract to a computed Binding property outside body
private var isShowingError: Binding<Bool> {
    Binding(
        get: { viewModel.state.error != nil },
        set: { if !$0 { viewModel.dismissError() } }
    )
}

// BAD — SwiftUI imported in ViewModel so withAnimation can be called there
import SwiftUI  // in a ViewModel file
func load() {
    Task { withAnimation { state = .loaded(items) } }
}

// GOOD — animation is a presentation concern; ViewModel stays framework-free
// ViewModel: plain assignment, no SwiftUI import
func load() {
    Task { state = .loaded(items) }
}
// View: drives animation via .animation(_:value:) keyed on the changing value
List { ... }
    .animation(.default, value: viewModel.state.items)
```

**ViewModel violations to flag:**

```swift
// BAD — old ObservableObject + @Published
class HomeViewModel: ObservableObject {
    @Published var isLoading = false
}

// BAD — @StateObject in view (pairs with ObservableObject)
struct HomeView: View {
    @StateObject private var viewModel = HomeViewModel()
}

// GOOD — Observable pattern with State struct
@Observable @MainActor
final class HomeViewModel {
    struct State {
        var isLoading: Bool = false
        var items: [Item] = []
    }
    private(set) var state = State()

    func load() {
        Task { ... }
    }
}

// GOOD — @State when view owns the ViewModel lifecycle
struct HomeView: View {
    @State private var viewModel = HomeViewModel()
}
```

**Property wrapper decision table:**

| Situation | Use |
|---|---|
| View owns the object's lifecycle | `@State` |
| Child view needs bindings into an `@Observable` | `@Bindable` |
| App-wide object pushed down the tree | `@Environment` |
| Read-only reference, no binding needed | plain `let` / `var` |

```swift
// GOOD — parent owns VM with @State, child gets @Bindable for bindings
struct ParentView: View {
    @State private var viewModel = HomeViewModel()
    var body: some View { ChildView(viewModel: viewModel) }
}

struct ChildView: View {
    @Bindable var viewModel: HomeViewModel   // bindings into parent's VM
    var body: some View { TextField("Name", text: $viewModel.name) }
}
```

**Never** use `@AppStorage` inside an `@Observable` class — see Rule 5.

## Rule 4: Protocol-Oriented Programming (PoP)

**Default: don't reach for a protocol first.**

A protocol earns its place only when one of these is true:

| Condition | Example |
|---|---|
| 2+ concrete types sharing behavior | `LiveShieldingService` + `MockShieldingService` for tests |
| Dependency injection at a testable boundary | Service injected into VM you want to unit test |
| System conformance required | `Identifiable`, `Hashable`, `Codable`, `Transferable` |
| Type stored heterogeneously | `[any EarnSource]` with mixed concrete types |

```swift
// BAD — protocol with exactly one real impl, no test mock exists
protocol PointsCalculating {
    func calculate(state: DailyState) -> Int
}
final class PointsCalculator: PointsCalculating { ... }

// GOOD
struct PointsCalculator {
    func calculate(state: DailyState) -> Int { ... }
}

// BAD — DI protocol invented "just in case"
protocol HealthManaging {
    func fetchSteps() async throws -> Int
}

// GOOD — inject concrete type; add protocol only when test demands it
final class SunlightViewModel {
    private let healthManager: HealthKitManager
    init(healthManager: HealthKitManager = .shared) { ... }
}
```

**Checklist before adding a protocol:**
1. Are there 2+ real conforming types right now? No → skip.
2. Is there a unit test that needs a mock? No → skip.
3. Does the system require conformance? No → skip.

## Rule 5: No Over-Engineering

- `@AppStorage` for simple persistent flags — not a VM `@State` + `UserDefaults` write
- Use existing computed properties before adding new data fields
- Three similar lines beats a premature abstraction
- No generics/protocols for single concrete use cases
- No feature flags, backwards-compat shims, or `_deprecated` variants — just change the code
- No error handling for scenarios that can't happen — trust framework guarantees
- Only validate at system boundaries (user input, external APIs)

```swift
// BAD — manual UserDefaults
private var nightLockEnabled: Bool {
    get { UserDefaults.standard.bool(forKey: "nightLock") }
    set { UserDefaults.standard.set(newValue, forKey: "nightLock") }
}

// GOOD
@AppStorage("nightLock") private var nightLockEnabled = false
```

Never use `@AppStorage` inside an `@Observable` class — it silently breaks observation (changes won't trigger view updates):

```swift
// BAD — @AppStorage inside @Observable
@Observable
class Settings {
    @AppStorage("theme") var theme = "light"
}

// GOOD — @AppStorage in the View, not the model
struct SettingsView: View {
    @AppStorage("theme") private var theme = "light"
}
```

### No Anonymous Inline Objects

Never instantiate objects inline at call sites if they are configurable, stateful, or reusable. Creates new allocations per call, scatters config, can't be injected or tested.

**Allowed only when:**
- Scoped to a small private function that is not reused elsewhere
- Must add a comment explaining why a shared instance isn't appropriate

```swift
// BAD — new allocation every call, config scattered
let data = try JSONEncoder().encode(request)
let model = try JSONDecoder().decode(Model.self, from: data)
let formatted = DateFormatter().string(from: date)
let session = URLSession(configuration: .default)

// GOOD — shared configured instance
extension JSONEncoder {
    static let shared: JSONEncoder = {
        let encoder = JSONEncoder()
        encoder.keyEncodingStrategy = .convertToSnakeCase
        return encoder
    }()
}

extension JSONDecoder {
    static let shared: JSONDecoder = {
        let decoder = JSONDecoder()
        decoder.keyDecodingStrategy = .convertFromSnakeCase
        decoder.dateDecodingStrategy = .iso8601
        return decoder
    }()
}

// GOOD — injectable dependency, testable
final class NetworkService {
    private let decoder: JSONDecoder

    init(decoder: JSONDecoder = .shared) {
        self.decoder = decoder
    }
}

// OK — one-off inside small non-reusable function, justified
private func debugDescription(of date: Date) -> String {
    // Debug-only path; not worth a shared formatter for a single format used nowhere else
    let formatter = DateFormatter()
    formatter.dateStyle = .short
    return formatter.string(from: date)
}
```

## Rule 6: Async / Error Handling

- All async operations `async throws` where errors matter
- `Task {}` only in ViewModels, not in Views
- Handle cancellation for timers and long-running operations
- No `try?` silently swallowing errors on critical paths
- Stored `Task` properties must use `[weak self]` and cancel in `deinit`

```swift
// BAD — no guard; calling load() twice (e.g. on each .onAppear) double-fetches
func load() {
    Task { state = .loading; let items = try await repo.fetchAll(); state = .loaded(items) }
}

// GOOD — guard prevents redundant work when view re-appears
func load() {
    guard case .idle = state else { return }
    Task { state = .loading; let items = try await repo.fetchAll(); state = .loaded(items) }
}

// BAD — silent failure on purchase
let result = try? await StoreKit.purchase(product)

// GOOD
let result = try await StoreKit.purchase(product)

// BAD — stored Task with strong self (retain cycle + never cancelled)
final class SyncManager {
    private var syncTask: Task<Void, Never>?

    func start() {
        syncTask = Task {
            while !Task.isCancelled {
                await self.sync()
            }
        }
    }
}

// GOOD
final class SyncManager {
    private var syncTask: Task<Void, Never>?

    func start() {
        syncTask = Task { [weak self] in
            while let self, !Task.isCancelled {
                await self.sync()
            }
        }
    }

    deinit { syncTask?.cancel() }
}
```

## Rule 7: General Structure

- No backwards-compatibility hacks (`_old`, `_v2`, `// removed`, unused `_var`)
- Delete unused code — don't comment it out
- `Destination` enums used with `.sheet(item:)` must be `Identifiable & Hashable` — use `var id: Self { self }`
- If `body` triggers "compiler unable to type-check", extract sub-expressions into `private var` computed properties

## Rule 8: Access Control

Apply the most restrictive access level that works. Default to `private`. Widen only when something genuinely needs to be visible.

| Access | Use when |
|---|---|
| `private` | Used only inside this file/type — default choice |
| `private(set)` | State owned internally, read-only externally |
| `internal` (default) | Shared within module — no keyword needed |
| `public` | Building a framework/library |
| `open` | Designed to be subclassed — explicit intent |

```swift
// BAD — everything public/internal by default, leaks internals
class UserStore {
    var isLoading = false
    var items: [Item] = []
    func fetchItems() { ... }
    func handleResponse(_ data: Data) { ... }
}

// GOOD — minimal surface, internals locked down
final class UserStore {
    private(set) var isLoading = false
    private(set) var items: [Item] = []

    func fetchItems() { ... }          // intentionally internal
    private func handleResponse(_ data: Data) { ... }
}

// BAD — open on a type not designed for subclassing
open class AnalyticsManager { ... }

// GOOD — final; open only on base types explicitly designed for inheritance
open class ServiceDispatcher<T: Requestable> { ... }   // subclassed by design
final class MoodivationService: ServiceDispatcher<EduTailsApi> { }
```

## Rule 9: Extension Discipline

Extensions on types **you own**: fine for protocol conformance, grouping related logic.
Extensions on types **you don't own** (Foundation, SwiftUI, third-party): only for syntactic convenience with no business logic.

```swift
// OK — convenience adapter on foreign type is fine
extension Dictionary where Key == String, Value == String {
    var parameter: APIRequestParameter { .urlQuery(self) }
}

// BAD — same extension but breaks other rules inside it
extension Dictionary where Key == String, Value == String {
    var body: APIRequestParameter {
        return .body(try! JSONEncoder().encode(self))  // FORCE-UNWRAP + ANON-OBJECT
    }
}

// GOOD — fix the violations, keep the extension
extension Dictionary where Key == String, Value == String {
    func body() throws -> APIRequestParameter {
        return .body(try JSONEncoder.shared.encode(self))
    }
}

// BAD — app domain logic hidden inside a foreign type
extension URL {
    var isProfilePhoto: Bool { path.contains("/profile/") }
}

// GOOD — belongs in your model
extension UserProfile {
    var isProfilePhotoURL: Bool { photoURL.path.contains("/profile/") }
}
```

Rule of thumb: convenience adapters on foreign types are fine. App domain logic (business rules, conditions, branching) on foreign types is not — it hides where the logic lives.

### Mapper Extensions

Mapping between DTO ↔ domain model uses extensions on your own types. No separate `Mapper` class needed.

```swift
// GOOD — extension on DTO (your type), maps to domain
extension UserDTO {
    func toDomain() -> User {
        User(id: userId, name: displayName, email: emailAddress)
    }
}

// GOOD — failable init on domain model (alternative style)
extension User {
    init?(_ dto: UserDTO) {
        guard !dto.userId.isEmpty else { return nil }
        self.init(id: dto.userId, name: dto.displayName, email: dto.emailAddress)
    }
}

// BAD — separate Mapper type for a trivial transform
struct UserMapper {
    func map(_ dto: UserDTO) -> User { ... }
}
```

**File placement**: mapper extension lives in `Data/Models/` alongside the DTO — same file or a dedicated `UserDTO+Mapping.swift`. Never in `Presentation/`.

## Rule 10: Force Unwrap / Force Try

**Default: never use `!` or `try!` unless failure is provably impossible.**

A force unwrap earns its place only when ALL are true:
1. The value is a **compile-time literal** (not a variable, not user input)
2. Failure would be a **programming error**, not a runtime condition
3. No safer alternative exists (e.g. `URL(staticString:)`)

```swift
// BAD — try! on fallible encoding (encoding CAN fail)
let data = try! JSONEncoder().encode(request)

// GOOD — propagate
let data = try JSONEncoder().encode(request)

// BAD — force unwrap on variable URL (can be nil at runtime)
let url = URL(string: userInput)!

// BAD — force unwrap on literal when safer API exists
let url = URL(string: "https://api.example.com/v1")!

// GOOD — staticString API for literal URLs (crashes at compile-time, not runtime)
let url = URL(staticString: "https://api.example.com/v1")

// BAD — force try on regex with variable pattern
let regex = try! NSRegularExpression(pattern: userPattern)

// OK — force try on literal pattern known valid at write-time
let regex = try! NSRegularExpression(pattern: "^[0-9]+$")
```

Never `try!`:
- `JSONEncoder().encode(_:)` — can fail for non-conforming Float values, custom encode logic
- `JSONDecoder().decode(_:from:)` — network data is never trusted
- Any call whose input is not a literal

## Rule 11: Color & Theme

Never hardcode colors inline. All colors must be semantic (system-adaptive) or named asset catalog entries.

### Semantic Color Hierarchy

Use the right semantic color for the job — don't reach for custom colors when system semantics already exist:

| Role | SwiftUI | UIKit |
|---|---|---|
| Primary text | `.primary` | `Color(.label)` |
| Secondary text | `.secondary` | `Color(.secondaryLabel)` |
| Tertiary text | `.tertiary` | `Color(.tertiaryLabel)` |
| Disabled text | `.quaternary` | `Color(.quaternaryLabel)` |
| Main background | `Color(.systemBackground)` | — |
| Grouped background | `Color(.systemGroupedBackground)` | — |
| Interactive fill | `Color(.systemFill)` | — |
| Separator | `Color(.separator)` | — |

```swift
// BAD — hardcoded, breaks dark mode and high contrast
Text("Hello")
    .foregroundStyle(Color(red: 0.2, green: 0.6, blue: 1.0))
    .background(Color(hex: "#F5F5F5"))

// BAD — non-adaptive; white stays white in dark mode
Rectangle().fill(Color.white)
Text("Label").foregroundStyle(.gray)  // may fail contrast

// GOOD — semantic, adapts automatically
Text("Title").foregroundStyle(.primary)
Text("Subtitle").foregroundStyle(.secondary)
VStack { }.background(Color(.systemBackground))
```

### Custom / Brand Colors — Asset Catalog

When you need a custom color (brand, product, accent):

1. Open `Assets.xcassets` → New Color Set
2. Name it clearly: `BrandPrimary`, `SurfaceCard`, `AccentDestructive`
3. Set **4 variants**: Light · Dark · High Contrast Light · High Contrast Dark
4. Declare once in `Color+Theme.swift`, use everywhere

```swift
// Color+Theme.swift — single source of truth
extension Color {
    static let brandPrimary    = Color("BrandPrimary")    // xcassets, 4 variants
    static let brandAccent     = Color("BrandAccent")
    static let surfaceCard     = Color("SurfaceCard")
    static let textOnBrand     = Color("TextOnBrand")
}

// At call sites — always via extension, never raw string
Text("Hello").foregroundStyle(.brandPrimary)
RoundedRectangle(cornerRadius: 12).fill(.surfaceCard)
```

**Rules:**
- No `Color(red:green:blue:)` or `Color(hex:)` at call sites — ever
- No `Color.white` / `Color.black` / `.gray` for UI text or backgrounds — use semantic or named asset
- No raw `Color("BrandPrimary")` at call sites — always via `Color+Theme.swift` extension
- Asset catalog color sets require all 4 variants: Light, Dark, High Contrast Light, High Contrast Dark
- No app-specific dark mode toggle — never use `.preferredColorScheme()` on the root based on user setting; respect system preference
- `.opacity()` on a semantic/asset color is fine; constructing a new `Color(red:green:blue:)` is not
- Color must never be the sole status indicator — always pair with icon or text

```swift
// BAD — colorblind users can't distinguish
Circle().fill(isComplete ? .green : .red)

// GOOD — shape + color + text
HStack {
    Image(systemName: isComplete ? "checkmark.circle.fill" : "xmark.circle.fill")
    Text(isComplete ? "Done" : "Pending")
}
.foregroundStyle(isComplete ? .green : .red)
```

## Rule 12: HIG Design Discipline

Follow Apple's Human Interface Guidelines. Enforce at code level.

### Tap Targets

Minimum 44×44pt on iOS. Pair with `contentShape` so the entire frame is tappable.

```swift
// BAD — icon-only button, tap area ~20pt
Button { action() } label: { Image(systemName: "xmark") }

// GOOD
Button { action() } label: { Image(systemName: "xmark") }
    .frame(minWidth: 44, minHeight: 44)
    .contentShape(Rectangle())
```

### Typography — Dynamic Type + Font Weight

```swift
// BAD — fixed size (won't scale), ultralight weight (legibility failure)
Text("Title").font(.system(size: 28, weight: .ultralight))
Text("Body").font(.custom("SFProText-Regular", size: 16))

// GOOD — system text styles scale automatically to 200%
Text("Title").font(.title)           // Bold weight, scales
Text("Body").font(.body)             // Regular weight, scales
Text("Caption").font(.caption)       // Never Light

// GOOD — custom font: must declare relativeTo for Dynamic Type
Text("Title").font(.custom("YourFont", size: 28, relativeTo: .title))
```

**Font weight**: never Ultralight, Thin, or Light. Regular minimum. Headers: Semibold/Bold.

### Spacing — 8pt Grid

```swift
// BAD — magic numbers
VStack(spacing: 13) { }
.padding(.horizontal, 17)

// GOOD — 8pt grid: 8, 12, 16, 20, 24, 32
VStack(spacing: 16) { }
.padding(.horizontal, 16)
```

### SF Symbols

```swift
// BAD — custom asset where SF Symbol exists
Image("icon-share")

// BAD — symbol weight mismatches surrounding label weight
Image(systemName: "square.and.arrow.up").fontWeight(.bold)

// GOOD — use Label so symbol and text share weight automatically
Label("Share", systemImage: "square.and.arrow.up")
    .font(.body)

// GOOD — explicit rendering mode for multicolor symbols
Image(systemName: "heart.fill")
    .symbolRenderingMode(.multicolor)
    .foregroundStyle(.red)
```

### Tab Bar

```swift
// BAD — icon without text label (HIG violation, App Store rejection risk)
TabView {
    HomeView().tabItem { Image(systemName: "house") }
}

// GOOD — every tab must have icon + text
TabView {
    HomeView().tabItem { Label("Home", systemImage: "house") }
    SearchView().tabItem { Label("Search", systemImage: "magnifyingglass") }
}
```

### Sheets & Navigation

```swift
// BAD — no dismiss affordance
.sheet(isPresented: $show) { ContentView() }

// GOOD — cancellationAction + confirmationAction (never both + Back)
.sheet(isPresented: $show) {
    NavigationStack {
        ContentView()
            .toolbar {
                ToolbarItem(placement: .cancellationAction) { Button("Cancel") { show = false } }
                ToolbarItem(placement: .confirmationAction) { Button("Done") { save(); show = false } }
            }
    }
}
```

### Reduce Motion

```swift
// BAD — animation always plays regardless of accessibility setting
.animation(.spring(), value: isExpanded)

// GOOD
@Environment(\.accessibilityReduceMotion) var reduceMotion

.animation(reduceMotion ? nil : .spring(), value: isExpanded)
```

### VoiceOver

```swift
// BAD — VoiceOver reads "Button"
Button { share() } label: { Image(systemName: "square.and.arrow.up") }

// GOOD
Button { share() } label: { Image(systemName: "square.and.arrow.up") }
    .accessibilityLabel("Share")
```

```
│           └── UserEndpoint.swift
│
├── Common/
│   ├── Extensions/                // convenience only, no business logic (Rule 9)
│   └── Helpers/                   // stateless pure functions
│
├── Theme/
│   ├── Color+Theme.swift          // all Color extensions (Rule 11)
│   ├── Typography.swift           // font scale constants if needed
│   └── Assets.xcassets            // Color Sets (4 variants each) + images
│
└── DI/                            // dependency wiring only — no business logic (Rule 16)
    ├── AppFactory.swift           // top-level graph: View → ViewModel → DataFactory
    ├── PresentationFactory.swift  // creates ViewModels with injected deps
    └── DataFactory.swift          // creates Services, Repositories, Persistence
```

### Rules

- One file per type — no `Utilities.swift` / `Misc.swift` dumping grounds
- `Color+Theme.swift` lives in `Theme/` — single source of truth
- `Common/` is for code shared across features; business logic goes in `Data/`
- `Data/Models/` for Codable structs only — no view state, no UI imports
- Test target mirrors source tree: `Tests/Presentation/Home/HomeViewModelTests.swift`

### Naming Conventions per Layer

| Layer | Suffix | When |
|---|---|---|
| View | `View` or `Screen` | SwiftUI view |
| ViewModel | `ViewModel` | MVVM view model |
| Service | `Service` | **network / remote** operations |
| Persistence | `Persistence` | **local / disk**: UserDefaults, Keychain, file system, Core Data |
| Repository | `Repository` | bridges Service + Persistence; single source of truth for a domain |
| Endpoint | `Endpoint` or `Api` | API request definition |
| Model | none | pure data struct (`User`, `Content`) |
| Manager | `Manager` | **complex domain logic / rules** (Rule 14) |
| Store | `Store` | global observable state (`SessionStore`) |

**SwiftData exception**: SwiftData models use `@Model` + `ModelContext` — no `Persistence` suffix needed. SwiftData types follow model naming (`User`, `CachedItem`), not the persistence layer convention.

```swift
// BAD — disk storage named "Service"
final class TokenService { ... }           // actually writes to Keychain

// GOOD — named by what it does
final class TokenPersistence { ... }       // Keychain read/write
final class AuthService { ... }            // network: sign in, refresh token API calls

// GOOD — protocol-named when injected
protocol TokenStoring {
    func save(_ token: String) throws
    func load() throws -> String
}
final class KeychainTokenPersistence: TokenStoring { ... }
```

## Rule 14: Business Logic Manager

Complex domain calculations and rules belong in a `Manager` type — not in ViewModel, not in Service, not in Repository.

**When to use Manager**: multi-step calculation, eligibility rules, scoring logic, pricing, state machine transitions — anything with branching domain rules that must be unit-tested in isolation.

### Protocol-First — Never Inject Concrete

```swift
// BAD — concrete dependency, untestable
final class PointsViewModel {
    private let manager = PointsCalculationManager()   // can't swap in tests
}

// BAD — protocol exists but init takes concrete
protocol PointsCalculating { ... }
final class PointsViewModel {
    init(manager: PointsCalculationManager) { ... }    // still locked to concrete
}

// GOOD — init accepts protocol, concrete is default
protocol PointsCalculating {
    func calculate(base: Int, multiplier: Double) -> Int
    func eligibility(for user: User) -> EligibilityResult
}

final class PointsViewModel {
    private let manager: any PointsCalculating

    init(manager: any PointsCalculating = PointsCalculationManager()) {
        self.manager = manager
    }
}
```

### Manager Structure

```swift
// GOOD — Manager owns the rules, dependencies injected as protocols
protocol PointsCalculating {
    func calculate(base: Int, multiplier: Double) -> Int
    func eligibility(for user: User) -> EligibilityResult
}

final class PointsCalculationManager: PointsCalculating {
    private let calendar: any CalendarProviding   // injected, not Calendar.current
    private let config: any PointsConfigProviding

    init(
        calendar: any CalendarProviding = SystemCalendarProvider(),
        config: any PointsConfigProviding = AppPointsConfig()
    ) {
        self.calendar = calendar
        self.config = config
    }

    func calculate(base: Int, multiplier: Double) -> Int {
        // pure domain logic here — no network, no disk
        let adjusted = Double(base) * multiplier
        return Int(adjusted.rounded())
    }

    func eligibility(for user: User) -> EligibilityResult {
        guard user.isActive else { return .ineligible(.accountInactive) }
        guard calendar.isWeekday() else { return .ineligible(.weekendRestriction) }
        return .eligible
    }
}
```

### Rules

- Manager contains **only** domain logic — no URLSession, no disk I/O, no SwiftData
- Every dependency injected as a protocol — no `Date()`, `Calendar.current`, `UUID()` inline
- Manager is `final class` — not a struct (holds injected deps, not value semantics)
- One protocol per Manager — `PointsCalculating` not `PointsManager`
- Lives in `Data/Managers/` alongside Services and Repositories
- Test with `MockPointsCalculationManager: PointsCalculating` — no network/disk needed

```swift
// BAD — untestable time dependency
func isEligibleToday() -> Bool {
    Calendar.current.isWeekday(Date())   // hardcoded, can't control in tests
}

// GOOD — injectable
protocol CalendarProviding {
    func isWeekday() -> Bool
}
func isEligibleToday() -> Bool {
    calendar.isWeekday()
}
```

## Rule 15: Delegation

Delegate protocols must be `AnyObject`-constrained so the owning type can hold a `weak` reference. Delegate property is always `weak var`. Protocol name ends in `Delegate`. First method parameter is the sender.

```swift
// BAD — strong delegate (retain cycle)
protocol LoaderCallback {
    func didFinish()
}
final class DataLoader {
    var callback: LoaderCallback?   // strong reference — retain cycle if parent holds loader
}

// BAD — wrong method signature (no sender, bad name suffix)
protocol DataDelegate {
    func finished(_ data: [Item])
}

// GOOD
protocol DataLoaderDelegate: AnyObject {
    func dataLoader(_ sender: DataLoader, didFinish items: [Item])
    func dataLoader(_ sender: DataLoader, didFailWith error: Error)
}

final class DataLoader {
    weak var delegate: (any DataLoaderDelegate)?

    private func finish(with items: [Item]) {
        delegate?.dataLoader(self, didFinish: items)
    }
}
```

Delegate value capture in async context — capture param values BEFORE spawning Task:

```swift
// BAD — reads delegate after suspension; delegate may be nil
func process(item: Item) {
    Task { [weak self] in
        guard let self else { return }
        let result = await compute(item)
        self.delegate?.dataLoader(self, didFinish: result)
    }
}

// GOOD — capture value before any suspension
func process(item: Item) {
    let delegate = self.delegate
    Task {
        let result = await compute(item)
        await MainActor.run { delegate?.dataLoader(self, didFinish: result) }
    }
}
```

### Rules

- Delegate protocol must be `AnyObject`-constrained
- `weak var delegate: (any XxxDelegate)?` — always weak, always optional
- Protocol suffix: `Delegate`
- First method param: sender (`_ sender: OwningType`)
- Capture delegate value before spawning `Task` — not inside closure after suspension

## Rule 16: Dependency Injection

All dependencies are injected via `init`. **Factory types in `DI/` are the canonical wiring** — they own the full object graph. Default arguments on `init` are a convenience for leaf types and tests only; when a factory exists for a type, the factory is the single source of truth and the default arg is omitted (no double-declaration of the concrete). Prefer manual DI; Swinject permitted only with project-wide approval.

```swift
// BAD — ViewModel creates own deps (untestable)
@Observable @MainActor
final class HomeViewModel {
    private let service = UserService()
    private let persistence = UserDefaultsPersistence()
}

// GOOD — injected via init, defaults are concrete impls
@Observable @MainActor
final class HomeViewModel {
    private let service: any UserProviding
    private let persistence: any UserPersisting

    init(
        service: any UserProviding = UserService(),
        persistence: any UserPersisting = UserDefaultsPersistence()
    ) {
        self.service = service
        self.persistence = persistence
    }
}
```

Factory types live in `DI/` and own wiring:

```swift
// DI/AppFactory.swift
enum AppFactory {
    static func makeHomeView() -> HomeView {
        HomeView(viewModel: PresentationFactory.makeHomeViewModel())
    }
}

// DI/PresentationFactory.swift
enum PresentationFactory {
    static func makeHomeViewModel() -> HomeViewModel {
        HomeViewModel(
            service: DataFactory.makeUserService(),
            persistence: DataFactory.makeUserPersistence()
        )
    }
}

// DI/DataFactory.swift
enum DataFactory {
    static func makeUserService() -> UserService { UserService() }
    static func makeUserPersistence() -> UserDefaultsPersistence { UserDefaultsPersistence() }
}
```

Swinject (if approved):

```swift
// DI/Container.swift
import Swinject

extension Container {
    static let shared: Container = {
        let c = Container()
        c.register((any UserProviding).self) { _ in UserService() }
        c.register(HomeViewModel.self) { r in
            // Resolver `!` at the composition root is the ONE sanctioned force-unwrap
            // (Rule 10 exception): a missing registration is a programmer error, caught
            // at first launch, not a runtime condition. Keep it confined to DI/.
            HomeViewModel(service: r.resolve((any UserProviding).self)!)
        }
        return c
    }()
}
```

### Rules

- All deps injected via `init` — no `SomeService()` inside a ViewModel or Repository body
- Factories are canonical wiring; omit the `init` default arg when a factory makes the type
- `init` default args allowed only for leaf types/tests — never force-unwrapped optionals
- Factory types are `enum` (no instances needed), grouped in `DI/` folder
- `DI/AppFactory.swift` → top-level graph; `DI/PresentationFactory.swift` → ViewModels; `DI/DataFactory.swift` → Services/Repos
- Swinject: register in `DI/Container.swift`, resolve only in factories — not in ViewModels. Resolver `!` is confined to `DI/` (Rule 10 exception)
- No `@EnvironmentObject` as a substitute for DI in business-logic types

## Rule 17: Typed Errors

Each domain defines a typed `Error` enum. `try?` is banned on critical paths. `catch {}` that swallows silently is a violation. Use Swift 6+ typed throws (`throws(DomainError)`) where the error set is closed.

```swift
// BAD — untyped, swallowed
func signIn() async throws {
    guard let data = try? fetchToken() else { return }   // failure invisible
    throw NSError(domain: "Auth", code: -1, userInfo: nil)
}

// BAD — catch swallows
do {
    try await authService.signIn(email: email, password: password)
} catch {
    print("error: \(error)")   // not handled, not re-thrown
}

// GOOD — typed domain error
enum AuthError: Error {
    case invalidCredentials
    case tokenExpired
    case networkUnavailable(underlying: Error)
}

func signIn(email: String, password: String) async throws(AuthError) -> User {
    guard !email.isEmpty else { throw .invalidCredentials }
    do {
        return try await network.authenticate(email: email, password: password)
    } catch let e as NetworkError {
        throw .networkUnavailable(underlying: e)
    } catch {
        // A typed-throws function (`throws(AuthError)`) cannot propagate a foreign
        // error — every untyped error must be mapped into the domain type or it
        // won't compile. Catch-all maps the remainder.
        throw .networkUnavailable(underlying: error)
    }
}

// GOOD — handle specifically, don't swallow
do {
    let user = try await authService.signIn(email: email, password: password)
    state = .authenticated(user)
} catch AuthError.invalidCredentials {
    state = .failed(.invalidCredentials)
} catch AuthError.tokenExpired {
    state = .failed(.tokenExpired)
} catch {
    state = .failed(.networkUnavailable(underlying: error))
}
```

### Rules

- Each domain has one `enum XxxError: Error` — not `NSError`, not raw `Error`
- `try?` allowed only for genuinely optional operations (cache reads, speculative pre-fetch)
- Critical path (auth, data write, payment): always `try`, never `try?`
- `catch {}` must either handle, propagate with `throw`, or log with `Logger` — no silent discard
- Typed throws `throws(DomainError)` where error set is known and closed (Swift 6+)

## Rule 18: Localization

All user-visible strings are localized. SwiftUI `Text("key")` auto-localizes from `.xcstrings` catalog. Non-SwiftUI code uses `String(localized: "key")`. String concatenation for user-visible text is a violation.

```swift
// BAD — string concatenation bypasses localization
let title = "Hello, " + name + "!"
let message = "Error occurred. Please try again."

// BAD — raw English in non-SwiftUI UIKit code
let alert = UIAlertController(title: "Sign In Failed", message: "Check your credentials.", preferredStyle: .alert)

// GOOD — SwiftUI Text uses .xcstrings catalog automatically
Text("welcome_title")
Button("save_button") { ... }

// GOOD — non-SwiftUI code
let message = String(localized: "error_occurred")
let alert = UIAlertController(
    title: String(localized: "sign_in_failed"),
    message: String(localized: "check_credentials"),
    preferredStyle: .alert
)

// GOOD — interpolation via xcstrings format argument
Text("hello_name \(name)")
let greeting = String(localized: "hello_name \(name)")
```

### Rules

- All user-visible strings in `.xcstrings` catalog (or `Localizable.strings`)
- `Text("key")` and `Button("key")` in SwiftUI auto-localize — use keys, not English sentences
- Non-SwiftUI: `String(localized: "key")` not raw English
- String concatenation for user-visible text is a violation — use format arguments in xcstrings
- Error messages shown to users must be localized — not `error.localizedDescription` passed directly to UI without localized wrapping

## Rule 19: Magic Numbers

No inline numeric literals for **domain values** — thresholds, durations, counts, ratios, prices. These get named constants or `enum` cases.

**Exempt (inline is fine):** the canonical 8pt-grid spacing values (`4, 8, 12, 16, 20, 24, 32`) and the HIG tap-target `44`. These are well-known design constants; Rules 11–12 show them inline and that is correct. Promoting them to `Spacing.*` / `Metrics.*` tokens is encouraged for reuse but **not required** — and never flagged as a violation. Non-grid layout numbers (`13`, `17`, `37`) ARE violations: snap to the grid or name them.

```swift
// OK — canonical grid + HIG values inline (matches Rules 11–12)
.frame(minWidth: 44, minHeight: 44)
.padding(.horizontal, 16)
.cornerRadius(8)

// BAD — off-grid layout literals
VStack(spacing: 13) { }
.padding(.horizontal, 17)

// BAD — domain magic numbers in logic
if score > 750 { ... }
let timeout: TimeInterval = 30
let fontSize: CGFloat = 28   // also breaks Dynamic Type — see Rule 12

// GOOD — named constants in Theme/
enum Spacing {
    static let xs: CGFloat = 4
    static let sm: CGFloat = 8
    static let md: CGFloat = 16
    static let lg: CGFloat = 24
    static let xl: CGFloat = 32
}

enum Radius {
    static let sm: CGFloat = 8
    static let md: CGFloat = 12
    static let lg: CGFloat = 16
    static let pill: CGFloat = 9999
}

enum Metrics {
    static let minimumTapTarget: CGFloat = 44
}

// GOOD — tokens (optional for grid values, encouraged for reuse)
.padding(.horizontal, Spacing.md)
.cornerRadius(Radius.sm)
.frame(minWidth: Metrics.minimumTapTarget, minHeight: Metrics.minimumTapTarget)

// GOOD — domain constants near their domain (REQUIRED, not optional)
extension CreditPolicy {
    static let premiumScoreThreshold = 750
    static let requestTimeoutSeconds: TimeInterval = 30
}
```

### Rules

- **Domain values** (thresholds, durations, counts, prices, ratios) MUST be named constants — never inline
- **Layout values:** canonical 8pt grid (`4, 8, 12, 16, 20, 24, 32`) and HIG `44` are exempt — inline is fine, tokens optional
- Off-grid layout literals (`13`, `17`, …) are violations — snap to grid or name them
- Design tokens (`Spacing`, `Radius`, `Metrics`) live in `Theme/`
- Domain-specific constants live in `extension` on the owning type, not global scope
- `0` and `1` in ratio/multiplier expressions are exempt
- Color literals are covered by Rule 11; fixed font sizes by Rule 12

## Rule 20: Logging

No `print()` in production. Use `Logger` from `os` framework with subsystem and category. PII must use `.private` or `.hash` privacy level. Each module declares its own `private let logger`.

```swift
// BAD — print in production code
print("User signed in: \(userId)")
print("Error: \(error)")
debugPrint(response)

// BAD — Logger without context
Logger().log("Something happened")

// GOOD
import OSLog

private let logger = Logger(subsystem: "com.myapp.MyApp", category: "Auth")

func signIn(email: String) async throws -> User {
    logger.info("Sign-in attempt started")
    do {
        let user = try await network.authenticate(email: email)
        logger.info("Sign-in succeeded userHash: \(user.id, privacy: .hash)")
        return user
    } catch {
        logger.error("Sign-in failed: \(error.localizedDescription, privacy: .public)")
        throw error
    }
}
```

Log level guide:
- `.debug` — verbose, development-only (stripped in release by default)
- `.info` — informational, production-safe
- `.error` — recoverable failures
- `.fault` — non-recoverable, programmer bugs (wrong state, impossible branch)

### Rules

- No `print()`, `debugPrint()`, or `NSLog()` in production code
- `Logger(subsystem: bundleId, category: featureName)` — always both params
- `private let logger` per file/module — not a shared singleton
- PII (email, user ID, token): `.privacy(.private)` or `.privacy(.hash)`
- Non-sensitive values default to `.public`; use `.auto` in debug-only paths
- `.fault` for programmer errors; `.error` for runtime failures

## Rule 21: Testing Conventions

Use Swift Testing for all new tests. `@Suite struct`, `@Test`, `#expect`, `#require`. Test doubles use `Mock` prefix. No `XCTAssert*` in Swift Testing functions. ViewModel tests use `@Test @MainActor`.

```swift
// BAD — XCTest style in new code
func testSignIn_success() async throws {
    XCTAssertEqual(result.name, "Alice")
}

// BAD — class Suite (shared mutable state bugs)
@Suite class HomeViewModelTests { }

// BAD — ambiguous test double name
class FakeUserService: UserProviding { }

// GOOD — Swift Testing
import Testing

@Suite struct HomeViewModelTests {

    @Test("Given valid credentials, state becomes authenticated")
    @MainActor
    func givenValidCredentials_stateBecomesAuthenticated() async {
        let mockService = MockUserService()
        let viewModel = HomeViewModel(service: mockService)

        await viewModel.signIn(email: "a@b.com", password: "secret")

        #expect(viewModel.state == .authenticated)
        #expect(mockService.signInCallCount == 1)
    }

    @Test("Given network failure, state shows error", arguments: [
        AuthError.invalidCredentials,
        AuthError.tokenExpired
    ])
    @MainActor
    func givenFailure_stateShowsError(error: AuthError) async {
        let mockService = MockUserService(failWith: error)
        let viewModel = HomeViewModel(service: mockService)

        await viewModel.signIn(email: "a@b.com", password: "secret")

        #expect(viewModel.state.isError)
    }
}

// Mock naming
final class MockUserService: UserProviding {
    var signInCallCount = 0
    private let failWith: AuthError?

    init(failWith: AuthError? = nil) { self.failWith = failWith }

    func signIn(email: String, password: String) async throws -> User {
        signInCallCount += 1
        if let error = failWith { throw error }
        return User.fixture()
    }
}
```

`confirmation()` for async callback testing:

```swift
@Test("Delegate receives didFinish after load")
func delegateReceivesDidFinish() async {
    let loader = DataLoader()
    let mockDelegate = MockDataLoaderDelegate()
    loader.delegate = mockDelegate

    await confirmation("delegate called once") { confirm in
        mockDelegate.onDidFinish = { confirm() }
        loader.load()
    }
}
```

### Rules

- New tests: Swift Testing — not `XCTAssert*` (`@Test`, `#expect`, `try #require`)
- `@Suite struct` not `class` — value semantics, no shared state
- Test display name in `@Test("When X, then Y")` — describes behavior
- Test double prefix: `Mock` — not Fake, Stub, Spy
- `@Test @MainActor` for tests touching `@Observable @MainActor` ViewModels
- Parameterized tests via `@Test(arguments: [...])` — not duplicated test functions
- `try #require(optional)` for fail-fast unwrap
- `withKnownIssue("reason") { }` not `.disabled` for known-broken tests
- Keep XCTest for: `XCUIApplication` UI tests, `XCTMetric` performance, ObjC tests

## Rule 22: Init Discipline

`init` does assignment only. No `Task {}`, no side effects, no async work. Default arguments use concrete implementations. Failable `init?` for invalid construction-time state. Validation guard at top before assignments.

```swift
// BAD — side effect in init
@Observable @MainActor
final class HomeViewModel {
    init() {
        Task { await load() }
        NotificationCenter.default.addObserver(...)
    }
}

// BAD — fatalError for invalid input
init(config: Config) {
    self.url = config.baseURL
    guard !config.apiKey.isEmpty else { fatalError("apiKey required") }
}

// GOOD — pure assignment, no side effects
@Observable @MainActor
final class HomeViewModel {
    private let service: any UserProviding
    private(set) var state = HomeState()

    init(service: any UserProviding = UserService()) {
        self.service = service
    }

    func load() {
        Task { await fetchUser() }   // called by View via .onAppear
    }
}

// GOOD — failable init for invalid state
struct APIConfig {
    let baseURL: URL
    let apiKey: String

    init?(baseURLString: String, apiKey: String) {
        guard let url = URL(string: baseURLString), !apiKey.isEmpty else { return nil }
        self.baseURL = url
        self.apiKey = apiKey
    }
}
```

### Rules

- `init` does assignment only — no `Task {}`, no `NotificationCenter`, no URLSession
- Validate at top: `guard` or failable `init?` before any property assignments
- No `fatalError` in `init` for invalid input — use failable `init?` or `throws`
- Default args = concrete impls for ergonomic call sites
- `URL(staticString:)` for compile-time-known URLs; `URL(string: literal)!` only when literal cannot fail
- ViewModel: View calls `viewModel.load()` via `.onAppear { viewModel.load() }`, never from `init`

## Rule 23: Reactive Streams and Observation

Prefer `AsyncStream` for new event publishers. Combine is maintained, not extended. `NotificationCenter` names use typed extensions. Stored `Task` properties need `[weak self]` and cancellation in `deinit`. No GCD.

```swift
// BAD — raw string notification name
NotificationCenter.default.addObserver(
    forName: NSNotification.Name("UserDidLogOut"),
    object: nil, queue: .main
) { _ in self.handleLogOut() }   // strong self, no removal

// GOOD — typed name extension
extension Notification.Name {
    static let userDidLogOut = Notification.Name("com.myapp.userDidLogOut")
}

// BETTER — AsyncStream instead of NotificationCenter
// CAVEAT: AsyncStream is single-consumer. Two `for await` loops on the same
// stream SPLIT events between them — they don't each receive every value. For
// one observer this is ideal; for fan-out, give each consumer its own stream
// (e.g. a `makeEvents() -> AsyncStream` factory) or use a broadcasting type.
final class AuthService {
    private let (stream, continuation) = AsyncStream.makeStream(of: AuthEvent.self)
    var events: AsyncStream<AuthEvent> { stream }

    func signOut() {
        continuation.yield(.signedOut)
    }
}

// Consumer in ViewModel
private var observationTask: Task<Void, Never>?

func startObservingAuth() {
    observationTask = Task { [weak self] in
        guard let self else { return }
        for await event in authService.events {
            await handleEvent(event)
        }
    }
}

deinit {
    observationTask?.cancel()
}
```

Combine (existing pipelines — maintain, don't extend with new publishers):

```swift
@Observable @MainActor
final class SearchViewModel {
    private var cancellables = Set<AnyCancellable>()

    func bind(searchText: Published<String>.Publisher) {
        searchText
            .debounce(for: .milliseconds(300), scheduler: DispatchQueue.main)
            .removeDuplicates()
            .sink { [weak self] query in
                self?.search(query: query)
            }
            .store(in: &cancellables)
    }
}
```

### Rules

- `AsyncStream` for new reactive sequences — not new Combine publishers, not raw `NotificationCenter`
- `AsyncStream` is single-consumer — for multiple observers, vend one stream per consumer or broadcast
- `Notification.Name` always typed via `extension Notification.Name` — no raw string literals
- SwiftUI: use `.task` modifier for observation (auto-cancels on view disappear)
- Combine: `[weak self]` in every `.sink`; store in `Set<AnyCancellable>` property
- Stored `Task` property: `[weak self]` inside + `task?.cancel()` in `deinit`
- No `DispatchQueue.main.async` — use `@MainActor` or `MainActor.run { }`
- No `DispatchQueue.global().async` — use `@concurrent` or extract to actor
- `Task.detached` only when intentionally discarding actor context — document why

## Rule 24: Typestate Pattern

Make invalid states unrepresentable using the Swift type system. Replace `Bool + Optional` combos with enums. Replace flag soup with single-source-of-truth enums with associated values.

```swift
// BAD — multiple orthogonal booleans (impossible states representable)
struct ProfileState {
    var isLoading: Bool = false
    var user: User? = nil
    var error: Error? = nil
    // isLoading=true + user=non-nil is invalid but compilable
}

// BAD — boolean flag soup
struct UploadState {
    var isUploading = false
    var isPaused = false
    var isSuccess = false
    var isError = false
    // 16 combinations, only 4 are valid
}

// GOOD — enum: exactly one state active at a time
// Note: `Error` and arbitrary models aren't Equatable, so Equatable can't be
// auto-synthesized — write `==` by hand (compare by identity / case), or skip
// Equatable and expose helper accessors like `isError`.
enum ProfileState {
    case idle
    case loading
    case loaded(User)
    case failed(Error)

    var isError: Bool {
        if case .failed = self { return true }
        return false
    }
}

extension ProfileState: Equatable {
    static func == (lhs: ProfileState, rhs: ProfileState) -> Bool {
        switch (lhs, rhs) {
        case (.idle, .idle), (.loading, .loading): return true
        case let (.loaded(a), .loaded(b)): return a.id == b.id
        case let (.failed(a), .failed(b)): return (a as NSError) == (b as NSError)
        default: return false
        }
    }
}

enum UploadState {
    case idle
    case uploading(progress: Double)
    case paused(progress: Double)
    case success(url: URL)
    case failed(Error)
}

// GOOD — phantom types for compile-time state enforcement
struct Token<State> {
    let value: String
}
enum Unverified {}
enum Verified {}

func verify(_ token: Token<Unverified>) async throws -> Token<Verified> { ... }
func callAPI(with token: Token<Verified>) async throws -> Response { ... }
// callAPI(with: unverifiedToken) → compile error
```

ViewModel using typestate:

```swift
@Observable @MainActor
final class ProfileViewModel {
    private(set) var state: ProfileState = .idle

    func load() {
        Task {
            state = .loading
            do {
                let user = try await service.fetchCurrentUser()
                state = .loaded(user)
            } catch {
                state = .failed(error)
            }
        }
    }
}
```

### Rules

- Replace `isLoading: Bool` + `data: T?` + `error: Error?` with a single `State` enum
- Enum cases carry associated values — not separate parallel properties
- Scan for `var isX: Bool` + `var x: X?` pairs — these are typestate violations
- Navigation routes: `enum Route: Hashable` not `@State var showSheet = false` flag soup
- Phantom types for compile-time state enforcement (verified vs unverified, authenticated vs guest)
- Impossible state = compile error, not runtime guard

## Rule 25: NavigationStack

Use value-based `NavigationStack` with a typed `Router`. Never push navigation from a ViewModel.

```swift
// BAD — deprecated NavigationView
NavigationView {
    NavigationLink(destination: DetailView(item: item)) {
        Text(item.title)
    }
}

// BAD — view-based NavigationLink (destination: evaluated eagerly)
NavigationStack {
    NavigationLink(destination: ProfileView()) {
        Text("Profile")
    }
}

// GOOD — value-based NavigationStack with typed Router
enum Route: Hashable {
    case detail(Item)
    case profile
    case settings
}

@Observable @MainActor
final class Router {
    var path = NavigationPath()

    func push(_ route: Route) { path.append(route) }
    func pop() { path.removeLast() }
    func popToRoot() { path.removeLast(path.count) }
}

struct RootView: View {
    @State private var router = Router()

    var body: some View {
        NavigationStack(path: $router.path) {
            HomeView()
                .navigationDestination(for: Route.self) { route in
                    switch route {
                    case .detail(let item): DetailView(item: item)
                    case .profile:         ProfileView()
                    case .settings:        SettingsView()
                    }
                }
        }
        .environment(router)
    }
}

// Child view navigates via Router from environment
struct HomeView: View {
    @Environment(Router.self) private var router

    var body: some View {
        Button("Go to Profile") { router.push(.profile) }
    }
}

// BAD — ViewModel drives navigation (imports SwiftUI, couples to Router)
@Observable @MainActor
final class ItemViewModel {
    var router: Router  // ViewModel owns navigation = layer violation

    func didTapItem(_ item: Item) {
        router.push(.detail(item))  // navigation is a presentation concern
    }
}

// GOOD — View handles navigation trigger, ViewModel provides intent
struct ItemView: View {
    @Environment(Router.self) private var router
    var viewModel: ItemViewModel

    var body: some View {
        List(viewModel.items) { item in
            NavigationLink(item.title, value: Route.detail(item))
        }
    }
}
```

For heterogeneous or deep-linkable paths, use `NavigationPath` directly. For homogeneous stacks (one destination type only), a typed `[Route]` array is cleaner than `NavigationPath`.

```swift
// Homogeneous stack — simpler
@Observable @MainActor
final class Router {
    var path: [Route] = []
}

// Heterogeneous / URL deep-linkable — use NavigationPath
@Observable @MainActor
final class Router {
    var path = NavigationPath()
}
```

### Rules

- Replace `NavigationView` with `NavigationStack` — `NavigationView` is deprecated
- Use value-based `NavigationLink(_:value:)` not destination-based `NavigationLink(destination:)`
- Define `enum Route: Hashable` for all navigable destinations
- Route via `@Observable @MainActor final class Router` injected via `@Environment`
- Place single `.navigationDestination(for: Route.self)` at root, not scattered across child views
- ViewModels must not import SwiftUI or hold a `Router` reference — navigation is a presentation concern
- Use `NavigationPath` for heterogeneous/deep-linkable stacks; typed `[Route]` for homogeneous stacks
- Handle deep links via `onOpenURL` at root, mapping URL → `Route`, then calling `router.push(_:)`

## Rule 26: Parameter Struct

When a function or initializer requires 4 or more parameters, extract them into a dedicated struct.

```swift
// BAD — 4+ inline parameters
func fetchTodos(
    searchText: String,
    showCompleted: Bool,
    sortOrder: SortOrder,
    limit: Int
) async throws -> [Todo] { ... }

// called at callsite — hard to read, no defaults without overloads
let todos = try await repo.fetchTodos(searchText: "", showCompleted: true, sortOrder: .createdAt, limit: 50)

// GOOD — parameter struct
struct TodoFilter {
    var searchText: String = ""
    var showCompleted: Bool = true
    var sortOrder: SortOrder = .createdAt
    var limit: Int = 50

    enum SortOrder { case createdAt, title }
}

func fetchTodos(_ filter: TodoFilter = TodoFilter()) async throws -> [Todo] { ... }

// callsite — readable, extensible, default-able
let todos = try await repo.fetchTodos()
let filtered = try await repo.fetchTodos(TodoFilter(searchText: "buy", showCompleted: false))
```

Struct can carry logic that belongs with its data:

```swift
extension TodoFilter {
    func apply(to todos: [Todo]) -> [Todo] {
        todos
            .filter { showCompleted || !$0.isCompleted }
            .filter { searchText.isEmpty || $0.title.localizedCaseInsensitiveContains(searchText) }
            .sorted {
                switch sortOrder {
                case .createdAt: $0.createdAt < $1.createdAt
                case .title:     $0.title < $1.title
                }
            }
    }

    var isActive: Bool { !searchText.isEmpty || !showCompleted }
}
```

### Rules

- 4+ parameters → extract to a named struct (name it `<Domain>Params`, `<Domain>Filter`, `<Domain>Config`, `<Domain>Request`)
- Struct lives next to its consumer or in `Models/` if shared across layers
- Give parameters sensible defaults — callsite should only supply what differs
- Logic that operates on the parameters belongs in the struct, not scattered at callsites
- 2–3 clearly ordered primitives are fine inline (`clamp(_ value: Double, min: Double, max: Double)`)
- System API overrides where you don't control the signature are exempt
