# PPT Orchestrator · 统一 PPT / 长图 / 周报 调度器

> **本 skill 是"统一入口 + 风格字典 + 决策树"——不做具体出图。出图本身分发到下游 skill（ai-image-to-pptx / html-ppt-viewer / mckinsey-presentation-generator / huashu-design / design-master）。**

## 何时用这个 Skill

**触发场景**：
- "做 PPT / 做个演示 / 演示文稿 / 幻灯片 / slides / deck / presentation"
- "打包成 HTML / HTML 阅读器 / HTML PPT"
- "真实 .pptx / PowerPoint 文件 / 可编辑的 PPT"
- "周报长图 / 月报 / 年报 / 事件复盘长图"
- "卡脖子分析长图 / 三棱镜长图"
- 任何 N 张图打包成可演示文档的需求

**不触发**（让其他 skill 处理）：
- 单张海报/封面/KV → `design-master` / `product-visual-creator`
- 视频 → `remotion-video`
- 漫画 → `comic-generator`
- 小红书单张图 → `xiaohongshu-image-creator`

## 一句话定位

```
做 PPT 真正难的，不是 prompt、不是模型、也不是工具，是这条闭环
  → 吃透内容 → 章节清单 → 60 行 prompt → 渲染核对 → 接受 AI 调整 → 沉淀 case
           ↓
  6 种风格字典选一种 + 输出形式决策树选一种 + 下游 skill 执行
```

## Step 0 · 风格 + 颜色主题讨论（用户硬规则 · 2026-07-04 沉淀）

> **优先级最高**：做「生图 PPT」或「HTML PPT」前，**必须先和用户讨论清楚风格 + 颜色主题**，才能开始ppt 出图法 V2 7 步。
> **来源**：用户 2026-07-04 15:44：「以后你做生图ppt时或者做html ppt时 务必选和我讨论清楚选哪种风格 哪种颜色主题」

**触发词**：「做 PPT」「打包成网页」「生图 PPT」「HTML PPT」「真实 .pptx」「演示文稿」「幻灯片」「slides」「deck」「presentation」等

**必须问的 2 个问题**（用 `ask_user` 或文字列候选均可）：

1. **风格**（ppt 出图法 V2 5 大类）：
   - 商务科技风 🏢（B 端/产品/方法论/培训/金融）
   - 博物图鉴风 📖（年度报告/系列科普/知识矩阵）
   - 手绘科教风 ✏️（小红书/视频号/教学课件/C 端学习者）
   - 真实生活感 📝（情感金句/朋友圈/日签）
   - 城市插画风 🗺️（旅行/城市/文创）
   - 反套路金句型 🎯（情感/人性/哲学/反鸡汤）

2. **颜色主题**（以商务科技风为例，6 个色版本——其他风格各有不同色版）：
   - 蓝白灰经典版（科技/SaaS/发布会）
   - 橙色主题版（课程/方法论/培训）★ 本月最常用
   - 绿色主题版（金融/ESG/碳中和）
   - 红色主题版（快讯/警示/紧急议题）
   - 紫/蓝紫主题版（AI/前沿/神秘感）
   - 黑金主题版（高端/奢侈/黑科技）
   - 完整速查：`knowhub/domains/visual-creation/cases/2026-07-04-business-tech-style-variants.md`

**执行流程**：
```
用户触发「做 PPT」
    ↓
Step 0 · 必问风格 + 颜色主题（用户硬规则）   ← 优先级最高
    ↓ 选 1 种风格 + 1 个色版
ppt 出图法 V2 7 步（准备阶段 + 出图 + 核对）
    ↓
Step 7 · 沉淀 case（包含风格+颜色选择记录）
```

**例外**（用户已明确指定风格+颜色，直接干）：
- 「做手绘马卡龙的 PPT」→ 直接走手绘科教风 + 马卡龙配色
- 「橙色商务科技风的演示」→ 直接走商务科技风 + 橙色版
- 「博物图鉴风」→ 直接走博物图鉴风

**反模式**（绝对不要做）：
- ❌ 直接默认「手绘科教 + 马卡龙」开干（2026-07-03 xhs-sponsorship-ppt 就是这样，但用户已经接受）
- ❌ 跳过 Step 0 直接ppt 出图法 V2 7 步
- ❌ ppt 出图法 V2 出 P1 hook 之前没有确认风格（造成返工）

## ppt 出图法 V2 · 7 步强制流程

> **完整方法论**：~/.mavis/knowledge/knowhub/domains/visual-creation/methodology/ppt-out-image-method.md
> **本节是速记版**，每步执行细节见源文件。

```
Step 1 · fetch 完整仓库     → README + 子目录 + examples 并行（≥3 个源）
Step 2 · reset todo          → 写到 todo 就按顺序走，禁止"读到一半改主意"
Step 3 · 列清单              → 每张图 1 行 "主题 + 核心一句话"
Step 4 · 60 行 prompt        → 不堆字体铁律，留 AI 自由空间
Step 5 · 出 hook + 渲染核对  → 10+ 项表格化（凭感觉看图 = 不可靠）
Step 6 · 接受 AI 调整        → 偏离 < 30% 有解释 = ✅ 接受
Step 7 · 沉淀 case           → AI 加了什么/改了什么 = 下次复用
```

**关键原则**：
- 吃透内容 > 锁死 prompt
- AI 偏差 = feature 不是 bug
- ppt 出图法 V2 的核心理念不是画面风格，而是**出图过程的工作流修炼**

**反例**（2026-07-02 how-to-agent-ppt）：跳过 V2 7 步 → PPT 图字体幼稚、布局不丰富、走 3 轮才修对。
**正例**（2026-06-30 ai-training-ppt）：走 V2 7 步 → 60 行 prompt + 接受 AI 加细节 + 渲染核对 → 8 张图一气呵成。

**跳过 V2 直接调下游 skill = 极大概率翻车。**

## 输出形式决策树（核心）

```
用户要什么？
│
├─ 快速预览 / 链接分享 / 跨平台
│   └─ HTML 阅读器 → 调 html-ppt-viewer skill
│
├─ PowerPoint / Keynote / WPS 打开 / 可二次编辑
│   └─ 真实 .pptx → 调 ai-image-to-pptx skill + python-pptx
│
├─ McKinsey 咨询风格 / 数据驱动
│   └─ 调 mckinsey-presentation-generator skill（自带工作流）
│
├─ 高保真设计 / 互动原型 / 动画 / 实验风格
│   └─ 调 huashu-design skill
│
├─ 视觉提案 / 海报 / KV / 封面
│   └─ 调 design-master skill
│
└─ 不确定
    └─ 默认 HTML 阅读器（5 分钟套壳 → 用户确认 → 再出真实 .pptx）
```

**默认路径**（ppt 出图法 V2 标准工作流）：
1. 先走 V2 7 步（准备阶段）
2. 选一种风格字典（见下）
3. 出 N 张 AI 图
4. 默认 **HTML 阅读器** 先看效果
5. 用户确认 → 出真实 **.pptx**
6. 媒体输出用 `<media />` 标签

**反向不成立**：用户先要 .pptx 再考虑 HTML 的情况基本没有。

## 风格字典 · 6 种（核心新增）

> **每种风格包括**：适用场景 / 配色 / 字体 / 装饰 / HTML 阅读器 prompt 模板 / PPTX 嵌入 prompt 模板 / AI lock 清单 / 失败案例。

> **HTML 阅读器版 vs PPTX 嵌入版的差异**：
> - **HTML 阅读器**：图片填满画幅，AI 不用预留页码位（HTML 阅读器自带 sidebar + badge）
> - **真实 PPTX**：图片右下角需留白 ~5%（页码 badge 区，避免遮挡）

### 风格 1 · 商务科技风 🏢

**适用场景**：行业报告、技术演进时间轴、产品架构图、商业科普、B 端报告
**来源**：ppt 出图法 V2 references/style-catalog.md 商务科技风
**风格关键词**：`clean infographic` / `blue-white-gray` / `line icons` / `rounded corners` / `soft shadows` / `sans-serif` / `grid layout` / `professional`

**配色**：
- 主色 `#1e3a5f`（深蓝）/ 辅色 `#3b82f6`（亮蓝）
- 背景 `#fafafa` / `#eaf5fa`（极浅蓝灰）
- 高亮 `#d63031`（红）/ `#f59e0b`（橙）
- 文字 `#14171e` / `#3a4256`

**字体**：思源黑体 / PingFang SC + Inter / SF Pro
**装饰**：圆角卡片 + 网格化模块 + 横向时间轴 / 流程图 + 轻阴影 + 线性图标（lucide/feather 风格）

**HTML 阅读器 prompt 模板**：
```
[主题] [一句话核心内容]

[画面布局 - 由 AI 自由发挥]
- 主体内容按"商务科技风"组织：圆角卡片 + 网格化模块
- 视觉锚点放画幅 50% 区域
- 底部 2-3 个对比/补充小卡

[风格锁]
- 主色 #1e3a5f 深蓝 + 辅色 #3b82f6 亮蓝 + 背景 #eaf5fa 浅蓝灰
- 高亮用 #d63031 红或 #f59e0b 橙
- 字体无衬线（不锁具体名）
- 圆角卡片 12-16px + 轻阴影 + 线性图标
- 禁止任何手写体 / 童趣图标 / 马卡龙色

[中文用语] [项目术语]
[约束] 16:9 / 2K / 无错字
```

**真实 PPTX prompt 模板**：
```
[同 HTML，但加一条约束]
- 右下角 ~5% 区域留白（页码 badge 区），不要把文字/图标画到这里

[其他同 HTML]
```

**AI lock 清单（必填）**：
- aspect_ratio: 16:9 / resolution: 2K
- 中文 prompt（避免 AI 自加英文）
- 禁止手写体 / 童趣图标 / 马卡龙色

**失败案例**：暂无
**典型案例**：行业研究报告 PPT、技术架构长图

### 风格 2 · 博物图鉴风 📖

**适用场景**：年度报告、系列科普卡片（3-10 张一组）、知识矩阵、分类大全、深度长文配图

**配色**：

- 辅色 `#c97b3f`（赭石）/ `#b06367`（暗红）
- 背景 `#f7f5f0`（奶油白）

**字体**：思源宋体 / 思源黑体 + DM Serif Display（标题）+ Outfit（正文）
**装饰**：像一本《XX 年鉴》或《百科图鉴》、留白克制但有呼吸感、模块化分区清晰、时间轴 + 对比表 + 评分条并用

```
[主题] [一句话核心内容]

[画面布局 - 由 AI 自由发挥]

- 禁止任何营销标语 / emoji / 卡通形象

[约束] 16:9 / 2K / 无错字
```

- aspect_ratio: 16:9 / resolution: 2K
- 中文 prompt
- 禁止营销标语 / emoji / 卡通形象

**失败案例**：暂无
**典型案例**：A 股年度报告长图、知识矩阵图鉴

#### 博物图鉴风 · 橙色主题变体（2026-07-04 沉淀 · qiuqiu-stock-ppt）

> **跨风格色版混合**：ppt 出图法 V2 第 0 步不锁死风格+色版"默认搭配"，用户可自由组合。
> 博物图鉴风 + 橙色主题版是**金融投研 PPT 最佳范式**（米黄底 + 橙色主色 + 赭石辅色 + 棕色/朱砂强调）。

**配色变体**：
- 底色：米黄/暖白 `#FDF6E3`
- 主色：橙色 `#F59E0B`
- 辅色：珊瑚橙 `#FB923C`
- 第三色：赭石 `#C97B3F`（保留博物图鉴风老书调性）
- 强调：深棕 `#78350F` / 朱砂红 `#C73E3A`（卡脖子环节高亮）

**适用场景**：A 股产业链分析、卡脖子分析、龙头股池、产业年鉴、金融投研报告

**触发词**：「做 A 股 PPT」「产业图鉴」「卡脖子 PPT」「投研封面」+ 用户选了橙色

**典型案例**：cases/2026-07-04-qiuqiu-stock-ppt.md（A 股 4 主线 + 卡脖子 + 龙头股）

| 第 3 层 · 后续衔接 | 5 min | 用"效果落差"自然过渡，不硬推销 |

- 底部：收束金句（数据震撼 / 行动号召二选一）
- 可选：自然衔接语（如果输出形式是单页 PPT 不需要）

### STAR-C 案例教学框架（P3-P6 案例页内部结构）

每张"案例演示页"都按 STAR-C 5 步展开：

| 元素 | 含义 | 在 PPT 图中的位置 |
|---|---|---|
| **S** - Situation | 企业背景和处境 | 顶部小字铺垫 |
| **T** - Task | 面临的具体挑战 | 模块标题 |
| **A** - Action | 做了什么（用了什么方法） | 中央主图（行动链/工具/方法） |
| **R** - Result | 取得的结果（用数据说话） | 数据卡片（"X 到 Y"对比） |
| **C** - Connection | 和学员业务的连接 | 底部金句过渡 |

**STAR-C 质量标准**：
- 来自真实企业（可脱敏，不可编造）
- 数据可验证（"省了 30%"要有计算过程）
- 行业相关或可类比（学员能说"这和我很像"）
- 有失败教训更好（只讲成功的案例不可信）

### 六维度审计（PPT 完成后的质量检查）

来源：`skills/quality-framework/six-dimension-audit.md` —— SKILL 质量 6 维评估。

每做完一份 PPT，按这 6 维度自评一次 ⬛/🟡/🟢：

| # | 维度 | 核心问题 | PPT 检查项 |
|---|---|---|---|
| 1 | **结果导向** | 有无明确可测试的验收标准 | 信息增量 ≥ 30%，每页都有可测论点 |
| 2 | **Enabling vs SOP** | 是方向指引还是步骤清单 | 不锁死 AI 布局，让 AI 自由发挥 |
| 3 | **陷阱覆盖** | 记录了已知失败模式吗 | 已知 V2 反模式库全部避开了吗 |
| 4 | **边界清晰** | 做什么/不做什么明确吗 | 风格禁区 / 内容禁区都明确 |
| 5 | **信息密度** | 每行都增加成功概率吗 | prompt 不堆砌，每行值回票价 |
| 6 | **新颖覆盖** | 填补了生态缺口吗 | 跟同风格案例对比，差异化在哪 |

**审计流程**：通读 → 逐维度打分 → 非🟢 写诊断（问题 + 修复） → 综合评级（⭐ 到 ⭐⭐⭐⭐⭐）。

## 反模式（绝对不要做）

❌ **直接开干不 fetch 完整内容** — 导致后续每张图都要重出（ppt 出图法 V2 Step 1）
❌ **多张图承担同一个主题** — ppt 出图法 V2 第 3 步强制信息增量 ≥ 30%，否则合并
❌ **100 行 prompt 锁死所有字体/布局** — 禁锢 AI 自由发挥（ppt 出图法 V2 反例）
❌ **真人照片当参考图（合规风险）** — 用 AI 出的人物/虚拟形象
❌ **只读路径不发 `<media />` 标签** — 用户看不到文件系统
❌ **省略 Step 5 渲染核对** — AI 出图必有偏差，必须核对
❌ **跳过 Step 3 清单** — 直接列 prompt 会导致结构混乱、内容重复
❌ **prompt 没 lock 抽象背景**（反套路金句型）— AI 会画会议室，重出成本高
❌ **不区分 HTML 阅读器版和 PPTX 版的约束差异** — PPTX 版需右下角留白

**踩过的坑（2 个真实 bug + 2 条 ppt 出图法 V2 新反模式）**：

🐛 **Bug 1 · AI 把 prompt 元注释当文案画进去**
- 症状：P5 v1 副小字写「（珊瑚粉 强调引号）」，AI 把这 5 个字当成内容画到画面里
- 根因：prompt【画面要点】段写了 "珊瑚粉 强调引号" 这种 AI 操作指令，AI 当视觉说明用
- 修复：v2 改成反向约束更有效——`【重要】不要写任何说明性元注释`
- **沉淀反模式**：❌【画面要点】段永远不要写 "X 色 强调 Y" 这种操作指令 → ✅ 颜色/字体/样式指令只放【风格锁】段 → ✅【画面要点】段只描述"画面要呈现什么"，不描述"如何呈现"

🐛 **Bug 2 · AI 重复 L1 + 标题乱字**
- 症状：P3 v1 「三层办公室」AI 在左侧重复一张 L1 卡片，标题乱字"次知指予先"
- 根因：层级标签（L1/L2/L3）有重复规律，AI 易重复 + 改字（短字符代号特别容易激发乱字倾向）
- 修复：v2 prompt 加 `右侧只放 3 张卡片，每张对应一个层级 L1/L2/L3，不重复` + 完整标题文字一字不差 + 标注"层级-位置"对应关系
- **沉淀反模式**：❌ L1/L2/L3 / Step1/2/3 / Lv.1 等短代号层级：AI 易重复 + 乱字 → ✅ prompt 强约束"不重复"+ 完整标题文字 → ✅ v2 重出 + mv 覆盖原文件，**不**在原图上 P 图（matrix 不支持 inpaint 单图）

**沉淀方法论**：
- **范式 A 第 3 次验证**：手绘科教 + 马卡龙 = 团队管理 / 方法论内容最佳组合（详见 ppt-methodology-v2 第 8 节案例对照）
- **范式 D「8 页黄金节奏」递进式变体**：4 解法 + 1 深化 + 1 钩子 + 1 总纲 + 1 收束（vs qiuqiu 的 4 主线并列）
- **PPT V2 必加反模式**：画面要点段禁止操作指令 + 短代号层级标签强约束
- **PDF 重做类需求**：第 1 步 fetch 用 pypdf 吃全文，第 3 步识别冗余对比表/页 → 强压缩

## PPT 标准工作流 V2（2026-07-07 用户反馈升级）⭐ HTML 验收 + PPTX 选项化

> **核心改进**：把"出一气呵成"工作流拆成 **「HTML 验收」中间环节** + **「PPTX 选项化」最终交付**。
> 用户做完一两次 PPT 后反馈："应该先生成 PPT HTML，让人确认效果不错，再制作真实 pptx"。

### 新工作流（替代默认路径）

```
Step 1 · Step 0 风格 + 颜色主题
Step 2 · fetch 完整内容（PDF/仓库/素材）
Step 3 · 列清单 + 信息增量 ≥ 30%
Step 4 · 60 行 prompt × N
Step 5 · 出 P0 hook → 六维度审计 ⬛🟡🟢
Step 6 · 批量出 P1-P（n-1）
Step 7 · HTML 阅读器（5 分钟套壳）+ **自动打开预览** ⬅️ NEW 必须
Step 8 · **【等用户验收 HTML】** ⬅️ NEW 默认行为
  ├─ 用户说 OK → 继续 Step 9
  └─ 用户想改 → 回到 Step 4/6 改 prompt / 重出图
Step 9 · 询问 PPTX 模式（2 选 1）⬅️ NEW
  ├─ 纯图片 PPTX：每页一张大图，无文字层（默认 / 简单）
  └─ 可编辑 PPTX：图 + 顶部主题文字框（用户能在 PowerPoint 改文字）
Step 10 · python-pptx 嵌入 + 真实 .pptx 落地
Step 11 · 沉淀 case
```

### 关键决策点

#### 何时停在 Step 8 等用户验收

- ✅ **默认全部走** —— 不是"快速模式才跳过"
- ✅ **必须先看 HTML 效果**才能进 Step 9，哪怕用户没异议也要明确"继续"
- ❌ **不允许一气呵成跳到 Step 9** —— 之前 cartman / social-ecom 都是这种"快但错的路径"

#### 何时选「纯图片 PPTX」vs「可编辑 PPTX」

| 维度 | 纯图片 pptx | 可编辑 pptx |
|---|---|---|
| 默认场景 | 内容定稿、只读演示、归档备份 | 客户拿到要改文字、自己编辑、培训前调整 |
| 文字编辑能力 | ❌ | ✅ 顶部主题文字框可改 |
| 视觉一致性 | ✅ 100% 跟 HTML 一致 | ⚠️ 用户改了文字可能破坏视觉平衡 |
| 文件大小 | 较小（无 overlay） | 略大（文字框 layer） |
| PPTX 二次加工 | 图片层可以做裁剪/翻转 | 文字可替换+图片可裁剪 |
| 何时选 | 内部教学 / 总结归档 | 客户交付 / 讲师自定义 |

#### V2 实现细节

- **HTML 阅读器**：自动 build + open（5 分钟套壳）—— sidebar 缩略图 + 主图全屏 + 键盘 ← → 翻页
- **PPTX 模式选项化**：脚本支持 `--mode image / --mode editable`，默认 image
- **可编辑模式细节**：每页 slide 顶部 12% 留白 = 一个可编辑文本框（半透明白底），用户改文字不会与图重叠

### 反模式（绝对不要做）

- ❌ **跳过 Step 8 验收** —— 一气呵成到 Step 9 直接出 .pptx（之前 cartman / social-ecom 都是这个错）
- ❌ **没有 HTML 预览就做 .pptx** —— 用户回看发现 8 张图里有 2 张不对
- ❌ **不询问 PPTX 模式默认选择** —— 直接当纯图片出，客户要可编辑时返工
- ❌ **假设"应该跳过 HTML"为节省时间** —— 10 分钟换来 100% 视觉验证，远比 1 小时返工划算

### 工作流升级带来的"业务收益"

| 之前（cartman / social-ecom） | 现在（V2） |
|---|---|
| 一气呵成出 .pptx | HTML 验收后再出 .pptx |
| 发现 bug 返工（cartman 25%）| **0 返工**（social-ecom 8/8 = 验收在前） |
| .pptx 不可改 | 可选可编辑模式 |
| 用户对成品的「视觉冲击力」靠猜 | 打开浏览器 5 分钟就能看 |

### 已沉淀 case（V2 工作流首次实战 = social-ecom-skill-ppt）

注意：social-ecom 实际是**边做边迭代到 8/8 0 返工**后才暴露这个流程问题。**V2 是 cartman 后做的，social-ecom 复用 V2 反模式库后 0 返工**。**所以 social-ecom 的工作流是"输出顺序对了"但"流程没明文沉淀"**。

→ 本次升级是真正的"流程明文化 + 工作流标准化"。
