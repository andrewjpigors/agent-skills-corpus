# cograft-init

> Agent-agnostic scaffolder. The YAML frontmatter above is one agent's skill
> format (e.g. Claude Code's `/cograft-init` slash command), but the body is
> plain instructions any AI coding agent — Cursor, Codex CLI, Cline, Aider,
> Continue, a custom agent — can execute. A human can also follow it by
> hand. The output (`.worktrees/` files) is the same.

You are making the current directory cograft-ready (worktree-ready). Output config files that the `cograft` runner consumes.

## Architecture (important — read first)

Everything cograft owns lives in one `.worktrees/` dir. Per repo,
`<repo>/.worktrees/` holds the **committable** config (`config.sh` + `hooks/`)
AND the local-only artifacts the runner later drops in (`<slug>/` checkouts,
`*_base.dump`). It's gitignored by default (solo mode); team mode shares only
the config via a gitignore negation (Step 4.5). Teammates who opt in pull →
instantly worktree-ready.

Multi-repo "umbrellas" add a tiny `<umbrella>/.worktrees/umbrella.sh` manifest
that **only lists which repos belong together** (and the umbrella's
`.worktrees/` also holds the coordinated `<slug>/` checkouts). No ports, no
env, no hooks live in the umbrella — those belong to each repo.

## Process

### Step 1 — Detect project shape

This is the most important step. Cograft handles four shapes. Detect in this order:

1. **Already scaffolded** — if `<cwd>/.worktrees/umbrella.sh` exists OR
   `<cwd>/.worktrees/config.sh` exists, this is a **re-run**. Read the
   existing config to understand prior decisions, then update only what
   drifted (compare watched files). Do not overwrite without showing a diff.

2. **Multi-repo umbrella** — `<cwd>` itself is NOT a git repo (no `.git/`),
   but contains ≥2 subdirs that ARE git repos (have `.git/`). Examples:
   `acme/{api,web,shared}`.
   → Write `<cwd>/.worktrees/umbrella.sh` + one `<each_repo>/.worktrees/`
   inside each member repo. Coordinate slug + offset across them.

3. **Monorepo** — `<cwd>` IS a git repo (has `.git/`) AND contains a
   monorepo-manager signal file at root:
   - `pnpm-workspace.yaml` (pnpm workspaces)
   - `turbo.json` (Turborepo)
   - `nx.json` (Nx)
   - `lerna.json` (Lerna)
   - `package.json` with `workspaces` field (npm/yarn workspaces)
   - `Cargo.toml` with `[workspace]` (Cargo workspace)
   - `go.work` (Go workspaces)

   → Write `<cwd>/.worktrees/config.sh` with **per-workspace port ranges**
   inside one config (each app/service in `apps/*` or `packages/*` gets its
   own offset slice). Detect each workspace's dev-server port and env files
   individually.

4. **Single-repo** — `<cwd>` is a git repo, no monorepo signal, no umbrella
   above. → Write `<cwd>/.worktrees/config.sh` only.

5. **None of the above** — `<cwd>` is not a git repo and has no `.git/`
   subdirs. → Ask user to `cd` into a repo or umbrella dir.

### Step 2 — Per-target detection

A "target" is whatever the shape resolves to:
- multi-repo umbrella → each member repo is one target
- monorepo → the repo itself is one target, BUT also enumerate each workspace
  (`apps/*`, `packages/*`, or wherever the manager declares them) as a
  **sub-target** that gets its own port-range slice inside the single config
- single-repo → one target

For EACH target, read:

- `docker-compose*.yml` (any variant: `docker-compose.yml`, `docker-compose.dev.yml`, `compose.yml`)
- `package.json` (root + each workspace's own)
- `pyproject.toml` / `Pipfile` / `requirements.txt` (Python)
- `Cargo.toml`, `go.mod`, `Gemfile`, `pom.xml`/`build.gradle` (Rust/Go/Ruby/Java)
- `.env*` files at all levels inside the target
- `Procfile`

Monorepo manager files to enumerate workspaces:
- `pnpm-workspace.yaml` → `packages:` glob patterns
- `turbo.json` → workspaces inferred from `package.json` `workspaces`
- `nx.json` → projects discovered via `apps/`, `libs/` (or `workspace.json`)
- `lerna.json` → `packages:` patterns
- `Cargo.toml` `[workspace] members =` → crate paths
- `go.work` → module paths

### Step 3 — Per-target extraction

For each target, capture:

1. **Compose port mappings** (per service block with `ports:`): compose_file + service + host_port:container_port[/proto]
2. **External volumes** (top-level `volumes:` section with `external: true`): compose_file + volume_name
3. **Env files** that compose `env_file` references AND that exist on disk
4. **Dev-server ports** outside compose (Vite/Next/Django config, package.json scripts with `--port` or `PORT=`)
5. **Watched files** — files whose change might invalidate config (compose files, package.json/pnpm-workspace.yaml, pyproject.toml, lockfiles, etc.)
6. **Env files that point at a localhost service port** (`ENV_PORT_OFFSET`) — scan each copied env file for `localhost` / `localhost:<port>` in URL-shaped values (e.g. a frontend's `*_API`, `*_GRAPHQL_ENDPOINT`, `*_WS_ENDPOINT`, `DATABASE_URL`). If a file has any, list its dst path in `ENV_PORT_OFFSET` so the runner offsets those ports per worktree. This is what makes a worktree's frontend hit ITS OWN backend rather than main's — without it, isolation is only half-done (services listen on offset ports, but clients still call main's).

For **monorepos**: also capture per-workspace dev ports so that worktrees of
the monorepo can run all apps in parallel without colliding even WITHIN one
worktree. Assign each workspace its own offset slice (e.g. workspace 0 gets
offset+0..+9, workspace 1 gets offset+10..+19, etc.) on top of the
per-worktree offset.

### Step 3.5 — Database fill strategy (only if the target has a DB)

A fresh worktree gets an **empty** database (the runner isolates the DB
container per worktree via `COMPOSE_PROJECT_NAME`, so it never shares data
with main). An empty DB is rarely useful — so if a target has a database,
decide HOW each new worktree's DB gets filled. This is the single most
impactful thing the scaffolder configures beyond ports.

**Detect the database service.** A compose service is a DB if its `image:`
matches `postgres|postgis|pgvector|timescale|mysql|mariadb|mongo|cockroach`
OR its service name is one of `db|database|postgres|pg|mysql|mariadb|mongo`.
Capture: `DB_SERVICE` (service name), `DB_ENGINE` (`postgres|mysql|mongo`),
and from its `environment:`/`env_file:` the `DB_NAME` and `DB_USER`. If no DB
service exists, **skip this step entirely** (no DB vars, no DB hook block).

**Detect migrate/seed tooling** from the stack (used by the `empty`/`seed`
strategies). Detect the app service that runs them (`APP_SERVICE` — the
compose service that mounts the source and has the framework installed):

| Stack signal | MIGRATE_CMD | SEED_CMD (if found) |
|---|---|---|
| Django (`manage.py`) | `python manage.py migrate` | a `*/management/commands/<name>.py` matching `seed*\|bootstrap\|demo\|sample\|loaddata` → `python manage.py <name>` |
| Rails (`bin/rails`) | `rails db:migrate` | `rails db:seed` |
| Prisma (`prisma/schema.prisma`) | `prisma migrate deploy` | `prisma db seed` (only if `prisma.seed` set in package.json) |
| Drizzle (`drizzle.config.*`) | `drizzle-kit migrate` | a `seed` script in package.json, if present |
| Knex (`knexfile.*`) | `knex migrate:latest` | `knex seed:run` |
| Laravel (`artisan`) | `php artisan migrate` | `php artisan db:seed` |
| Alembic (`alembic.ini`) | `alembic upgrade head` | — |
| golang-migrate (`migrations/*.sql`) | `migrate -path migrations -database "$DATABASE_URL" up` | — |

Mark anything you can't infer with `# REVIEW:` rather than guessing a command.

**Detect the app image to reuse** (`APP_IMAGE` — so migrate/seed don't rebuild
the image per worktree). Compose names a built image `<project>-<service>`,
where `<project>` defaults to the sanitized basename of the dir holding the
compose file (the source repo dir). So `APP_IMAGE = <sanitized repo-dir
basename>-<APP_SERVICE>` (lowercase; keep only `[a-z0-9_-]`). Example: repo
`acme-backend`, service `web` → `acme-backend-web`. Record it; the user
overrides it in config.sh if their main project uses a custom name/image. If
the app image is pulled (not built), leave `APP_IMAGE` empty — the hook then
skips migrate/seed instead of rebuilding.

**Engine → copy tooling** (used by the `copy_from_base` strategy):

| DB_ENGINE | dump (refresh-base) | restore (post_create) | readiness probe |
|---|---|---|---|
| postgres | `pg_dump -U $DB_USER -Fc $DB_NAME` | `pg_restore -U $DB_USER -d $DB_NAME --clean --if-exists` | `pg_isready -U $DB_USER` |
| mysql | `mysqldump -u$DB_USER $DB_NAME` | `mysql -u$DB_USER $DB_NAME` | `mysqladmin ping` |
| mongo | `mongodump --archive` | `mongorestore --archive --drop` | `mongosh --eval 'db.runCommand({ping:1})'` |

**Ask the user** (once per target that has a DB — do NOT ask on re-run if
`DB_FILL_STRATEGY` is already recorded; reuse it):

> Target `<name>` has a `<DB_ENGINE>` database. How should each new worktree's
> DB be filled?
> 1. **empty** — bring the DB up and run migrations only (`<MIGRATE_CMD>`). Fast, no data.
> 2. **seed** — migrations + the detected seed command (`<SEED_CMD>`). Deterministic synthetic data, no PII.
> 3. **copy_from_base** — restore each worktree from a canonical base dump you
>    refresh from your main checkout (`<DB_ENGINE>` dump). Realistic data —
>    "branch the DB". Each worktree runs its OWN full stack (Postgres/Redis/
>    object store per worktree) — realistic but heavy; N worktrees = N stacks.
> 4. **shared_infra** — ONE shared Postgres/Redis/object-store for all worktrees;
>    each worktree runs ONLY the app and gets an instant `CREATE DATABASE …
>    TEMPLATE` clone of the base DB. No per-worktree DB/object copy, no per-worktree
>    infra containers. Lightest by far for many parallel worktrees. **Postgres only**
>    (relies on `CREATE DATABASE … TEMPLATE`). Recommended when the machine can't run
>    N full stacks. See the dedicated block below.
> 5. **none** — leave DB handling to you (commented suggestions only).

If `SEED_CMD` wasn't detected, drop option 2. `shared_infra` requires
`DB_ENGINE=postgres` — drop it otherwise. Record the answer (see `DB_FILL_*` in
Step 4's config template). The choice drives which block Step 4 writes
**un-commented** into `post_create.sh`.

**Hook blocks to emit** (write ONLY the chosen one, un-commented). Each block
assumes the hook has already sourced its `config.sh` (the template's first
line) so `$DB_SERVICE`, `$DB_NAME`, `$MIGRATE_CMD`, etc. are defined. All run
with `COMPOSE_PROJECT_NAME` already set by the runner, and `docker-compose.override.yml`
already generated — so compose is isolated and ports are offset automatically.
Postgres shown; swap the tool per the engine table above.

Any strategy that runs an app-service command (migrate/seed) must NOT rebuild
the app image per worktree — a fresh `COMPOSE_PROJECT_NAME` makes
`docker compose run` build from scratch (slow, network-dependent, fails
offline). Emit this `app_run` helper once near the top of the hook and call it
instead of `docker compose run`. It reuses the image the MAIN checkout already
built (`$APP_IMAGE`); if that image isn't present it SKIPS rather than rebuilds:

```bash
app_run() {  # reuse the main-built app image; never rebuild per worktree
  if [[ -n "${APP_IMAGE:-}" ]] && docker image inspect "$APP_IMAGE" >/dev/null 2>&1; then
    docker image tag "$APP_IMAGE" "${COMPOSE_PROJECT_NAME}-${APP_SERVICE}"
    docker compose run --rm "$APP_SERVICE" "$@" || echo "cograft: '$*' failed (non-fatal)" >&2
  else
    echo "cograft: no prebuilt app image ('${APP_IMAGE:-unset}') — skipping '$*'. Build it in your main checkout (docker compose build $APP_SERVICE) or set APP_IMAGE." >&2
  fi
}
```

`empty`:
```bash
cd "$COGRAFT_DIR"
docker compose up -d "$DB_SERVICE"
until docker compose exec -T "$DB_SERVICE" pg_isready -U "$DB_USER" >/dev/null 2>&1; do sleep 1; done
app_run $MIGRATE_CMD
```

`seed` (= empty + the seed command):
```bash
cd "$COGRAFT_DIR"
docker compose up -d "$DB_SERVICE"
until docker compose exec -T "$DB_SERVICE" pg_isready -U "$DB_USER" >/dev/null 2>&1; do sleep 1; done
app_run $MIGRATE_CMD
app_run $SEED_CMD
```

`copy_from_base` (restore the canonical base, then apply any migrations newer
than the base so a branch that adds migrations still converges):
```bash
cd "$COGRAFT_DIR"
dump="$COGRAFT_ROOT/$BASE_DUMP_PATH"
if [[ ! -f "$dump" ]]; then
  echo "cograft: base dump missing ($dump). Run .worktrees/refresh-base.sh once." >&2
  exit 1
fi
docker compose up -d "$DB_SERVICE"
until docker compose exec -T "$DB_SERVICE" pg_isready -U "$DB_USER" >/dev/null 2>&1; do sleep 1; done
docker compose exec -T "$DB_SERVICE" pg_restore -U "$DB_USER" -d "$DB_NAME" --clean --if-exists < "$dump"
app_run $MIGRATE_CMD   # apply migrations newer than base (no-op if current)
```

`none`: emit only commented suggestions (the legacy default).

**`shared_infra` (Postgres only) — the light model for many parallel worktrees.**
Instead of isolating the whole compose per worktree, ONE infra instance is shared
and each worktree runs only the app against it. This needs a few extra artifacts;
generate them all when the user picks this strategy:

1. **Classify services** in `config.sh`: `SHARED_SERVICES` (the DB/cache/object
   store — detected in Step 3.5) vs `APP_SERVICES` (everything the app runs:
   web/worker/asgi/proxy). The shared ones are NOT isolated per worktree.

2. **Extract a shared-infra compose** `<COGRAFT_ROOT>/.worktrees/infra.yml` holding
   ONLY the `SHARED_SERVICES`, published on their default host ports, with the
   project's `external: true` volumes kept external (so the shared infra reuses the
   main checkout's data — DB + objects — for free). Bring it up once under a fixed
   project name (`SHARED_INFRA_PROJECT`, e.g. `<umbrella>-infra`).

3. **Scaffold an app-only override** at the compose default name
   `docker-compose.override.yml` (auto-loaded, so no `-f` needed) in the repo that
   points the app services at the shared infra over the host (`host.docker.internal`,
   which every container can reach on Docker Desktop; on native-Linux hosts set it via
   `extra_hosts: ["host.docker.internal:host-gateway"]`). It sets the DB/redis/object
   env vars the app reads (discovered in Step 3 — e.g. `DB_HOST`, `DB_NAME`,
   `REDIS_HOST`, the object-store endpoint, and any browser-facing presign URL →
   `localhost:<shared host port>`). To make a plain **`docker compose up -d`** run the
   app ONLY (no per-worktree infra, no flags to remember), the override also:
   (a) parks each SHARED_SERVICE behind an inactive `profiles: ["cograft-shared-disabled"]`
   so `up` skips them; (b) clears each app service's `depends_on`/`links` to those infra
   services with `!override []` (a `depends_on`/`links` to a profiled-out service otherwise
   errors "depends on undefined service" or drags the infra back in) — keeping only the
   proxy's dep on its app upstreams. Result: `docker compose up -d` = app against shared
   infra. Then apply the branch's newer migrations onto the clone (the clone is a snapshot
   of the base DB): `docker compose exec -T <APP_SERVICE> <MIGRATE_CMD>`.

4. **Hook block** (`post_create.sh`, un-commented): ensure infra up (idempotent) +
   clone the base DB via TEMPLATE (instant; TEMPLATE needs no active sessions on the
   source, so terminate + retry on `ObjectInUse`) + write the per-worktree app env.
```bash
psql_infra() { docker compose -p "$SHARED_INFRA_PROJECT" -f "$COGRAFT_ROOT/$SHARED_INFRA_COMPOSE" exec -T "$DB_SERVICE" psql -U "$DB_USER" -d postgres -tc "$1"; }
docker compose -p "$SHARED_INFRA_PROJECT" -f "$COGRAFT_ROOT/$SHARED_INFRA_COMPOSE" up -d
until psql_infra 'select 1' >/dev/null 2>&1; do sleep 1; done
if ! psql_infra "select 1 from pg_database where datname='${DB_NAME}'" | grep -q 1; then
  psql_infra "CREATE DATABASE \"${DB_NAME}\" TEMPLATE \"${DB_TEMPLATE}\"" || {
    psql_infra "select pg_terminate_backend(pid) from pg_stat_activity where datname='${DB_TEMPLATE}' and pid<>pg_backend_pid()" >/dev/null
    psql_infra "CREATE DATABASE \"${DB_NAME}\" TEMPLATE \"${DB_TEMPLATE}\""
  }
fi
# Per-worktree app env (redis broker DB from the offset bucket; caches/channels
# namespaced by slug so they can share the one Redis without cross-talk):
cat > "$COGRAFT_DIR/.worktree.env" <<ENV
DB_NAME=${DB_NAME}
CELERY_BROKER_DB=$(( (COGRAFT_OFFSET / 100 % 14) + 2 ))
REDIS_KEY_PREFIX=${COGRAFT_SLUG}
CHANNELS_PREFIX=${COGRAFT_SLUG}
ENV
```
No `refresh-base.sh` and no dump/mirror: `shared_infra` clones live from the running
shared DB, and the shared object store already holds the objects (browser-facing
URLs point at its host port, so previews/uploads work with zero copy). `DB_NAME` is
per-worktree (`<db>_<slug>`); `DB_TEMPLATE` is the base DB to clone (defaults to the
app's working DB, e.g. `backend`). **Depends on the app honoring per-worktree Redis
key/channel prefixes** — if the app shares one Redis, its cache/broker/channels code
must read `REDIS_KEY_PREFIX`/`CELERY_BROKER_DB`/`CHANNELS_PREFIX`; flag as REVIEW if
that wiring isn't present in the app yet. Also: if the app reads a **full URL** env
var directly (e.g. a worker started from `CELERY_BROKER_URL`, not the settings-computed
value), set that whole URL in `.worktree.env` — overriding just `REDIS_HOST` won't
reach it. Write both the host var AND the full `*_URL` var (e.g.
`CELERY_BROKER_URL=redis://host.docker.internal:6379/<broker_db>`).

**For `copy_from_base`, also scaffold the base-refresh helper** at
`<COGRAFT_ROOT>/.worktrees/refresh-base.sh` (the user runs it to (re)create the
canonical dump from their MAIN checkout's running DB — the scaffolder writes
it but NEVER runs it):
```bash
#!/usr/bin/env bash
# Refresh the canonical base dump that every new worktree is cloned from.
# Run from the umbrella/repo root, against your MAIN checkout's running DB.
set -euo pipefail
mkdir -p "$(dirname "$0")"
# REVIEW: point at your main checkout's DB. Default assumes it's up on the base host port.
docker compose -f "<main_repo>/docker-compose.yml" exec -T "$DB_SERVICE" \
  pg_dump -U "$DB_USER" -Fc "$DB_NAME" > "$(dirname "$0")/<db>_base.dump"
echo "base dump refreshed → .worktrees/<db>_base.dump"
```
Add a `# REVIEW:` note in the report that the base dump must be created once
(run `refresh-base.sh`) **before** the first `cograft new`, and that if the
base is a copy of production it carries PII into every worktree (prefer a
seeded or sanitized base if that matters).

### Step 4 — Write files

For **each repo**, write `<repo>/.worktrees/config.sh`:

```bash
#!/usr/bin/env bash
# Per-repo worktree config. Committable. Sourced by the `cograft` runner.

# Compose port mappings INSIDE this repo. No repo prefix — paths/files relative to this repo.
# Format: "compose_file|service|host_port:container_port[/proto]"
COMPOSE_PORTS=(
  "docker-compose.yml|database|5432:5432"
  "docker-compose.yml|web|8000:8000"
)

# Top-level volumes declared `external: true` (must be overridden per worktree to
# avoid sharing data with main checkout). Format: "compose_file|volume_name".
COMPOSE_EXTERNAL_VOLUMES=(
  "docker-compose.yml|my-database"
)

# Files inside this repo to copy verbatim into the worktree at create time.
# Format: "src_relative|dst_relative". Both relative to this repo's root.
ENV_COPIES=(
  "backend/.env|backend/.env"
  ".env.local|.env.local"
)

# Copied env files whose localhost:<port> references point at ANOTHER worktree
# service (classically a frontend's API/GraphQL/WS URL pointing at the backend).
# The runner rewrites every localhost:<port> (and bare localhost → :80) in these
# by the worktree's uniform offset AFTER copying, so each worktree's frontend
# talks to ITS OWN backend instead of main's. WITHOUT this, a copied .env.local
# still says localhost:80 = main's backend, breaking full-stack isolation.
# List dst paths (relative to the worktree). Leave empty if no env points at a
# localhost service port.
ENV_PORT_OFFSET=(
  ".env.local"
)

# Files inside this repo to track for drift (used by `cograft doctor`).
# Format: bare relative paths.
WATCHED_FILES=(
  "docker-compose.yml"
  "pyproject.toml"
)

# Database fill (only present if this target has a DB service — see Step 3.5).
# DB_FILL_STRATEGY drives which block the post_create hook runs. Recorded here
# so re-runs are deterministic and don't re-ask the user.
DB_FILL_STRATEGY="copy_from_base"   # empty | seed | copy_from_base | shared_infra | none
DB_SERVICE="database"               # compose service name of the DB
DB_ENGINE="postgres"                # postgres | mysql | mongo
DB_NAME="backend"
DB_USER="backend"
APP_SERVICE="web"                   # service that runs migrate/seed
APP_IMAGE="myproject-web"           # prebuilt image to reuse for migrate/seed (main's <project>-<service>); empty → skip, never rebuild
MIGRATE_CMD="python manage.py migrate"
SEED_CMD="python manage.py seed_local"          # only for strategy=seed
BASE_DUMP_PATH=".worktrees/backend_base.dump"     # only for strategy=copy_from_base; relative to COGRAFT_ROOT

# --- shared_infra only (see Step 3.5) ---
# Services split: SHARED_SERVICES run once in the shared infra (NOT isolated per
# worktree); APP_SERVICES run per worktree against it. Leave empty for other strategies.
SHARED_SERVICES=(database redis minio createbuckets)
APP_SERVICES=(web celery daphne nginx)
SHARED_INFRA_PROJECT="myproject-infra"             # fixed compose project for the one shared infra
SHARED_INFRA_COMPOSE=".worktrees/infra.yml"        # relative to COGRAFT_ROOT; only SHARED_SERVICES
DB_TEMPLATE="backend"                              # base DB to clone (CREATE DATABASE <DB_NAME> TEMPLATE <DB_TEMPLATE>)
```

For `shared_infra`, `DB_NAME` is per-worktree — the hook overrides it to
`<DB_TEMPLATE>_<slug>` at create time (the value above is just the template's own
name as a default).

Also write `<repo>/.worktrees/hooks/post_create.sh` and `<repo>/.worktrees/hooks/pre_remove.sh`.
The runner exports `COGRAFT_SLUG`, `COGRAFT_OFFSET`, `COGRAFT_DIR`,
`COGRAFT_REPO_NAME`, `COGRAFT_ROOT`, `COGRAFT_UMBRELLA`, and
`COMPOSE_PROJECT_NAME` into the hook's environment — but NOT the scalar
`config.sh` vars (`DB_SERVICE`, `MIGRATE_CMD`, …). The hook runs as a separate
bash process, so it must **source its own `config.sh`** to see them. The
template does this on the first line.

```bash
#!/usr/bin/env bash
# Env from runner: COGRAFT_SLUG, COGRAFT_OFFSET, COGRAFT_DIR, COGRAFT_REPO_NAME,
# COGRAFT_ROOT, COGRAFT_UMBRELLA, COMPOSE_PROJECT_NAME.
# COGRAFT_DIR is THIS repo's worktree dir. The runner already generated the
# port-override file, copied env files, and set COMPOSE_PROJECT_NAME — so any
# `docker compose` below is already isolated and port-offset. Don't repeat that.
set -euo pipefail

# Bring the DB_* (and other) config vars into scope — they are NOT exported by
# the runner. Path is relative to THIS hook file, not the CWD.
source "$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)/config.sh"

# Generic suggestions stay commented — uncomment what applies:
# (cd "$COGRAFT_DIR" && pnpm install)
# (cd "$COGRAFT_DIR" && poetry install)

# Reuse the main-built app image for migrate/seed; never rebuild per worktree.
app_run() {
  if [[ -n "${APP_IMAGE:-}" ]] && docker image inspect "$APP_IMAGE" >/dev/null 2>&1; then
    docker image tag "$APP_IMAGE" "${COMPOSE_PROJECT_NAME}-${APP_SERVICE}"
    docker compose run --rm "$APP_SERVICE" "$@" || echo "cograft: '$*' failed (non-fatal)" >&2
  else
    echo "cograft: no prebuilt app image ('${APP_IMAGE:-unset}') — skipping '$*'." >&2
  fi
}

# --- DB fill (strategy=copy_from_base) — written UN-commented per Step 3.5 ---
# This block is the ONE part written active, because the user explicitly chose
# DB_FILL_STRATEGY. Emit the block matching the recorded strategy (see Step 3.5).
cd "$COGRAFT_DIR"
dump="$COGRAFT_ROOT/$BASE_DUMP_PATH"
if [[ ! -f "$dump" ]]; then
  echo "cograft: base dump missing ($dump). Run .worktrees/refresh-base.sh once." >&2
  exit 1
fi
docker compose up -d "$DB_SERVICE"
until docker compose exec -T "$DB_SERVICE" pg_isready -U "$DB_USER" >/dev/null 2>&1; do sleep 1; done
docker compose exec -T "$DB_SERVICE" pg_restore -U "$DB_USER" -d "$DB_NAME" --clean --if-exists < "$dump"
app_run $MIGRATE_CMD   # apply migrations newer than base (no-op if current)
```

For **umbrella mode**, also write `<umbrella>/.worktrees/umbrella.sh`:

```bash
#!/usr/bin/env bash
UMBRELLA_NAME="my-project"
WORKTREES_ROOT=".worktrees"

# Format: "name|relative_path|default_branch"
REPOS=(
  "backend|backend|main"
  "frontend|frontend|develop"
)
```

### Step 4.5 — Gitignore by default (solo mode)

**This is the default behaviour.** Everything cograft owns lives in a single
`.worktrees/` dir, and it starts gitignored — local to the user's machine,
zero impact on teammates until they deliberately opt in.

That one dir holds BOTH committable config (`config.sh`, `hooks/`) AND
never-committable artifacts (`<slug>/` checkouts, `*_base.dump`). Solo mode
ignores all of it; team mode (later) un-ignores only the config via negation —
so the user gets the fine-grained control without two separate dirs.

For **each git repo** you wrote a `.worktrees/` into (single-repo, monorepo,
and each member of an umbrella):

1. Read `<repo>/.gitignore` (create it if missing).
2. If `.worktrees/` is NOT already covered, append the **solo-mode** block:

```
# cograft — local worktree env (config + checkouts + dumps). All local by
# default. To SHARE config with the team, replace this line with the
# "team mode" block below.
.worktrees/
```

For the **umbrella** dir itself: the `<umbrella>/.worktrees/` there holds the
`umbrella.sh` manifest and the `<slug>/` checkouts. The umbrella dir is
typically NOT a git repo, so no gitignore action is needed. If it IS a git
repo (rare), gitignore `.worktrees/` there too (and use the team-mode negation
if the manifest should be shared).

**Team mode (the user's later, deliberate choice — do NOT pre-empt it).** When
they want teammates to inherit the config, the whole-dir ignore is replaced
with a negation that shares only `config.sh` + `hooks/` and keeps checkouts and
dumps out:

```
# cograft — share config with the team, keep local artifacts ignored.
.worktrees/*
!.worktrees/config.sh
!.worktrees/hooks
!.worktrees/hooks/**
```

`.worktrees/*` re-ignores everything (so `<slug>/` checkouts and `*_base.dump`
stay out of git); the `!` lines re-include just the config. The base dump is
**data, may contain PII — it must never be committed** under any mode; the
negation block above already keeps it ignored.

**Slug name collisions:** because checkouts (`<slug>/`) share the dir with
`config.sh`/`hooks/`/`*_base.dump`, a slug must not be one of those reserved
names. The runner's `validate_slug` rejects them, so no scaffolder action is
needed — just be aware.

## Hard rules

- **NEVER modify application source code.** Codemod is a separate command (`cograft prepare`, v0.2+).
- **NEVER run install/up/migrate/seed/dump commands.** You only WRITE files
  inside `.worktrees/` (and `.worktrees/refresh-base.sh`). The hooks run later, at
  `cograft new` — you never execute them, and you never create the base dump.
- **NEVER commit anything.** You write files. The user decides what to track. Default is solo mode (gitignored per repo).
- **ALWAYS write per-repo configs in the repo itself**, not at umbrella level.
- **ALWAYS append `.worktrees/` to each repo's `.gitignore`** (Step 4.5). Solo mode is the default.
- **Generic hook suggestions default to commented** (install, plain `compose up`).
  **EXCEPTION: the DB-fill block is written UN-commented** to match the user's
  recorded `DB_FILL_STRATEGY` (Step 3.5) — it's a deliberate, recorded choice,
  not a guess. `strategy=none` is the only one that stays commented.
- **ALWAYS ask the DB-fill question once per DB target**, and skip it on re-run
  when `DB_FILL_STRATEGY` is already recorded (reuse the recorded value).

## Anti-patterns to avoid

- ❌ Repeating port info from one repo inside another repo's config
- ❌ Putting `REPOS=` array in a per-repo config (that belongs in the umbrella manifest)
- ❌ Using absolute paths in per-repo configs (paths must be repo-relative for portability)
- ❌ Writing hooks that assume Docker without checking compose file exists

## What success looks like

User can now:
```
cd <umbrella>            # or cd <single-repo>
cograft new feature-x         # creates worktree(s), copies env, generates overrides, runs hooks
cograft ls
cograft rm feature-x
cograft doctor
```

The configs are git-trackable, PR-reviewable, and travel with each repo.
